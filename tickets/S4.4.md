## Names and signatures
- `BeanRating`: add `mode = input<'display' | 'input'>('display')`. Display mode keeps the `value` input and its `role="img"` markup. In input mode it is a `ControlValueAccessor` (`providers: [{ provide: NG_VALUE_ACCESSOR, useExisting: forwardRef(() => BeanRating), multi: true }]`, value `number | null`), with its value in `protected readonly current = signal<number | null>(null)`, set by `writeValue`.
- Input-mode markup, like the prototype's `.rating-input`: a container with `role="radiogroup"` and `aria-label` "Rating". For each bean i from 1 to 5 there is a `<label>` (44 px target), with class `on` when `i <= (current() ?? 0)`, holding:
  - a native `<input #beanInput type="radio">` with `name` `"bean-rating-" + n` (n from a module-level counter, so it's unique per instance), `[value]` i, `[checked]` `i === current()` and `[tabIndex]` `i === (current() ?? 1) ? 0 : -1`. This makes the group's only Tab stop the checked bean, or bean 1 while unrated, for both Tab and Shift+Tab (R46).
  - `<span class="sr-only">` "i of 5 beans"
  - the `bean-fill` icon up to `current()`, the `bean` icon after it
- Beside the beans is the text `current() + " of 5"`, or "Not rated" when `current()` is null.
- `(change)` on bean i → `select(i)`. `(keydown)` on bean i → `onKey(event, i)` (Hard logic). `(focusout)` on the group → `onTouched()` when `event.relatedTarget` is outside the group (moving between beans doesn't count).
- `select(v: number)`: when `v !== current()`, it calls `current.set(v)` and `onChange(v)`. Otherwise nothing happens: no `onChange` call for an unchanged value.
- `beanInputs = viewChildren<ElementRef<HTMLInputElement>>('beanInput')`, used to move focus.
- `setDisabledState(d)` disables all 5 radios.
- SCSS: port `.rating-input` (`components.css` lines 121–127). The radio is invisible there (`opacity: 0`), so its keyboard focus ring goes on its label: `.rating-input label:has(input:focus-visible) { outline: 2px solid var(--color-tertiary); outline-offset: 2px; }` (the `base.scss` ring values).
- `MethodSelect`: `ControlValueAccessor` for a method id (`number | null`), wrapping `mat-select` inside `mat-form-field`. `methods = input.required<BrewMethod[]>()`, shown in `methodsAz` order, each option with `MethodIcon` + name. Placeholder "Choose a method". (The "+ Add new method…" and "Manage methods…" options come in the methods stories.)

## Tests that prove it
**Seam:** component · **Setup:** TestBed + Material harnesses (`MatSelectHarness`), a host with a `FormControl<number | null>` bound to `<app-bean-rating mode="input">` / `<app-method-select>`; keys are `new KeyboardEvent('keydown', { key, bubbles: true, cancelable: true })` dispatched on the focused bean radio (`radio.focus()` first), with `event.defaultPrevented` checked · **Mocked:** HTTP (sprite)

**Happy path**
1. Given `BeanRating` in input mode, when the 4th bean is clicked, then the control is 4, 4 beans have `bean-fill` and the text reads "4 of 5" (R12).
2. Given the control null, then no radio is checked, the text reads "Not rated", bean 1's radio has `tabIndex` 0 and beans 2–5 have `tabIndex` -1 (bean 1 is the only Tab stop) (R46).
3. Given the control null and bean 1 focused, when ArrowRight is pressed, then the control is 1, bean 1 is checked, the text reads "1 of 5" and `defaultPrevented` is true. The same with ArrowUp, starting again from null (R46).
4. Given the control null and bean 1 focused, when Space (`key` `' '`) is pressed, then the control is 1 and the text reads "1 of 5" (R46).
5. Given the control 4, then only bean 4's radio has `tabIndex` 0. When ArrowRight is pressed on it, then the control is 5, the text reads "5 of 5", `document.activeElement` is bean 5's radio and bean 5 now has `tabIndex` 0. The same with ArrowUp, starting again from 4 (R46).
6. Given the control 4, when ArrowLeft is pressed on bean 4, then the control is 3, the text reads "3 of 5" and focus is on bean 3's radio. The same with ArrowDown, starting again from 4 (R46).
7. Given the focused group, when focus leaves it, then the control is touched.
8. Given `MethodSelect` with the 7 seeded methods (+ custom "chemex"), when it is opened, then it lists AeroPress, chemex, Cold Brew, Espresso, French Press, Moka Pot, Pour Over, Other. Choosing "Pour Over" sets the control to 2 (B21).

**Negative**
9. Given the control null and bean 1 focused, when ArrowLeft is pressed, then the control stays null, `valueChanges` doesn't emit, the text still reads "Not rated", focus stays on bean 1 and `defaultPrevented` is true. The same with ArrowDown (R46).
10. Given the control 5, when ArrowRight is pressed on bean 5, then the control stays 5 (no wrap to 1), `valueChanges` doesn't emit and `defaultPrevented` is true. The same with ArrowUp (R46).
11. Given the control 1, when ArrowLeft is pressed on bean 1, then the control stays 1 (never back to null), `valueChanges` doesn't emit and `defaultPrevented` is true. The same with ArrowDown (R46).
12. Given the control 4, when Tab is pressed on bean 4, then `defaultPrevented` is false and the control stays 4 (Tab leaves the group natively) (R46).
13. Given the control disabled, then all 5 bean radios are disabled.
14. Given `MethodSelect` with the value null, then it shows "Choose a method". Disabling the control disables the select.

## Hard logic
```ts
onKey(event: KeyboardEvent, bean: number): void {
  const value = this.current();
  let next: number | null;
  switch (event.key) {
    case 'ArrowRight':
    case 'ArrowUp':
      next = Math.min(5, (value ?? 0) + 1); // from "Not rated" to 1; stops at 5
      break;
    case 'ArrowLeft':
    case 'ArrowDown':
      next = value === null ? null : Math.max(1, value - 1); // stays "Not rated"; stops at 1
      break;
    case ' ':
      next = bean; // Space checks the focused bean
      break;
    default:
      return; // Tab, Shift+Tab, Enter… keep their native behavior
  }
  event.preventDefault(); // native radios wrap 5 → 1 and treat ArrowUp as "previous"
  if (next === null) return;
  this.select(next);
  this.beanInputs()[next - 1].nativeElement.focus();
}
```
