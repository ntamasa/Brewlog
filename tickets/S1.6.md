## Files that change
- create `frontend/scripts/build-icons.mjs`: reads `design/prototype/icons.js`, extracts its `symbols` object literal, evaluates it with `new Function`, and writes `frontend/public/icons.svg`: `<svg xmlns="http://www.w3.org/2000/svg"><defs>` + one `<symbol id="<key>" viewBox="0 0 24 24" fill="none" stroke="currentColor" stroke-width="1.25" stroke-linecap="round" stroke-linejoin="round">…</symbol>` per key + `</defs></svg>`. Add the script `icons` = `node scripts/build-icons.mjs` to `package.json`, run it once and commit the generated `public/icons.svg`.
- create `frontend/public/images/hero-pour-over.jpg`, `beans.jpg`, `cup-notebook.jpg`: copies of `design/prototype/assets/*.jpg` (copy, never move).
- create `frontend/src/app/core/icons.ts`: `registerIcons()`.
- modify `frontend/src/app/app.config.ts`: add `provideAppInitializer(registerIcons)`.
- create `frontend/src/app/core/icons.spec.ts`: tests 1 and 3.
- create `frontend/src/app/core/icons-sprite.spec.ts`: test 2.
- create `frontend/src/svg.d.ts`: exactly `declare module '*.svg' { const content: string; export default content; }`. It types the sprite import of test 2 (`tsconfig.spec.json` already includes `src/**/*.d.ts`).
- No change to `angular.json`, and no new dependency: the `with { loader: 'text' }` import uses the Angular CLI's own esbuild text loader.

## Names and signatures
- `export function registerIcons(): void`: `inject(MatIconRegistry).addSvgIconSet(inject(DomSanitizer).bypassSecurityTrustResourceUrl('icons.svg'))`

**Happy path**

**Negative**
