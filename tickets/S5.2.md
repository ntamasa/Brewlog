## Names and signatures
- `brew-validators.ts` (Angular `ValidatorFn`s whose error keys are the API codes):
  - `requiredTrimmed: ValidatorFn` → `{ REQUIRED: true }` when the value is null, or a string that is empty after `trim()`
  - `maxTrimmedLength(max: number): ValidatorFn` → `{ TOO_LONG: true }` when `value.trim().length > max`
  - `notAfterToday: ValidatorFn` → `{ FUTURE_DATE: true }` when the `Date` is after today (browser local date, compared with date-fns `isAfter(startOfDay(value), startOfDay(new Date()))`)
  - `BREW_VALIDATORS: Record<keyof BrewFormControls, ValidatorFn[]>`: name/beanName/origin `[requiredTrimmed, maxTrimmedLength(100)]`, methodId/roast/rating `[requiredTrimmed]`, brewDate `[requiredTrimmed, notAfterToday]`, notes `[maxTrimmedLength(2000)]`
- `error-messages.ts`:
  - `brewFieldMessage(field: string, code: string, value?: string): string | null` with exactly the texts of R13, R15, R16, R18, R19 (e.g. `('origin','REQUIRED')` → "Enter where the beans are from", `('methodId','REQUIRED')` → "Choose a brew method", `('rating','REQUIRED')` → "Choose a rating from 1 to 5 beans", `('rating','OUT_OF_RANGE')` → "Choose a rating from 1 to 5 beans", `('roast','INVALID')` → "Choose a roast level", `('brewDate','REQUIRED')` → "Choose a date", `('brewDate','FUTURE_DATE')` → "The date can’t be in the future", `('name','DUPLICATE', 'kenyan morning')` → "You already have a brew called “kenyan morning”. Brew names must be unique, ignoring capitals.", `('methodId','METHOD_NOT_FOUND')` → "This method no longer exists. Choose another one."). Curly quotes and apostrophes exactly as in the spec. Field names are the API's: `name`, `beanName`, `origin`, `methodId`, `roast`, `rating`, `brewDate`, `notes`.
  - For every field/code pair not in that table (e.g. `('origin','DUPLICATE')`, `('methodId','TOO_LONG')`, `('brewDate','matDatepickerMax')`, an unknown field) it returns `null`. It never throws and never returns an empty string.
  - `BREW_ERROR_ORDER: readonly string[] = ['REQUIRED', 'TOO_LONG', 'OUT_OF_RANGE', 'INVALID', 'FUTURE_DATE', 'DUPLICATE', 'METHOD_NOT_FOUND']`: "first match wins" of the design's Field error messages table (Empty, then Too long, then Other).
  - `firstErrorCode(errors: ValidationErrors | null): string | null`: the first code of `BREW_ERROR_ORDER` that is a key of `errors`, whatever the key order inside `errors`. Keys outside the list are skipped: Material's datepicker adds `matDatepickerMax` (the input's `[max]="today"`) next to `FUTURE_DATE`, and `matDatepickerParse` next to `REQUIRED` for unparseable text. `null` when `errors` is null or holds no listed code.
  - `fieldErrorMessage(field: string, errors: ValidationErrors | null, value?: string): string | null`: `firstErrorCode(errors)`, then `brewFieldMessage(field, code, value)`; `null` when there is no code. This is the one function the form calls for a field's message.
- `api-error.ts`: `parseApiError(err: unknown): ApiError` with `interface ApiError { kind: 'fields' | 'notFound' | 'protected' | 'network'; fields: ApiFieldError[]; code: string | null }`: 400 with a non-empty `errors` array → `fields`; 404 → `notFound` with `code` from the body; 409 → `protected` with `code`; everything else (status 0, 5xx, a 400 without `errors`, non-HTTP errors) → `network`.

## Tests that prove it
**Seam:** unit · **Setup:** Vitest, `FormControl`s, `vi.setSystemTime(new Date(2026, 10, 1, 9, 0))` · **Mocked:** nothing

**Happy path**
1. `requiredTrimmed` on "Kenyan Morning" → null; `maxTrimmedLength(100)` on 100 characters → null, and on `"  " + 100 characters + "  "` → null (R15, B3).
2. `notAfterToday` on 1 Nov 2026 → null (R18).
3. `brewFieldMessage` returns each text listed above for its field and code (R13, R15, R18). `fieldErrorMessage('name', { DUPLICATE: true }, 'kenyan morning')` → "You already have a brew called “kenyan morning”. Brew names must be unique, ignoring capitals.": BREW-27 passes the trimmed name as `value` (R16).
4. `firstErrorCode({ matDatepickerMax: { max: new Date(2026, 10, 1), actual: new Date(2026, 10, 2) }, FUTURE_DATE: true })` and `firstErrorCode({ FUTURE_DATE: true, matDatepickerMax: { max: new Date(2026, 10, 1), actual: new Date(2026, 10, 2) } })` → `'FUTURE_DATE'`; `fieldErrorMessage('brewDate', { matDatepickerMax: { max: new Date(2026, 10, 1), actual: new Date(2026, 10, 2) }, FUTURE_DATE: true })` → "The date can’t be in the future" (R18).
5. `firstErrorCode({ matDatepickerParse: { text: 'not a date' }, REQUIRED: true })` → `'REQUIRED'`, and `fieldErrorMessage('brewDate', { matDatepickerParse: { text: 'not a date' }, REQUIRED: true })` → "Choose a date"; `firstErrorCode({ TOO_LONG: true, REQUIRED: true })` → `'REQUIRED'` (R13, R18).
6. `parseApiError` of a 400 `{errors:[{field:'name',code:'DUPLICATE'}]}` → `{kind:'fields', fields:[{field:'name',code:'DUPLICATE'}], code:null}`; of 404 `{code:'BREW_NOT_FOUND'}` → `{kind:'notFound', code:'BREW_NOT_FOUND', fields:[]}`; of 409 `{code:'PROTECTED'}` → `kind` `protected`.

**Negative**
7. `requiredTrimmed` on `"   "`, `''` and `null` → `{ REQUIRED: true }` (R13, R14).
8. `maxTrimmedLength(100)` on 101 characters → `{ TOO_LONG: true }`; `maxTrimmedLength(2000)` on 2001 → `{ TOO_LONG: true }` (R15).
9. `notAfterToday` on 2 Nov 2026 → `{ FUTURE_DATE: true }` (R18).
10. `brewFieldMessage('origin','DUPLICATE')`, `brewFieldMessage('methodId','TOO_LONG')`, `brewFieldMessage('brewDate','matDatepickerMax')` and `brewFieldMessage('unknown','REQUIRED')` → `null` (not `''`, no throw).
11. `firstErrorCode({ matDatepickerMax: { max: new Date(2026, 10, 1), actual: new Date(2026, 10, 2) } })`, `firstErrorCode({})` and `firstErrorCode(null)` → `null`; `fieldErrorMessage('brewDate', { matDatepickerMax: { max: new Date(2026, 10, 1), actual: new Date(2026, 10, 2) } })` → `null`.
12. `parseApiError` of status 0, of 503, and of a 400 with no `errors` → `kind` `network` (R20, R41).
