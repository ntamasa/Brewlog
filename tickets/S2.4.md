## Names and signatures
- `Pagination`: `page = input.required<number>()`, `totalPages = input.required<number>()`, `pageChange = output<number>()`. Renders ‹, every page number 1…totalPages, ›; current page has `aria-current="page"`; ‹ disabled on page 1, › disabled on the last page; renders nothing when `totalPages <= 1`.
- `JournalPage`: on init reads `queryFromParams(route.snapshot.queryParamMap)` and calls `store.setQuery(...)`; on `pageChange` calls `store.setPage(n)` and `router.navigate([], { queryParams: queryToParams(store.query()) })`. Count text: `brewCount(totalCount)`. Footer: "Showing {first}–{last} of {matchingCount}" where `first = (page - 1) * 12 + 1`, `last = first + items.length - 1`.

## Tests that prove it
**Seam:** component (`Pagination`) · **Setup:** TestBed · **Mocked:** nothing

**Happy path**
1. Given page 1 of 4, then buttons "1", "2", "3", "4" show, "1" has `aria-current="page"`, ‹ is disabled and › is enabled (R2).
2. Given page 2 of 4, when "3" is clicked, then `pageChange` emits 3; when › is clicked, it emits 3; when ‹ is clicked, it emits 1.

**Negative**
3. Given page 4 of 4, then › is disabled. Given 1 page, then nothing is rendered.

**Seam:** integration (`JournalPage`) · **Setup:** TestBed, real `JournalStore` and `BrewApi`, `provideRouter(routes)`, `RouterTestingHarness` · **Mocked:** HTTP (`HttpTestingController`)

**Happy path**
4. Given `/journal`, when GET `/api/brews?sort=NEWEST&page=1` is flushed with 12 items and `{page: 1, totalPages: 4, matchingCount: 41, totalCount: 41}`, then the count reads "41 brews", 12 cards render in the response order, the footer reads "Showing 1–12 of 41" and pages 1–4 show with ‹ disabled (R2).
5. Given that state, when page "4" is clicked, then GET `…&page=4` is sent and the URL has `page=4`; flushing 5 items gives "Showing 37–41 of 41" (R2).

**Negative**
6. Given `/journal?page=2`, then the first request is for `page=2` (B20).
