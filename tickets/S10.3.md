## Names and signatures
- `JournalToolbar`: `query = input.required<BrewQuery>()`, `search = output<string>()` (emits on every input event; the store debounces). The field shows `query().q` when the query changes from outside (chip removal, URL).
- `FilterChips`: `query = input.required<BrewQuery>()`, `remove = output<'q' | 'methodId' | 'roast' | 'minRating'>()`, `clearAll = output<void>()`; for now one chip for a non-blank search, text `“<q trimmed>”` with × (aria-label "Clear search"), then ghost "Clear all". Renders nothing when `isFiltered` is false.
- `JournalStore.clearFilters()`: `setQuery({ ...DEFAULT_QUERY, sort: query().sort })` (keeps the sort). `JournalStore.removeFilter(key)`: sets that key to its default and `page: 1`.
- Count: `isFiltered()` → `matchingCount + ' of ' + brewCount(totalCount)` (e.g. "2 of 41 brews", "0 of 41 brews"); else `brewCount(totalCount)`; `totalCount` 0 → "No brews yet".
- The toolbar and chips are hidden only in the empty state: `@if (!isEmpty())` around both, with the existing `isEmpty()` of `journal-page.ts` (`status() === 'ready' && totalCount() === 0`, R3; `brews.md` state empty: "Toolbar hidden"). Never test `totalCount() === 0` alone: the store starts with `totalCount` 0, so that would hide the toolbar during the first load and after a first-load error. In loading (first load or page change) and error the toolbar shows: `brews.html` line 84, the toolbar's `data-states` include `loading` and `error`. The chips there follow `FilterChips`' own rule (nothing unless `isFiltered`).
- No-results panel when `status() === 'ready'`, `totalCount > 0`, `matchingCount === 0`: search art, "No brews match", "Nothing in your journal matches “<q>” with these filters. Try a different name or loosen a filter.", `button-secondary` "Clear search and filters" → `clearFilters()`. `<q>` is `query().q.trim()`, the same text as the chip (B3, B17): `q: '  panama natural '` reads “panama natural”.
- Footer in no-results: `journal-page.html` today renders `<div class="list-foot">` (footer text + `app-pagination`) whenever `isEmpty()` is false, so no-results shows "Showing 1–0 of 0". Change the `@else` branch of `@case ('ready')` to: `@if (store.matchingCount() === 0) {` the no-results panel `} @else {` the `.brew-grid` and the `.list-foot` exactly as today `}`. So in no-results there is no `.brew-grid`, no `.list-foot`, no `app-pagination` and no "Showing" text, at every width. Source: `design/prototype/screens/brews.html` has `.list-foot` only for the states "default card-menu saved" (line 399), "many-pages" (line 411) and "filtered filters-sheet filters-sheet-any" (line 426), none for "no-results"; `design/screenshots/brews.no-results.desktop.png` and `.mobile.png` show no footer. `footerText()` stays as it is.
