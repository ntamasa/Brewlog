## Names and signatures
- `JournalToolbar`: `query = input.required<BrewQuery>()`, `search = output<string>()` (emits on every input event; the store debounces). The field shows `query().q` when the query changes from outside (chip removal, URL).
- `FilterChips`: `query = input.required<BrewQuery>()`, `remove = output<'q' | 'methodId' | 'roast' | 'minRating'>()`, `clearAll = output<void>()`; for now one chip for a non-blank search, text `“<q trimmed>”` with × (aria-label "Clear search"), then ghost "Clear all". Renders nothing when `isFiltered` is false.
- `JournalStore.clearFilters()`: `setQuery({ ...DEFAULT_QUERY, sort: query().sort })` (keeps the sort). `JournalStore.removeFilter(key)`: sets that key to its default and `page: 1`.
- Count: `isFiltered()` → `matchingCount + ' of ' + brewCount(totalCount)` (e.g. "2 of 41 brews", "0 of 41 brews"); else `brewCount(totalCount)`; `totalCount` 0 → "No brews yet".
- The toolbar and chips are hidden when `totalCount() === 0` (empty journal, R3).
- No-results panel when `status() === 'ready'`, `totalCount > 0`, `matchingCount === 0`: search art, "No brews match", "Nothing in your journal matches “<q>” with these filters. Try a different name or loosen a filter.", `button-secondary` "Clear search and filters" → `clearFilters()`. `<q>` is `query().q.trim()`, the same text as the chip (B3, B17): `q: '  panama natural '` reads “panama natural”.

## Tests that prove it
**Seam:** component (`FilterChips`) · **Setup:** TestBed · **Mocked:** nothing
1. Given `q: '  kenya '`, then one chip reads "“kenya”" and "Clear all" shows; clicking × emits `remove('q')`; clicking "Clear all" emits `clearAll` (R5).
2. Given `DEFAULT_QUERY`, then nothing renders (R5).

**Seam:** integration (`JournalPage`) · **Setup:** TestBed, real store and API, `vi.useFakeTimers()`, the `MAT_FORM_FIELD_DEFAULT_OPTIONS` provider of BREW-100; Search is `MatInputHarness.with({ selector: '#q' })` (Form fields → Tests) · **Mocked:** HTTP

**Happy path**
3. Given 41 brews, when "  kenya " is typed in Search and 250 ms pass, then GET `…q=kenya…page=1` is sent; flushing 2 items with `matchingCount` 2, `totalCount` 41 shows 2 cards, the count "2 of 41 brews", the chip "“kenya”" and the URL `q=kenya` (R5).
4. Given "  panama natural " typed in Search and answered with 0 items, `totalCount` 41, then the count reads "0 of 41 brews" and the panel reads "No brews match" / "Nothing in your journal matches “panama natural” with these filters. Try a different name or loosen a filter." (R11).
5. Given that panel, when "Clear search and filters" is clicked, then GET without `q` and `page=1` is sent, the Search field is empty and the chip is gone (R11).

**Negative**
6. Given only spaces typed in Search, then the request has no `q`, the count reads "41 brews" and no chip shows (R5).
7. Given 1 match of 41, then the count reads "1 of 41 brews" (B23).
8. Given `totalCount` 0, then neither the toolbar nor the chips render (R3).

**Seam:** E2E · **Setup:** compose stack, both projects (`desktop` 1440×900 and `phone` 390×844), no `test.skip`; brews `<p> Kenyan Morning`, `<p> KENYA AA Batch`, `<p> Sunday Moka` created with `page.request.post('/api/brews', …)` (body per Epic → API) with `p = uniqueName('S')`; Search found by `page.getByPlaceholder('Search brew names')`, never by id, so the test still passes on `phone` once BREW-52 replaces `#q` with `#q-m` (same placeholder) · **Mocked:** nothing
9. Given `/journal`, when "  <p> kenya " is typed in Search, then exactly the two Kenya cards show, the chip "“<p> kenya”" (trimmed) is visible and the URL contains `q=` (R5). Same steps and checks on `phone`: there the Search field is the `.toolbar` one, visible, and nothing else is asserted about the phone layout (R42 is checked by BREW-52 and BREW-83).
