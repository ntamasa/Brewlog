**Goal:** Delete a method with `POST /api/methods/{id}/delete`, moving its brews to the chosen targets or "Other", tolerant of stale data, and protect "Other".

**Read first:**
- Epic → Technical design → API, Backend, Hard logic (delete method M)
- Story → Acceptance criteria (R34, R36, R37), Business rules (B11, B14, B15)

## Files that change
- create `backend/src/main/java/com/brewlog/dto/DeleteMethodRequest.java`, `dto/Reassignment.java`, `dto/DeleteMethodResponse.java`.
- modify `service/BrewMethodService.java`: `delete`; `controller/BrewMethodController.java`: `POST /api/methods/{id}/delete`.
- create `backend/src/test/java/com/brewlog/MethodDeleteIT.java`, `service/BrewMethodServiceTest.java`.

## Names and signatures
- `record Reassignment(Long brewId, Long methodId)`; `record DeleteMethodRequest(List<Reassignment> reassignments)` (null → empty list); `record DeleteMethodResponse(int reassignedBrewCount)`.
- `BrewMethodService.delete(long id, DeleteMethodRequest request): DeleteMethodResponse`, `@Transactional`, exactly as Epic → Hard logic: 404 `METHOD_NOT_FOUND`; protected → `ProtectedMethodException` (409); any `r.methodId == id` → `ValidationException([FieldErrorDto("reassignments", INVALID)])`; `other = findByIsProtectedTrue()`; target ids that exist = `brewMethodRepository.findAllById(…)`; for each brew of `findByMethodId(id)`: its listed target if that target exists, else `other`; entries for brews not of M are ignored; delete M; return the number of brews of M.

## Tests that prove it
**Seam:** HTTP API · **Setup:** `MethodDeleteIT extends IntegrationTest`, `TestData` · **Mocked:** nothing

**Happy path**
1. Given custom "Kalita Wave" with 0 brews, POST `/api/methods/<id>/delete` `{"reassignments":[]}` → 200 `{"reassignedBrewCount":0}` and it's gone from `GET /api/methods` (R34).
2. Given Moka Pot (5) with brews b1, b2, b3, POST `{"reassignments":[{"brewId":b1,"methodId":7},{"brewId":b2,"methodId":7},{"brewId":b3,"methodId":4}]}` → 200 `{"reassignedBrewCount":3}`; b1, b2 have Other, b3 AeroPress; Moka Pot is gone (B14).
3. Given Moka Pot with b1, b2, b3 and brew x of Espresso: request `[{b1 → 999 (no such method)}, {x → 4}, {12345 (no such brew) → 4}]` (b2, b3 not listed) → 200 `{"reassignedBrewCount":3}`; b1, b2, b3 have Other; x is still Espresso (R36).

**Negative**
4. POST on Moka Pot with `[{"brewId":b1,"methodId":5}]` (itself) → 400 `[{"field":"reassignments","code":"INVALID"}]`; Moka Pot and b1 unchanged (R36).
5. POST on Other (id 7) → 409 `"code":"PROTECTED"`; PUT `/api/methods/7` `{"name":"Misc"}` → 409 `"code":"PROTECTED"`; Other unchanged (R37).
6. POST `/api/methods/999/delete` → 404 `"code":"METHOD_NOT_FOUND"`.

**Seam:** unit (`BrewMethodServiceTest`) · **Setup:** JUnit 5 + Mockito · **Mocked:** repositories
7. Given M with brews [b1, b2], other = Other, targets {b1 → 999} where 999 isn't found, then b1 and b2 get Other, `delete(M)` is called once and the result is 2 (R36).
