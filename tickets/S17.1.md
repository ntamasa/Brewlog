**Goal:** List the brews of a method, newest first, with `GET /api/methods/{id}/brews`.

**Read first:**
- Epic → Technical design → API; Technical design → Backend (below, from the spec)
- Story → Acceptance criteria (R33), Business rules (B13, B19)

## Files that change
- create `backend/src/main/java/com/brewlog/dto/MethodBrewResponse.java`.
- modify `repository/BrewRepository.java`: `findByMethodId(long methodId, Sort sort)` (keep the unsorted one for the delete story).
- modify `service/BrewMethodService.java`: `brewsOf`; `controller/BrewMethodController.java`: `GET /api/methods/{id}/brews`.
- create `backend/src/test/java/com/brewlog/MethodBrewsIT.java`.

## Names and signatures
- `record MethodBrewResponse(long id, String name, String beanName, String origin, LocalDate brewDate)`
- `BrewMethodService.brewsOf(long id): List<MethodBrewResponse>`: missing method → `NotFoundException(METHOD_NOT_FOUND)`; else `findByMethodId(id, BrewSort.toSort(NEWEST))`.

## Tests that prove it
**Seam:** HTTP API · **Setup:** `MethodBrewsIT extends IntegrationTest`, `TestData` · **Mocked:** nothing

**Happy path**
1. Given Pour Over with 14 brews (distinct dates) and Espresso with 1, `GET /api/methods/2/brews` → 200 with 14 entries `{id, name, beanName, origin, brewDate}`, latest date first (R33).
2. Given two Pour Over brews on the same date, the later-added one comes first (B19).

**Negative**
3. Given Chemex with 0 brews → 200 `[]`.
4. `GET /api/methods/999/brews` → 404 `"code": "METHOD_NOT_FOUND"`.
