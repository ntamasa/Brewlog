**Goal:** Reject duplicate brew names (ignoring case, also under parallel saves) and methods that no longer exist.

**Read first:**
- Epic → Technical design → API (errors), Backend, Risks (parallel saves); Story → Hard logic
- Story → Acceptance criteria (R16, R19), Business rules (B5, B25)

## Files that change
- modify `backend/src/main/java/com/brewlog/service/BrewValidator.java`: gets `BrewRepository` and `BrewMethodRepository` injected (next to the `Clock`); adds the two checks below.
- modify `exception/ApiExceptionHandler.java`: `DataIntegrityViolationException` whose message contains `ux_brew_name` → 400 `errors: [{field: "name", code: "DUPLICATE"}]`; containing `ux_brew_method_name` → 400 `[{field: "name", code: "DUPLICATE"}]`; any other → 500.
- modify `service/BrewValidatorTest.java` (repositories mocked with Mockito); create `backend/src/test/java/com/brewlog/BrewConflictIT.java`.

## Names and signatures
- `name` (after the existing checks pass): `brewRepository.existsByNameIgnoreCaseAndIdNot(name, selfId == null ? -1L : selfId)` → `DUPLICATE`.
- `methodId` (when not null): `!brewMethodRepository.existsById(methodId)` → `METHOD_NOT_FOUND`.

## Tests that prove it
**Seam:** unit · **Setup:** JUnit 5 + Mockito · **Mocked:** repositories

**Happy path**
1. Given `existsByNameIgnoreCaseAndIdNot("Kenyan Morning", -1)` false and method 2 exists → no errors.

**Negative**
2. Given `existsByNameIgnoreCaseAndIdNot("kenyan morning", -1)` true → `name` `DUPLICATE` (R16).
3. Given `existsById(9)` false → `methodId` `METHOD_NOT_FOUND` (R19).

**Seam:** HTTP API (`BrewConflictIT`) · **Setup:** `IntegrationTest`, `TestData` · **Mocked:** nothing
4. Given "Kenyan Morning", when POST a valid brew named "kenyan morning", then 400 `{"errors":[{"field":"name","code":"DUPLICATE"}]}` and `brew` still has 1 row (R16).
5. Given method "Kalita Wave" inserted then deleted with `jdbc`, when POST with its id, then 400 `[{"field":"methodId","code":"METHOD_NOT_FOUND"}]` and nothing is saved (R19).
6. Given no brews, when two POSTs of "Parallel Brew" run at the same time (two threads, `CountDownLatch` start), then exactly one answers 201 and the other 400 `name` `DUPLICATE`, and `brew` has 1 row (R16).
