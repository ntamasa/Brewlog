## Tests that prove it

So, as BREW-26 does:
1. **Stub commit** (`BREW-29: Add stubs for the validator's repositories and the duplicate-name query`), before any test: `BrewValidator`'s constructor taking `BrewRepository` and `BrewMethodRepository` next to the `Clock` (stored, unused), and the derived query `boolean existsByNameIgnoreCaseAndIdNot(String name, Long id)` on `BrewRepository` (a Spring Data declaration, no body), each under its exact name and signature from "Names and signatures", and no behavior: every new method only throws `new UnsupportedOperationException("BREW-29: not implemented")`; a new record or exception class is written in full (it has no behavior). `cd backend && ./gradlew compileJava` passes on it (an existing test that calls a changed constructor compiles again once the red commit updates it). No test file in this commit, no red mark.
2. **Red commit:** only the test files. Every new test fails on a stub's "BREW-29: not implemented" error, on an assertion, or on an element the stubs don't render, never on a missing module, import or type error. A new test that already passes on the stubs (one that checks that something is absent, `false` or `null`) is a guard, not a blocker: commit it in the red commit too, and after green prove it can fail with the smallest edit to the code it guards, then revert; name the test and the edit in the report.
3. **Green:** fill the stubs. The test files stay as committed.
