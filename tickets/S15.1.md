**Goal:** Add "+ Add new method…" to the form's method list: an inline box that saves the method and selects it.

**Read first:**

## Files that change
- modify `frontend/src/app/brew-form/method-select/method-select.ts`, `.html`, `.scss`, `.spec.ts`.

## Names and signatures
- `MethodSelect`: option "+ Add new method…" (terracotta, after the divider, before "Manage methods…") switches `adding = signal(true)`: the select is replaced by a terracotta-soft box with label "New method name", a focused input, `button-primary` "Add", help "It will be saved and selected for this brew." and ghost "Cancel" (back to the select, value unchanged).
- "Add" / Enter: `checkMethodName(value, methods(), null)` → `methodNameMessage(code, existing, 'form')` under the input, nothing sent; else `MethodStore.add(value)`; success: `adding` false, the control value becomes the new id (`onChange(id)`); 400 → the matching message; network → "Couldn’t save the method. Try again." with the input keeping its value.

## Tests that prove it
**Seam:** integration (`BrewForm` with `MethodSelect`) · **Setup:** TestBed + harnesses, real `MethodStore` and `MethodApi` · **Mocked:** HTTP (`HttpTestingController`)

**Happy path**
1. Given the form with name "Kenyan Morning" and roast Light, when "+ Add new method…" is chosen, "Chemex" typed and "Add" clicked, then POST `/api/methods` `{"name":"Chemex"}` is sent; after 201 (id 8) the select shows "Chemex", the method control is 8, and name and roast are unchanged (R31).
2. Given the add box, when "Cancel" is clicked, then the select shows again with the previous value (R31).

**Negative**
3. Given an empty input, when "Add" is clicked, then "Enter a method name" shows and nothing is sent (R31).
4. Given "pour over", then "“Pour Over” already exists." shows and nothing is sent (R31, B12).
5. Given 51 characters, then "Method name can be at most 50 characters" (R31).
6. Given the POST fails with 503, then "Couldn’t save the method. Try again." shows and the input still reads "Chemex" (R31).
