## Names and signatures
- `MethodSelect`: option "+ Add new method…" (after the divider, before "Manage methods…"; `plus` icon and class `add`, like "Manage methods…" in BREW-60) switches `adding = signal(true)`: inside the same `.field[data-field="method"]`, under the "Brew method" label, the select's form field is replaced by the terracotta-soft box `.add-method` (`brew-form.html` lines 158–168 and `<style>` lines 32–34): `<label class="field-label" for="new-method">New method name</label>`, a `.row` with a `<mat-form-field>` holding the focused `<input matInput id="new-method" />` and `button-primary` "Add", then the prototype's `<p class="field-help">It will be saved and selected for this brew.</p>` beside ghost "Cancel" (back to the select, value unchanged).
- "Add" / Enter: `checkMethodName(value, methods(), null)` → `methodNameMessage(code, existing, 'form')` as `<mat-error class="field-error">` with the `alert` icon inside the input's form field, nothing sent. `addError = signal<string | null>(null)` holds the message; the input's form field is in the error state while it is set (`[errorStateMatcher]="addErrorMatcher"`, as in BREW-60, Form fields → Error state, kept in sync by the effect in Hard logic), and choosing "+ Add new method…" and each Add first set it back to null; else `MethodStore.add(value, 'quick-add')` (BREW-59: the store's `pending` is `'quick-add'` while it runs; the next subtask, BREW-107, makes "Add" busy and blocks the primary with it); success: `adding` false, the control value becomes the new id (`onChange(id)`); 400 → the matching message; network → "Couldn’t save the method. Try again." with the input keeping its value.
- Error state of `#new-method`: `MatInput.ngDoCheck` re-runs its matcher only when the input has an ngControl (`@angular/material/fesm2022/input.mjs` lines 204–210, checked on Material 22.3.0), `#new-method` has none (a plain `matInput`, value read from the element, no `FormControl`), and `errorState` is no input, so `[errorStateMatcher]` alone never shows `mat-form-field-invalid` or the `mat-error`. So `#new-method` gets `#quickAddInput`, `MethodSelect` gets `private readonly quickAddInput = viewChild('quickAddInput', { read: MatInput })` (`MatInput` from `@angular/material/input`) and the first effect in Hard logic.
- The select is gone while the box shows, so `matSelect` (BREW-21) becomes `viewChild(MatSelect)`, not `required`: BREW-27's effect reads it and re-runs when the select leaves and comes back, and a required query throws NG0951 while it is absent. That effect becomes the second one in Hard logic (it now also restores the error state on the new `mat-select` after "Cancel" or a successful Add), and `closeOnEscape` starts with `const matSelect = this.matSelect(); if (!matSelect?.panelOpen) return;`.

## Tests that prove it
**Seam:** integration (`BrewForm` with `MethodSelect`) · **Setup:** TestBed + harnesses, real `MethodStore` and `MethodApi`, the `MAT_FORM_FIELD_DEFAULT_OPTIONS` provider of BREW-100; the input is `MatInputHarness.with({ selector: '#new-method' })` and its message `MatFormFieldHarness.with({ ancestor: '.add-method' }).getTextErrors()` · **Mocked:** HTTP (`HttpTestingController`)

**Happy path**

**Negative**

7. Given test 3's error shown, when "Cancel" is clicked and "+ Add new method…" chosen again, then the box's field has no `mat-form-field-invalid` and its `getTextErrors()` is `[]` (R31).
8. Given an empty create form and "Add to journal" clicked (the method field shows "Choose a brew method"), when "+ Add new method…" is chosen, then the box shows and no error is thrown; when "Cancel" is clicked, then the method form field (`[data-field="method"]`) has `mat-form-field-invalid` and `getTextErrors()` `["Choose a brew method"]` again (R31). With `matSelect` still `viewChild.required` this test fails.

## Hard logic
```ts
private readonly matSelect = viewChild(MatSelect);
private readonly quickAddInput = viewChild('quickAddInput', { read: MatInput });

constructor() {
  // Neither control has an ngControl, so Material never re-runs their matchers by itself:
  // re-run each one when its message changes or the control (re)appears.
  effect(() => {
    this.addError();
    this.quickAddInput()?.updateErrorState();
  });
  effect(() => {
    this.error();
    this.matSelect()?.updateErrorState();
  });
}
```
