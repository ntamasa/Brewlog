## Names and signatures
- `MethodSelect`: option "+ Add new method…" (after the divider, before "Manage methods…"; `plus` icon and class `add`, like "Manage methods…" in BREW-60) switches `adding = signal(true)`: inside the same `.field[data-field="method"]`, under the "Brew method" label, the select's form field is replaced by the terracotta-soft box `.add-method` (`brew-form.html` lines 158–168 and `<style>` lines 32–34): `<label class="field-label" for="new-method">New method name</label>`, a `.row` with a `<mat-form-field>` holding the focused `<input matInput id="new-method" />` and `button-primary` "Add", then the prototype's `<p class="field-help">It will be saved and selected for this brew.</p>` beside ghost "Cancel" (back to the select, value unchanged).
- "Add" / Enter: `checkMethodName(value, methods(), null)` → `methodNameMessage(code, existing, 'form')` as `<mat-error class="field-error">` with the `alert` icon inside the input's form field, nothing sent. `addError = signal<string | null>(null)` holds the message; the input's form field is in the error state while it is set (`[errorStateMatcher]`, as `addErrorMatcher` in BREW-60, Form fields → Error state), and each Add first sets it back to null; else `MethodStore.add(value, 'quick-add')` (BREW-59: the store's `pending` is `'quick-add'` while it runs; the next subtask, BREW-107, makes "Add" busy and blocks the primary with it); success: `adding` false, the control value becomes the new id (`onChange(id)`); 400 → the matching message; network → "Couldn’t save the method. Try again." with the input keeping its value.

## Tests that prove it
**Seam:** integration (`BrewForm` with `MethodSelect`) · **Setup:** TestBed + harnesses, real `MethodStore` and `MethodApi`, the `MAT_FORM_FIELD_DEFAULT_OPTIONS` provider of BREW-100; the input is `MatInputHarness.with({ selector: '#new-method' })` and its message `MatFormFieldHarness.with({ ancestor: '.add-method' }).getTextErrors()` · **Mocked:** HTTP (`HttpTestingController`)

**Happy path**
1. Given the form with name "Kenyan Morning" and roast Light, when "+ Add new method…" is chosen, "Chemex" typed and "Add" clicked, then POST `/api/methods` `{"name":"Chemex"}` is sent; after 201 (id 8) the select shows "Chemex", the method control is 8, and name and roast are unchanged (R31).
2. Given the add box, when "Cancel" is clicked, then the select shows again with the previous value (R31).

**Negative**
3. Given an empty input, when "Add" is clicked, then the error reads "Enter a method name" with an `alert` icon, the input's form field has `mat-form-field-invalid`, and nothing is sent (R31).
4. Given "pour over", then "“Pour Over” already exists." shows and nothing is sent (R31, B12).
5. Given 51 characters, then "Method name can be at most 50 characters" (R31).
6. Given the POST fails with 503, then "Couldn’t save the method. Try again." shows and the input still reads "Chemex" (R31).

## Out of scope
- "Add" busy and blocked, the input disabled while it runs and refocused after a failure, and the primary blocked meanwhile (BREW-107).
