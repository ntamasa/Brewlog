**Goal:** Bring the design system into the app: tokens, Material theme, fonts, the icon sprite and the landing photos.

**Read first:**
- Story → UI implementation, Frontend
- `design/DESIGN.md`, `design/prototype/tokens.css`, `design/prototype/components.css`, `design/prototype/icons.js`, `design/prototype/index.html` (font links, lines 3–5)

## Files that change
- create `frontend/src/styles/tokens.css`: exact copy of `design/prototype/tokens.css`.
- create `frontend/src/styles/theme.scss`: `mat.theme` (Brewlog primary/tertiary, typography `plain-family` Inter, `brand-family` Cormorant Garamond, density 0) plus the `mat.button-overrides`, `mat.form-field-overrides`, `mat.select-overrides`, `mat.dialog-overrides`, `mat.bottom-sheet-overrides`, `mat.snack-bar-overrides`, `mat.card-overrides`, `mat.button-toggle-overrides`, `mat.datepicker-overrides`, `mat.menu-overrides`, `mat.sidenav-overrides` mixins, every value a `var(--color-*)`, `var(--radius-*)` or `var(--text-*)` from tokens.css. Never `::ng-deep`.
- create `frontend/src/styles/base.scss`: the global base rules of `design/prototype/components.css` (body font, background, text colour, focus ring, `.sr-only`, reduced-motion rule).
- modify `frontend/src/styles.scss`: include tokens.css, theme.scss, base.scss in that order.
- modify `frontend/src/index.html`: `<title>Brewlog</title>` and the three Google Fonts tags from `design/prototype/index.html` lines 3–5.
- create `frontend/scripts/build-icons.mjs`: reads `design/prototype/icons.js`, extracts its `symbols` object literal, evaluates it with `new Function`, and writes `frontend/public/icons.svg`: `<svg xmlns="http://www.w3.org/2000/svg"><defs>` + one `<symbol id="<key>" viewBox="0 0 24 24" fill="none" stroke="currentColor" stroke-width="1.25" stroke-linecap="round" stroke-linejoin="round">…</symbol>` per key + `</defs></svg>`. Add the script `icons` = `node scripts/build-icons.mjs` to `package.json`, run it once and commit the generated `public/icons.svg`.
- create `frontend/public/images/hero-pour-over.jpg`, `beans.jpg`, `cup-notebook.jpg`: copies of `design/prototype/assets/*.jpg` (copy, never move).
- create `frontend/src/app/core/icons.ts`: `registerIcons()`.
- modify `frontend/src/app/app.config.ts`: add `provideAppInitializer(registerIcons)`.

## Names and signatures
- `export function registerIcons(): void`: `inject(MatIconRegistry).addSvgIconSet(inject(DomSanitizer).bypassSecurityTrustResourceUrl('icons.svg'))`

## Tests that prove it
**Seam:** `MatIconRegistry` · **Setup:** TestBed with `provideHttpClient()`, `provideHttpClientTesting()`, `provideAppInitializer(registerIcons)` · **Mocked:** HTTP (`HttpTestingController`)

**Happy path**
1. Given the initializer ran, when `getNamedSvgIcon('logo')` is subscribed, then one GET `icons.svg` is made, and after flushing `<svg><defs><symbol id="logo" viewBox="0 0 24 24"><circle r="1"/></symbol></defs></svg>` it emits an `SVGElement` containing a `circle`.
2. Given the generated `public/icons.svg` (imported with `?raw`), then it contains `<symbol id="…">` for each of `logo`, `bean`, `bean-fill`, `espresso`, `pour-over`, `french-press`, `aeropress`, `moka-pot`, `cold-brew`, `cup`, `search`, `sliders`, `plus`, `more`, `close`, `edit`, `trash`, `lock`, `alert`, `check`, `refresh`, `calendar`.

**Negative**
3. Given the same flushed sprite, when `getNamedSvgIcon('no-such-icon')` is subscribed, then it errors with a message containing `no-such-icon`.

## Out of scope
- Styles of individual screens: each screen subtask ports its own part of `components.css`.
