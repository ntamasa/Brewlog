## Names and signatures
- `MethodSelect` injects `MethodStore` and gets:
  - `protected readonly addBusy = computed(() => this.methodStore.pending() === 'quick-add')`
  - `protected readonly addBlocked = computed(() => this.isDisabled() || (this.methodStore.pending() !== null && this.methodStore.pending() !== 'quick-add'))`
- Quick-add "Add" (`matButton="filled"`, label "Add", no spinner): `[disabled]="addBusy() || addBlocked()"`, `disabledInteractive`, `[attr.aria-busy]="addBusy() ? 'true' : null"`, `[tabIndex]="addBlocked() ? -1 : 0"`.
- `#new-method`: `[disabled]="addBusy()"`. The box's ghost "Cancel" never gets `[disabled]` (B26).
- The Add handler (button and Enter) starts with `if (this.methodStore.pending() !== null || this.isDisabled()) return;` (R48: a click on a busy or blocked "Add" sends nothing).
- After an error answer (400 or network), `#new-method` is focused after the next render, when it is enabled again: `afterNextRender(() => this.newMethodInput()?.nativeElement.focus(), { injector: this.injector })` from the `error` callback, with `newMethodInput = viewChild<ElementRef<HTMLInputElement>>('newMethodInput')` and `#newMethodInput` on the input. Inside the callback `pending()` is still `'quick-add'` (BREW-59), so a direct `focus()` would hit a disabled input. The value stays as typed.
- `BrewForm` injects `MethodStore` and gets `protected readonly quickAddPending = computed(() => this.methodStore.pending() === 'quick-add')`. The primary becomes `[disabled]="saving() || quickAddPending()"`, `[tabIndex]="quickAddPending() ? -1 : 0"`; `disabledInteractive`, `[attr.aria-busy]="saving() ? 'true' : null"` and its labels stay. `submit()` starts with `if (this.saving() || this.quickAddPending()) return;`: blocked, the primary sends nothing (R48). "Cancel" and × stay enabled.

## Tests that prove it
**Seam:** integration (`BrewForm` with `MethodSelect`) · **Setup:** as BREW-62 (TestBed + harnesses, real `MethodStore` and `MethodApi`, the `MAT_FORM_FIELD_DEFAULT_OPTIONS` provider of BREW-100); "Add" is `MatButtonHarness.with({ ancestor: '.add-method', text: 'Add' })`, the input `MatInputHarness.with({ selector: '#new-method' })` · **Mocked:** HTTP (`HttpTestingController`)

Setup for tests 1–4: the form filled valid (`fillValid()`: Pour Over, Light, 5 beans), then "+ Add new method…" chosen, "Chemex" typed and "Add" clicked; POST `/api/methods` not flushed yet.

**Happy path**
1. Then "Add" has `aria-busy="true"` and `aria-disabled="true"`, no `disabled` attribute, the text "Add" and no `span.spinner`; `#new-method` is disabled and reads "Chemex"; the primary reads "Add to journal" with `aria-disabled="true"`, `tabindex="-1"` and no `aria-busy`; the box's "Cancel" and the foot's "Cancel" have neither `disabled` nor `aria-disabled` (R48, R49, B26).
2. When the POST answers 201 Chemex (id 8), then the select shows "Chemex", and the primary has no `aria-disabled="true"` and `tabindex="0"` (R48, R31).

**Negative**
3. When "Add" is clicked again, then there is still exactly one POST `/api/methods`; when "Add to journal" is clicked, then no POST `/api/brews` is sent (`http.expectNone('/api/brews')`) (R48). Mutation: temporarily drop `|| this.quickAddPending()` from `submit()`'s guard, and test 3 fails with a POST `/api/brews`; revert.
4. When the POST answers 503, then "Couldn’t save the method. Try again." shows, "Add" has no `aria-busy` and no `aria-disabled="true"`, `#new-method` is enabled, still reads "Chemex" and is `document.activeElement` (after `await fixture.whenStable()`), and the primary has no `aria-disabled="true"` (R48, R49).
5. Given the valid form with Pour Over and the quick-add box open with "Chemex", when "Add to journal" is clicked (POST `/api/brews` not flushed), then "Add" has `aria-disabled="true"`, `tabindex="-1"` and no `aria-busy`, and clicking it sends no POST `/api/methods` (`http.expectNone('/api/methods')`) (R48: blocked while the form saves). The POST `/api/brews` is flushed with 201 at the end.
