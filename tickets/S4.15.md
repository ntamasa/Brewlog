**Goal:** A card highlighted by a later save keeps its highlight for its full 1.2 s: the timer of an earlier `highlight()` call never clears it early.

**Source (review of PR #6):** `JournalStore.highlight(id)` (`frontend/src/app/journal/journal.store.ts`) starts a new 1200 ms timer on every call and never cancels the previous one, so the first call's timer sets `highlightId` to `null` while a second brew saved 600 ms later is still meant to be highlighted. The highlight lasts ~1.2 s per save: `design/screens/brews.md` → States → saved: "that card gets `brew-card-highlight` (terracotta-soft fill + terracotta border), fading back over ~1.2s".

## Files that change
- modify `frontend/src/app/journal/journal.store.ts`: `highlight()` cancels the previous timer before it starts its own.
- modify `frontend/src/app/journal/journal.store.spec.ts`: the tests below.

## Names and signatures
- No new public names. `highlight(id: number): void` keeps its signature.
- Inside `withMethods`, next to `const api = inject(BrewApi);`: `let highlightTimer: ReturnType<typeof setTimeout> | undefined;`

## Hard logic
```ts
highlight(id: number): void {
  clearTimeout(highlightTimer);
  patchState(store, { highlightId: id });
  highlightTimer = setTimeout(() => patchState(store, { highlightId: null }), 1200);
},
```
Cancel the timer, don't compare ids in the callback: test 4 highlights the same id twice, and an `if (store.highlightId() === id)` check would still clear it 1200 ms after the first call.

## Tests that prove it
**Seam:** store (`JournalStore`) · **Setup:** like `journal.store.spec.ts` (`setUp(() => of(FIRST_PAGE))`), with `vi.useFakeTimers()` before the first `highlight()` and `vi.useRealTimers()` in an `afterEach` · **Mocked:** `BrewApi`

**Happy path**
1. Given no highlight, when `highlight(7)` is called, then `highlightId()` is 7; after `vi.advanceTimersByTime(1199)` it is still 7; after 1 ms more it is `null` (R12).
2. Given `highlight(7)`, when 600 ms later `highlight(8)` is called, then `highlightId()` is 8; at 1200 ms after the first call (`advanceTimersByTime(600)`) it is still 8; at 1799 ms (`advanceTimersByTime(599)`) still 8; at 1800 ms, 1200 ms after the second call (`advanceTimersByTime(1)`), it is `null`. Red before the change: it is `null` at 1200 ms.

**Negative**
3. Given `highlight(7)`, when 600 ms later `highlight(8)` is called, then `vi.getTimerCount()` is 1: the first timer was cancelled. After 1200 ms more, `highlightId()` is `null` and `vi.getTimerCount()` is 0.
4. Given `highlight(7)`, when 600 ms later `highlight(7)` is called again, then at 1200 ms after the first call `highlightId()` is still 7, and it is `null` at 1800 ms.
