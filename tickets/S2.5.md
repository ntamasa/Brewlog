## Names and signatures
- `public interface MethodWithCount { BrewMethod getMethod(); long getBrewCount(); }`: the getters match the JPQL aliases `method` and `brewCount`. `getMethod()` is the whole `BrewMethod` (id, name, icon key, predefined, protected, position: every field of the Method JSON except the count), `getBrewCount()` is the Method JSON's `brewCount`.
- In `BrewMethodRepository`:
  ```java
  @Query("select m as method, count(b) as brewCount from BrewMethod m left join Brew b on b.method = m group by m")
  List<MethodWithCount> findAllWithBrewCount();
  ```
  One row per method; a method without brews is a row with count 0. No order: `BrewMethodService.list` sorts (BREW-18).
- `class BrewMethodRepositoryIT extends IntegrationTest` with `@Autowired BrewMethodRepository methods`.

**Happy path**
1. Given 2 brews with Pour Over (method 2) and 1 with Espresso (method 1), when `findAllWithBrewCount()`, then it returns exactly 7 rows and the map is exactly {Espresso 1, Pour Over 2, French Press 0, AeroPress 0, Moka Pot 0, Cold Brew 0, Other 0}.
2. Given the same 3 brews, then the Pour Over row's `getMethod()` has id 2, name "Pour Over", icon key "pour-over", `isPredefined()` true, `isProtected()` false, position 2, and the Other row's has id 7, name "Other", icon key "cup", `isPredefined()` true, `isProtected()` true, position 99.

3. Given no brews, then it still returns exactly 7 rows, each with count 0: methods without brews aren't dropped.
