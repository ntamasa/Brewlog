**Goal:** When the API says a method no longer exists (404) during rename, delete or opening a step, close the step or confirm, reload, and tell the user.

**Read first:**
- Story → Frontend, Acceptance criteria (R38), Business rules (B24, B25)
- `design/screens/methods.md` (State gone), `design/screenshots/methods.gone.desktop.png`, `design/screenshots/methods.gone.mobile.png`

## Files that change
- modify `frontend/src/app/methods/methods-dialog/methods-dialog.ts`, `.spec.ts`.

## Names and signatures
- `handleGone()`: called when `parseApiError(err).kind === 'notFound'` (code `METHOD_NOT_FOUND`) from `rename`, `remove` or `brewsOf`: `view 'list'`, `renamingId` and `confirmingDeleteId` null, `MethodStore.load()`, `Toaster.show('That method no longer exists. The list has been refreshed.')`, `JournalStore.reload()`.

## Tests that prove it
**Seam:** integration (`MethodsDialog`) · **Setup:** TestBed, real stores and APIs · **Mocked:** HTTP (`HttpTestingController`), `MatSnackBar` spied

**Happy path**
1. Given "Chemex" in rename mode, when the PUT answers 404 `{code:'METHOD_NOT_FOUND'}`, then the rename input closes, GET `/api/methods` is sent (flushed without Chemex: the row is gone), the snack bar shows "That method no longer exists. The list has been refreshed." and GET `/api/brews…` is sent (R38).
2. Given the delete step of Moka Pot, when the POST answers 404, then the step view closes and the same reload, toast and journal refresh happen (R38).
3. Given a trash click on Moka Pot, when GET `/api/methods/5/brews` answers 404, then no step view opens and the same happens (R38).
4. Given the rename confirm step, when the PUT answers 404, then the step closes and the same happens (R38).

**Negative**
5. Given the 0-brew inline panel, when the POST answers 404, then the panel closes (no "Couldn’t delete the method" text) and the same happens (R38).
6. Given the PUT answers 503, then the save-error text shows instead and no toast opens (R38).
