## Names and signatures
- `BrewForm` edit mode: title "Edit brew", all controls prefilled from `brew()` (`brewDate` parsed with `parseISO`), no date help text, no "Last edited" text, primary "Save changes". Submit sends `BrewApi.patch(brew.id, changedFields(brew, toBody(value)))`; success emits `saved(brew)` (the journal shows the same toast and highlight as a create).
- New output `stale = output<void>()`: the journal reloads the list.
- On 404 `BREW_NOT_FOUND`: `brewGone = signal(true)`; emit `stale`; banner "This brew no longer exists" + "It may have been deleted in another tab. Your changes are still here: save them as a new brew, or close."; foot `button-secondary` "Close" (emits `closed` without asking) + `button-primary` "Save as new brew" (sends `BrewApi.create(toBody(value))`; success emits `saved`; errors show their usual states).
- Field errors and banners of the earlier stories apply to edit the same way.

## Tests that prove it
**Seam:** component (`BrewForm`) · **Setup:** TestBed + harnesses, real `BrewApi` · **Mocked:** HTTP (`HttpTestingController`)

**Happy path**
1. Given edit mode with Kenyan Morning, then the title is "Edit brew", every field holds its value, the primary reads "Save changes", and the text "Last edited" is absent (R22).
2. Given the rating changed to 4, when "Save changes" is clicked, then PATCH `/api/brews/<id>` with exactly `{"rating":4}`; flushing 200 emits `saved` (R22).
3. Given the notes emptied, when saving, then the PATCH body is `{"notes":null}` (R23).
4. Given the PATCH answers 404 `{code:'BREW_NOT_FOUND'}`, then `stale` emits, the banner reads "This brew no longer exists" / "It may have been deleted in another tab. Your changes are still here: save them as a new brew, or close.", the foot shows "Close" and "Save as new brew", and the fields keep the edited values (R25).
