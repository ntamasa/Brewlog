## Names and signatures
- `BrewForm` edit mode: title "Edit brew", all controls prefilled from `brew()` (`brewDate` parsed with `parseISO`), no date help text (the date's `<mat-hint>` renders only in create mode), no "Last edited" text, primary "Save changes". Submit sends `BrewApi.patch(brew.id, changedFields(brew, toBody(value)))`; success emits `saved(brew)` (the journal shows the same toast and highlight as a create).
- New output `stale = output<void>()`: the journal reloads the list.
- On 404 `BREW_NOT_FOUND`: `brewGone = signal(true)`; emit `stale`; banner "This brew no longer exists" + "It may have been deleted in another tab. Your changes are still here: save them as a new brew, or close."; foot `button-secondary` "Close" (emits `closed` without asking) + `button-primary` "Save as new brew" (sends `BrewApi.create(toBody(value))`; success emits `saved`; errors show their usual states).
- Field errors and banners of the earlier stories apply to edit the same way, through the same answer handler (`saving.set(false)`, `form.enable()`, then the errors, then `banner`). So R50 / B27 hold in edit: a server field error stays until its field changes and blocks "Save changes", and every banner, the brew-gone one too, stays on field changes until the next submit. `brewGone` is not tied to `banner`: the brew-gone foot stays while a later banner shows.
- Busy (R48, R49): "Save changes" and "Save as new brew" are the same primary button as "Add to journal", with only its idle label changed, so while `saving()` each shows `<span class="spinner" aria-hidden="true"></span>Saving…` with `aria-busy="true"` and `aria-disabled="true"`, and `form.disable()` disables the fields. The PATCH and the brew-gone POST both set `saving` and go through the guard `if (this.saving()) return;` before anything is sent; a separate "Save as new brew" handler starts with the same guard. "Close" (brew-gone) and "Cancel" never get `[disabled]` (B26).
