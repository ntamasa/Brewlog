**Goal:** Add the PATCH call and the helper that turns the edited form into a PATCH body of only the changed fields.

**Read first:**
- Epic → Technical design → API
- Technical design → Frontend (below, from the spec); Story → Acceptance criteria (R22, R23)

## Files that change
- modify `frontend/src/app/core/brew-api.ts` (+ spec): `patch`.
- create `frontend/src/app/brew-form/diff.ts` (+ `diff.spec.ts`).

## Names and signatures
- `BrewApi.patch(id: number, changes: Partial<BrewBody>): Observable<Brew>` → PATCH `/api/brews/{id}` with the object as JSON.
- `changedFields(original: Brew, value: BrewBody): Partial<BrewBody>`: compares each of `name`, `beanName`, `origin`, `methodId` (vs `original.method.id`), `roast`, `rating`, `brewDate`, `notes` with the original and returns only those that differ; text compared as typed (`'Kenyan Morning '` differs from `'Kenyan Morning'`); `notes` that are empty after `trim()` become `null`, and count as unchanged when the original notes are `null`.

**Happy path**
1. Given Kenyan Morning with rating 5, when only the rating becomes 4, then `changedFields` → `{ rating: 4 }` (R22).
2. Given notes "Bright", when the notes become `''`, then `changedFields` → `{ notes: null }` (R23).
3. Given method 2, when the method becomes 4 and the roast `DARK`, then → `{ methodId: 4, roast: 'DARK' }`.
4. `BrewApi.patch(7, { rating: 4 })` sends PATCH `/api/brews/7` with body `{"rating":4}` (R22).

**Negative**
5. Given no change, then `changedFields` → `{}`.
6. Given original notes `null` and form notes `'   '`, then `notes` is not in the result.
