## Names and signatures
- `DeleteStep`: inputs `method: BrewMethod`, `brews: MethodBrew[]`, `methods: BrewMethod[]`, `deleting: boolean`, `error: boolean`; outputs `confirm = output<Reassignment[]>()`, `cancel = output<void>()`.
- Targets: `methodsAz(methods)` without `method` itself ("Other" last). `targets = signal<Record<number, number>>` — every brew starts on the protected method's id.
- Head: back (aria-label "Back to methods"), title "Delete “<name>”?" (focus on enter), close. Text `brewCount(n) + (n === 1 ? ' uses' : ' use') + ' this method. Choose where each one goes; any you leave on “Other” move there. Deleting the method can’t be undone.'`.
- "Move all brews to" `mat-select` (default "Other"), as `methods.html` lines 171–174 and Form fields: `<div class="bulk">` with `<span class="field-label" id="dl-all-label">Move all brews to</span>`, then a `<mat-form-field>` with `<mat-select id="dl-all" aria-labelledby="dl-all-label">` and the `chevron-down` suffix (`<mat-icon matIconSuffix svgIcon="chevron-down" class="icon-sm" aria-hidden="true" />`): sets every row; rows can still change afterwards.
- Summary (`aria-live="polite"`): groups `"<count> to <method name>"` joined by " · ", largest count first, equal counts in the target list order (e.g. "10 to Other · 3 to Kalita Wave · 1 to AeroPress", "3 to Other", "1 to Other").
- Rows: brew name over "Bean · Origin · <formatDate>", a `mat-select` (210 px; aria-label "Move “<brew>” to", no visible label) in its own outlined `mat-form-field` with the same `chevron-down` suffix, and a 6 px terracotta dot before the select when the target isn't "Other".
- Foot: `button-secondary` "Keep method" (`cancel`) + `button-danger` "Delete method" (`confirm` with one `{ brewId, methodId }` per brew in list order). `deleting`: "Delete method" is busy, with `[disabled]="deleting()"`, `disabledInteractive`, `[attr.aria-busy]="deleting() ? 'true' : null"` and `<span class="spinner" aria-hidden="true"></span>Deleting…` as its content; its click handler emits `confirm` only when `!deleting()`; all selects disabled. "Keep method", back and × never get `[disabled]` (B26). `error`: `banner-error` "Couldn’t delete the method — Nothing was changed. Try again." above the actions; choices kept.

## Tests that prove it
**Seam:** component · **Setup:** TestBed + `MatSelectHarness`, the `MAT_FORM_FIELD_DEFAULT_OPTIONS` provider of BREW-100; "Move all brews to" is `MatSelectHarness.with({ selector: '#dl-all' })`, a row's select by its aria-label, e.g. `MatSelectHarness.with({ selector: '[aria-label="Move “Sunday Moka” to"]' })` · **Mocked:** nothing

**Happy path**
1. Given Moka Pot with 3 brews, then the title reads "Delete “Moka Pot”?", the text starts "3 brews use this method.", every row select shows "Other", the summary reads "3 to Other" and no row has a dot (R35).
2. When the third row is set to AeroPress, then the summary reads "2 to Other · 1 to AeroPress", that row shows the dot, and "Delete method" emits `confirm` with `[{b1, Other}, {b2, Other}, {b3, AeroPress(4)}]` (R35).
3. When "Move all brews to" is set to Espresso, then all 3 rows show Espresso and the summary reads "3 to Espresso"; then changing row 1 to Other gives "2 to Espresso · 1 to Other" (R35).
4. Given 1 brew, then the text starts "1 brew uses this method." and the summary reads "1 to Other" (B23).

**Negative**
5. The target options don't include "Moka Pot" itself, and "Other" is last (B21).
6. Given `deleting` true, then the button reads "Deleting…" with `aria-busy="true"`, `aria-disabled="true"`, no `disabled` attribute and exactly one `span.spinner` with `aria-hidden="true"`, and every select is disabled (`MatSelectHarness.isDisabled()`) (R35, R48, R49).
7. Given `error` true, then the banner reads "Couldn’t delete the method — Nothing was changed. Try again." and the row choices are unchanged (R35).
8. When "Keep method" is clicked, then `cancel` emits and `confirm` doesn't (R35).
9. Given `deleting` true, when "Deleting…" is clicked, then `confirm` doesn't emit (R48); "Keep method", back ("Back to methods") and × have neither `disabled` nor `aria-disabled`, and "Keep method" still emits `cancel` (B26). Mutation: temporarily drop the `!deleting()` check, and the first half fails; revert.
