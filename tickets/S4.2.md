**Goal:** Create a brew with `POST /api/brews`, trimming text and storing empty notes as null.

**Read first:**
- Epic → Technical design → Data model, API, Backend
- Story → Acceptance criteria (R12), Business rules (B2, B3, B8)

## Files that change
- create `backend/src/main/java/com/brewlog/dto/BrewRequest.java`, `service/BrewDraft.java`, `service/BrewValidator.java` (a `@Component`, injected into `BrewService`).
- modify `service/BrewService.java`: `create`. modify `controller/BrewController.java`: `POST`.
- create `backend/src/test/java/com/brewlog/BrewCreateIT.java`, `service/BrewValidatorTest.java`.

## Names and signatures
- `record BrewRequest(String name, String beanName, String origin, Long methodId, String roast, Integer rating, LocalDate brewDate, String notes)` (roast as `String` so an unknown value can be reported later as INVALID instead of a parse error).
- `BrewDraft`: mutable class with the same 8 fields; `static BrewDraft from(BrewRequest r)`, `static BrewDraft from(Brew b)`.
- `BrewValidator.validate(BrewDraft draft, Long selfId): List<FieldErrorDto>`: for now only normalises (B3): `strip()` every text field, notes that are blank after stripping become `null`; returns an empty list. The checks come in the next story. Create its types now: `exception/ErrorCode.java` (`enum ErrorCode { REQUIRED, TOO_LONG, DUPLICATE, OUT_OF_RANGE, FUTURE_DATE, METHOD_NOT_FOUND, INVALID, BREW_NOT_FOUND, PROTECTED }`) and `dto/FieldErrorDto.java` (`record FieldErrorDto(String field, ErrorCode code)`).
- `BrewService.create(BrewRequest request): BrewResponse`: draft → validate → map to a new `Brew` (method via `BrewMethodRepository.getReferenceById`) → `saveAndFlush` → response.
- `POST /api/brews` → 201 with the `BrewResponse` and `Location: /api/brews/{id}`.

## Tests that prove it
**Seam:** HTTP API · **Setup:** `BrewCreateIT extends IntegrationTest` · **Mocked:** nothing

**Happy path**
1. When POST `{"name":"Kenyan Morning","beanName":"AA Kiambu","origin":"Kenya","methodId":2,"roast":"LIGHT","rating":5,"brewDate":"2026-11-01","notes":""}`, then 201 with `name` "Kenyan Morning", `method` `{"id":2,"name":"Pour Over","iconKey":"pour-over"}`, `notes` null, and `GET /api/brews` lists it with `totalCount` 1 (R12).
2. When POST with name `"  Kenyan Morning "` and notes `"  Bright  "`, then the response and database hold "Kenyan Morning" and "Bright" (B3).

**Negative**
3. When POST with notes `"   "`, then the stored `notes` column is NULL (B3).

**Seam:** unit · **Setup:** JUnit 5 · **Mocked:** nothing
4. `validate` on a draft with origin `" Kenya\t"` leaves origin "Kenya" and returns an empty list.
