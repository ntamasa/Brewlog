**Goal:** Create a brew with `POST /api/brews`, trimming text and storing empty notes as null.

**Read first:**
- Story → Data model; Epic → Technical design → API, Backend (entity constructors and Entity mapping)
- Story → Acceptance criteria (R12), Business rules (B2, B3, B8)

## Files that change
- modify `backend/src/main/java/com/brewlog/entity/Brew.java`: add the public constructor below; keep the `protected Brew()` for JPA.
- create `dto/BrewRequest.java`, `service/BrewDraft.java`, `service/BrewValidator.java` (a `@Component`, injected into `BrewService`).
- modify `service/BrewService.java`: `create`, and its constructor also gets `BrewMethodRepository` and `BrewValidator`. modify `controller/BrewController.java`: `POST`.
- create `backend/src/test/java/com/brewlog/BrewCreateIT.java`, `service/BrewValidatorTest.java`.

## Names and signatures
- `public Brew(String name, String beanName, String origin, BrewMethod method, Roast roast, int rating, LocalDate brewDate, String notes)`: sets the 8 fields, `rating` stored as `(short) rating`; `id` and `createdAt` stay unset (the database fills them).
- `record BrewRequest(String name, String beanName, String origin, Long methodId, String roast, Integer rating, LocalDate brewDate, String notes)` (roast as `String` so an unknown value can be reported later as INVALID instead of a parse error).
- `BrewDraft`: mutable class in `com.brewlog.service` with 8 package-private fields of the same names and types as `BrewRequest`; `static BrewDraft from(BrewRequest r)`, `static BrewDraft from(Brew b)`.
- `BrewValidator.validate(BrewDraft draft, Long selfId): List<FieldErrorDto>`: for now only normalises (B3): `strip()` every text field, notes that are blank after stripping become `null`; returns an empty list. The checks come in the next story. Create its types now: `exception/ErrorCode.java` (`enum ErrorCode { REQUIRED, TOO_LONG, DUPLICATE, OUT_OF_RANGE, FUTURE_DATE, METHOD_NOT_FOUND, INVALID, BREW_NOT_FOUND, PROTECTED }`) and `dto/FieldErrorDto.java` (`record FieldErrorDto(String field, ErrorCode code)`).
- `BrewService(BrewRepository brewRepository, BrewMethodRepository brewMethodRepository, BrewValidator validator)`.
- `@Transactional public BrewResponse create(BrewRequest request)`: `BrewDraft.from(request)` → `validator.validate(draft, null)` → `BrewMethod method = brewMethodRepository.getReferenceById(draft.methodId)` → `new Brew(draft.name, draft.beanName, draft.origin, method, Roast.valueOf(draft.roast), draft.rating, draft.brewDate, draft.notes)` → `brewRepository.saveAndFlush(brew)` → `toResponse(saved)`. The `@Transactional` is what lets `toResponse` read the method's name and icon key from the reference (open-in-view is off).
- `POST /api/brews` → 201 with the `BrewResponse` and `Location: /api/brews/{id}`.

## Tests that prove it
**Seam:** HTTP API · **Setup:** `BrewCreateIT extends IntegrationTest` · **Mocked:** nothing

**Happy path**
1. When POST `{"name":"Kenyan Morning","beanName":"AA Kiambu","origin":"Kenya","methodId":2,"roast":"LIGHT","rating":5,"brewDate":"2026-11-01","notes":""}`, then 201 with `name` "Kenyan Morning", `method` `{"id":2,"name":"Pour Over","iconKey":"pour-over"}`, `notes` null, and `GET /api/brews` lists it with `totalCount` 1 (R12). Without `@Transactional` on `create` this fails on the method's name (lazy reference outside a transaction).
2. When POST with name `"  Kenyan Morning "` and notes `"  Bright  "`, then the response and database hold "Kenyan Morning" and "Bright" (B3).

**Negative**
3. When POST with notes `"   "`, then the stored `notes` column is NULL (B3).

**Seam:** unit · **Setup:** JUnit 5 · **Mocked:** nothing
4. `validate` on a draft with origin `" Kenya\t"` leaves origin "Kenya" and returns an empty list.
