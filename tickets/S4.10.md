**Goal:** Make the brew method select look like the design. The field shows the chosen method's icon before its name, the list shows terracotta icons, and the selected option is bold with a terracotta dot instead of Material's checkmark.

**Read first:**
- Story → Frontend, Business rules (B21, B22)
- Technical design → Form fields, in BREW-100 (`jira.mjs read BREW-100`). The method field's markup (`.field`, `#method-label`, `#method-btn`, chevron suffix) comes from BREW-101.
- `design/screens/brew-form.md` (Body → Brew method; State method-open), `design/prototype/screens/brew-form.html` (`<style>` lines 22–29 and 41; method markup lines 135–157), `design/screenshots/brew-form.method-open.desktop.png`, `design/screenshots/brew-form.method-open.mobile.png`, `design/screenshots/brew-form.create.desktop.png`

## Names and signatures
- `MethodSelect` gets `protected readonly selected = computed(() => this.methods().find((m) => m.id === this.value()) ?? null)`. `MethodIcon` leaves its imports: it draws 40 px icons, and the select uses 20 px ones.
- The `mat-select` gets `hideSingleSelectionIndicator`, so Material draws no checkmark.
- Inside the `mat-select`, a `<mat-select-trigger>` holding `@if (selected(); as method) { <span class="method-value"><mat-icon class="icon" [svgIcon]="method.iconKey" aria-hidden="true" /><span>{{ method.name }}</span></span> }`. With no method, or with an id that isn't in `methods()`, Material shows the placeholder "Choose a method" instead, in the muted placeholder colour `theme.scss` already sets.
- Each option is `<mat-option [value]="method.id"><mat-icon class="icon" [svgIcon]="method.iconKey" aria-hidden="true" />{{ method.name }}</mat-option>`. A `mat-icon` that is a direct child of `mat-option` goes into Material's icon slot before the text, 16 px from it, the gap of the prototype's `.listbox li`.
- `method-select.scss`. The options are rendered in the overlay but created by this template, so its emulated styles reach `mat-option` and its icons. They don't reach Material's inner `.mdc-list-item__primary-text`, which inherits the option's weight.
  - `.method-value { display: inline-flex; align-items: center; gap: var(--spacing-sm); }` (prototype line 22)
  - `.method-value .mat-icon, .mat-mdc-option .mat-icon { color: var(--color-tertiary); }` (lines 23, 26)
  - `.mat-mdc-option.mdc-list-item--selected { font-weight: var(--font-weight-title-md); }` (line 28)
  - `.mat-mdc-option.mdc-list-item--selected::after { content: ''; flex: none; margin-left: var(--spacing-md); width: 6px; height: 6px; border-radius: var(--radius-full); background: var(--color-tertiary); }` (line 29). Material's primary text has `margin-right: auto`, which pushes the dot to the right end. The dot itself takes no `auto` margin, or the free space would be split.

## Tests that prove it
**Seam:** component (`MethodSelect`) · **Mocked:** HTTP (the icon sprite)

**Setup:**
- as BREW-21's `method-select.spec.ts`: a host with a `FormControl<number | null>` and the 7 seeded methods plus "chemex" (`cup`)
- the `MAT_FORM_FIELD_DEFAULT_OPTIONS` provider of BREW-100
- icons are read with `MatIconHarness`, and the open panel with `TestbedHarnessEnvironment.documentRootLoader(fixture)`

**Happy path**
1. Given the control 2, then the select's value text is "Pour Over", and the select shows exactly one icon before it, named `pour-over` (`MatIconHarness.with({ ancestor: '#method-btn' })`).
2. Given the control null, when "AeroPress" is chosen, then the select's icon is named `aeropress` and its value text is "AeroPress".
3. Given the select opened, then the 8 options' icons, in order, are named `aeropress`, `cup`, `cold-brew`, `espresso`, `french-press`, `moka-pot`, `pour-over`, `cup`. These are AeroPress, chemex, Cold Brew, Espresso, French Press, Moka Pot, Pour Over and Other (B21, B22).
4. Given the control 2 and the select opened, then only "Pour Over" is selected (`MatOptionHarness.isSelected()`), and the panel contains no `mat-pseudo-checkbox` element.

**Negative**
5. Given the control null, then the value text is "Choose a method", and the select contains no `mat-icon`. The `chevron-down` suffix is the field's only icon.
6. Given the control 42 (no such method), then the value text is "Choose a method" and the select contains no `mat-icon`.
7. Given the control null and the select opened, then no option is selected and the panel contains no `mat-pseudo-checkbox`.

**Seam:** E2E · **Setup:** like the create test in `e2e/tests/brew-form.spec.ts` (BREW-99), both projects · **Mocked:** nothing

8. Given the form open with Pour Over chosen:
   - `#method-btn` contains a visible `mat-icon[data-mat-icon-name="pour-over"]` that computes `color` "rgb(180, 83, 42)".
   - When the select is opened again, then the option "Pour Over" computes `font-weight` "600", and its `::after` computes `background-color` "rgb(180, 83, 42)" and `width` "6px".
   - The option "AeroPress" computes `font-weight` "400", and its icon computes `color` "rgb(180, 83, 42)".
   - The panel contains no `.mat-pseudo-checkbox`.
