## Names and signatures
- `MethodApi.create(name: string): Observable<BrewMethod>` → POST `/api/methods` `{ name }`.
- `export type MethodPending = 'add' | 'quick-add' | 'row-rename' | 'step-rename' | 'inline-delete' | 'step-delete';` in `method.store.ts`.
- `MethodState` gets `pending: MethodPending | null`, initial `null`, so `methodStore.pending()` is a `Signal<MethodPending | null>`: the button that sent the methods request in flight, or null. Only the store's `add` (here), `rename` (BREW-65) and `remove` (BREW-71) change it.
- `MethodStore.add(name: string, from: 'add' | 'quick-add'): Observable<BrewMethod>`: sets `pending` to `from` when the request is sent and back to null when it answers, success or error (Hard logic); calls the API; on success appends the method to `methods` and returns it; errors pass through to the caller. The methods dialog calls it with `'add'` (BREW-60), the form's quick-add with `'quick-add'` (BREW-62).
- In the caller's `next` and `error` callbacks `pending()` still holds `from`: `finalize` runs right after them. A component that moves focus to an input it disables while pending does it after the next render (BREW-60, BREW-107).
- `methodsDialogOrder(methods)`: non-protected predefined by `position`, then custom (`predefined` false) A–Z ignoring case, then protected.
- `checkMethodName(name: string, methods: BrewMethod[], selfId: number | null): { code: 'REQUIRED' | 'TOO_LONG' | 'DUPLICATE'; existing?: string } | null`: trims; empty → REQUIRED; > 50 → TOO_LONG; another method (id ≠ selfId) with the same name ignoring case → DUPLICATE with `existing` = that method's name.
- `methodNameMessage(code: string, existing: string | null, place: 'dialog' | 'form'): string`: REQUIRED "Enter a method name"; TOO_LONG "Method name can be at most 50 characters"; DUPLICATE dialog "“<existing>” already exists. Method names must be unique.", form "“<existing>” already exists."; anything else (network) "Couldn’t save the method. Try again."

## Tests that prove it
**Seam:** unit · **Setup:** Vitest + TestBed, `HttpTestingController`; store with a fake `MethodApi` · **Mocked:** HTTP / API

**Happy path**
1. `methodsDialogOrder` of the API order (AeroPress, chemex, Cold Brew, Espresso, French Press, Moka Pot, Pour Over, Other) → Espresso, Pour Over, French Press, AeroPress, Moka Pot, Cold Brew, chemex, Other (R29, B21).
2. `MethodApi.create('Chemex')` sends POST `/api/methods` with `{"name":"Chemex"}` (R30).
3. `MethodStore.add('Chemex', 'add')` with the fake answering Chemex (id 8) → `methods` contains Chemex (R30).
4. `checkMethodName(' Chemex ', seeded, null)` → null; 50 characters → null (R30).
5. Given the fake's `create` returning a `Subject` that hasn't emitted, when `add('Chemex', 'add')` is subscribed, then `pending()` is `'add'`; when the subject emits Chemex and completes, then `pending()` is null and `methods` contains Chemex (R48). The same with `'quick-add'` gives `pending()` `'quick-add'` while it hasn't answered (R48).

**Negative**
6. `checkMethodName('   ', …)` → REQUIRED; 51 characters → TOO_LONG; `'pour over'` → DUPLICATE with `existing` "Pour Over"; `'Pour Over'` with `selfId` 2 → null (R30, B12).
7. `methodNameMessage('DUPLICATE', 'Pour Over', 'dialog')` → "“Pour Over” already exists. Method names must be unique."; `'form'` → "“Pour Over” already exists."; `methodNameMessage('NETWORK', null, 'dialog')` → "Couldn’t save the method. Try again." (R30).
8. `MethodStore.add('Chemex', 'add')` with the fake erroring (a 503 `HttpErrorResponse`) → `methods` unchanged, the error is re-emitted, and `pending()` is null afterwards (R48: busy ends on failure).
9. A fresh store has `pending()` null, and `add('Chemex', 'add')` that nobody subscribes to leaves it null and sends nothing (R48).

## Hard logic
```ts
add(name: string, from: 'add' | 'quick-add'): Observable<BrewMethod> {
  return defer(() => {
    patchState(store, { pending: from }); // when the request is sent
    return api.create(name);
  }).pipe(
    tap((method) => patchState(store, { methods: [...store.methods(), method] })),
    finalize(() => patchState(store, { pending: null })), // success or error
  );
}
```
