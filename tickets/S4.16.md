**Goal:** Esc with the Brew method listbox open closes only the listbox: the drawer stays open and every typed value is kept.

**Source (review of PR #6):** with the listbox open, focus stays on the `mat-select` host inside the sidenav. Esc's `keydown` bubbles to the `mat-sidenav` element, whose own listener closes the drawer and stops the event, so the select's overlay never sees it. `design/screens/brew-form.md` → Interactions:

> - Method select: click/Enter/Space opens; arrows move; Enter selects; Esc closes.
> - Cancel / close / Esc / backdrop click → close. If fields were changed, ask inline in the foot: "Discard changes?" with "Keep editing" / "Discard" (not a browser dialog).

The first rule wins while the listbox is open: that Esc must not reach the sidenav (nor, later, the form's own Esc of BREW-31).

## Names and signatures
- `MethodSelect`: `private readonly matSelect = viewChild.required(MatSelect);`. Not `select`: that name is taken by the existing `protected select(id: number): void`, which `method-select.html` calls from `(selectionChange)="select($event.value)"` and which stays as it is.
- `MethodSelect.closeOnEscape(event: Event): void` (`protected`). Angular's `keydown.escape` only fires for Esc without Shift, Ctrl, Alt or Meta.

## Hard logic
```ts
protected closeOnEscape(event: Event): void {
  const matSelect = this.matSelect();
  if (!matSelect.panelOpen) return; // listbox closed: the drawer handles Esc as before
  event.stopPropagation();       // never reaches mat-sidenav
  event.preventDefault();
  matSelect.close();             // the overlay never sees this Esc, so close it here
}
```
`matSelect.close()` emits `(closed)`, so `touch()` still runs. The value doesn't change: Esc never selects the active option.
