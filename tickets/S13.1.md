**Goal:** Reject invalid list parameters with 400 `INVALID`, and answer pages past the last and unknown methods with an empty page.

**Read first:**
- Epic → Technical design → API (list params, errors), Backend
- Story → Acceptance criteria (R9, R10), Business rules (B18, B20)

## Files that change
- modify `backend/src/main/java/com/brewlog/controller/BrewQueryParams.java`: bind every param as a raw `String` (`q`, `methodId`, `roast`, `minRating`, `sort`, `page`) and add `toQuery()`.
- modify `controller/BrewController.java`: `list` calls `params.toQuery()`.
- create `backend/src/test/java/com/brewlog/BrewListParamsIT.java`.

## Names and signatures
- `BrewQueryParams.toQuery(): BrewQuery`, collecting one `FieldErrorDto(<param>, INVALID)` per bad param, in the order `methodId`, `roast`, `minRating`, `sort`, `page`, then throwing `ValidationException` if any:
  - `methodId`: present and not a positive `long`
  - `roast`: present and not `LIGHT`/`MEDIUM`/`DARK` (exact, upper case)
  - `minRating`: present and not an integer 2–5
  - `sort`: present and not one of the four `SortKey` names
  - `page`: present and not an integer ≥ 1
  - Absent or empty params take their defaults (`page` 1, `sort` `NEWEST`).

## Tests that prove it
**Seam:** HTTP API · **Setup:** `BrewListParamsIT extends IntegrationTest`, 41 brews via `TestData` · **Mocked:** nothing

**Happy path**
1. `GET /api/brews?page=9` → 200 `items` [], `page` 9, `totalPages` 4, `matchingCount` 41, `totalCount` 41 (R10).
2. `GET /api/brews?methodId=9` (no such method) → 200 `items` [], `matchingCount` 0, `totalCount` 41 (R9).
3. `minRating=2` and `minRating=5` → 200 (R9).

**Negative**
4. `roast=FOO` → 400 `errors` `[{"field":"roast","code":"INVALID"}]` and no `items` (R9).
5. Each of `minRating=7`, `minRating=1`, `sort=X`, `page=0`, `methodId=abc` → 400 with exactly `[{"field":"<that param>","code":"INVALID"}]` (R9).
6. `roast=light` (lower case) → 400 `roast` `INVALID` (R9).
7. `roast=FOO&page=0` → 400 with both errors, `roast` first (R9).
