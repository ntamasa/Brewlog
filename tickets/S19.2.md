**Goal:** Open the delete step from the trash of a method with brews, send all targets in one request, and update the dialog and the journal.

**Read first:**
- Story → Frontend, Acceptance criteria (R35), Business rules (B14, B23, B24)
- `design/screens/methods.md` (Interactions: Delete, Focus), `design/screenshots/methods.delete-reassign.desktop.png`, `design/screenshots/methods.default.desktop.png`

## Files that change
- modify `frontend/src/app/methods/methods-dialog/methods-dialog.ts`, `.html`, `.spec.ts`.
- modify `e2e/tests/methods.spec.ts`.

## Names and signatures
- Trash on rows with `brewCount >= 1` too. On those: `MethodApi.brewsOf(id)` → `view 'delete'` with `DeleteStep`.
- `confirm(reassignments)` → `deleting` true → `MethodStore.remove(id, reassignments)`; success: `view 'list'`, `Toaster.show('“<name>” deleted · ' + brewCount(r.reassignedBrewCount) + ' reassigned')` (e.g. "“Moka Pot” deleted · 3 brews reassigned", "… · 1 brew reassigned"), `JournalStore.reload()`, focus to the list; failure (network/5xx): `error` true, `deleting` false. Cancel, back or Esc: `view 'list'`, focus back on that row's trash, nothing sent.

## Tests that prove it
**Seam:** integration (`MethodsDialog`) · **Setup:** TestBed, real stores and APIs · **Mocked:** HTTP (`HttpTestingController`), `Toaster` (`{ provide: Toaster, useValue: { show: vi.fn() } }`, BREW-104)

**Happy path**
1. Given Moka Pot (`brewCount` 3), when its trash is clicked, then GET `/api/methods/5/brews` is sent and the step view lists the 3 brews (R35).
2. When the third brew is set to AeroPress and "Delete method" clicked, then POST `/api/methods/5/delete` with `{"reassignments":[{"brewId":b1,"methodId":7},{"brewId":b2,"methodId":7},{"brewId":b3,"methodId":4}]}`; after 200 `{"reassignedBrewCount":3}`, GET `/api/methods` reloads (Moka Pot gone, Other +2, AeroPress +1 in the flushed data shown), `Toaster.show` is called with "“Moka Pot” deleted · 3 brews reassigned" and GET `/api/brews…` is sent (R35).
3. Given `reassignedBrewCount` 1, then `Toaster.show` is called with "“Moka Pot” deleted · 1 brew reassigned" (R35, B23).

**Negative**
4. When "Keep method", back or Esc is used in the step, then no POST is sent and the list shows Moka Pot unchanged (R35).
5. Given the POST fails with 503, then the step view stays with the banner and the AeroPress choice kept; "Delete method" sends the same body again (R35).

**Seam:** E2E · **Setup:** compose stack, both projects; method `m = uniqueName('Siphon')` and 2 brews with it created through the API · **Mocked:** nothing
6. Given `/journal`, when "Manage methods" → trash on `m` → second brew set to "AeroPress" → "Delete method", then the toast "“<m>” deleted · 2 brews reassigned" shows, `m` is gone from the list, and the two cards (searched by name) show "Other" and "AeroPress" (R35).
