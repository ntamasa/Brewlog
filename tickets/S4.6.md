## Names and signatures
- `formOpen = signal(false)`; `sidenav = viewChild.required(MatSidenav)`. `BrewForm` is rendered in the sidenav only while `formOpen()` is true, and `(closed)` on the `mat-sidenav` sets it false (Hard logic).
- `JournalPage.openCreate()`: loads methods if `MethodStore.status()` is `idle`, sets `formOpen` true, then opens the sidenav in create mode. On `saved(brew)`: close, `Toaster.show('“' + brew.name + '” saved to your journal')`, `store.highlight(brew.id)`, `store.reload()`. On the form's `closed`: `sidenav().close()`, nothing else.
- Focus (R47): the sidenav moves it to the form's `[cdkFocusInitial]` Brew name once it has opened, and returns it to the element focused before it opened ("+ Add brew", the FAB or "+ Log your first brew") when it closes. `JournalPage` calls no `focus()` and nothing uses `cdkTrapFocus`.
- `BrewCard`'s `highlighted` = `brew.id === store.highlightId()`.

## Tests that prove it
**Seam:** integration (`JournalPage`) · **Setup:** TestBed, real stores, APIs and `Toaster`, harnesses, `RouterTestingHarness` on `/journal` as now. TestBed doesn't load `app.config.ts`, so the shared `TestBed.configureTestingModule` of `journal-page.spec.ts` provides exactly these, for every test:
- `provideRouter(routes)`, `provideHttpClient()`, `provideHttpClientTesting()`, `provideAppInitializer(registerIcons)` (already there)
- `provideDateFnsAdapter(BREWLOG_DATE_FORMATS)` (`core/date-formats.ts`) and `{ provide: MAT_DATE_LOCALE, useValue: enGB }` (`enGB` from `date-fns/locale`), as in `app.config.ts` and `brew-form.spec.ts`; without them every test that opens the form fails with "MatDatepicker: No provider found for DateAdapter"
- `{ provide: MATERIAL_ANIMATIONS, useValue: { animationsDisabled: true } }` (`@angular/material/core`): with transitions on, the sidenav waits for a `transitionend` that jsdom never fires and never moves focus
- `{ provide: MatSnackBar, useValue: { open: vi.fn() } }`, read with `TestBed.inject(MatSnackBar)` in test 3

Focus tests focus the trigger with its harness's `focus()` before `click()` (harness clicks don't move focus in jsdom; a browser click does), and assert with `await vi.waitFor(() => expect(document.activeElement).toBe(<element>))`, because the sidenav moves focus a timer tick after it opens. Triggers: "+ Add brew" is `MatButtonHarness.with({ text: 'Add brew' })`, the FAB `MatButtonHarness.with({ selector: '[aria-label="Add brew"]' })`, "+ Log your first brew" `MatButtonHarness.with({ text: 'Log your first brew' })`. **"The form closes"** (tests 3, 4, 5, 6 and 8) is checked the same way in every `JournalPage` test, by one helper in `journal-page.spec.ts`, `expectFormClosed(page: HTMLElement): Promise<void>`: `await vi.waitFor(() => { expect(<the mat-sidenav element>.classList.contains('mat-drawer-opened')).toBe(false); expect(page.querySelector('app-brew-form')).toBeNull(); })`. Always wait, never check at once: `close()` returns focus at once, but the sidenav emits `(closed)`, which sets `formOpen` false and so removes the form, only a timer tick later, and `fixture.whenStable()` doesn't wait for that tick. **The FAB in jsdom** (tests 5 and 8): one more helper, `showFab(page: HTMLElement): HTMLButtonElement`, finds `button[aria-label="Add brew"]` (throws if none), expects its `getComputedStyle(…).display` to be `"none"` (the `min-width: 768px` rule), then `fab.style.setProperty('display', 'inline-flex', 'important')` (an inline `!important` beats that rule) and returns it. Only tests that use the FAB call it, before focusing it; no other element is shown or hidden this way · **Mocked:** HTTP (`HttpTestingController`), `MatSnackBar` spied

## Hard logic
```ts
openCreate(): void {
  if (this.methodStore.status() === 'idle') this.methodStore.load();
  this.formOpen.set(true);     // renders <app-brew-form> with its [cdkFocusInitial] input…
  void this.sidenav().open();  // …before the sidenav reports opened and focuses that selector
}
onFormClosed(): void {
  void this.sidenav().close(); // focus is still inside the sidenav, so it returns focus to the trigger
}
```
```html
<mat-sidenav-container>
  <mat-sidenav mode="over" position="end" fixedInViewport autoFocus="[cdkFocusInitial]" (closed)="formOpen.set(false)">
    @if (formOpen()) {
      <app-brew-form mode="create" [methods]="methods()" (saved)="onSaved($event)" (closed)="onFormClosed()" />
    }
  </mat-sidenav>
  <mat-sidenav-content>
    <header class="app-header">…</header>
    <main class="container">…</main>
    <button matFab class="mobile-only" …>…</button>
  </mat-sidenav-content>
</mat-sidenav-container>
```
Never remove the form before `close()`: with focus gone from the sidenav it returns none. `close()` returns focus at once; `(closed)`, and with it the form's removal, follows a timer tick later, which the tests wait for (`expectFormClosed`).
