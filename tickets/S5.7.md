**Goal:** Every inline field error in the brew form, inside a `mat-form-field` or not, shows its alert icon at 16 × 16 px with a 4 px gap before the text, checked in a browser.

**Source (review of PR #7):** the `mat-error` of Brew name, Bean name, Origin, Brew method, Date and Tasting notes (`frontend/src/app/brew-form/brew-form.html:39`, `:52`, `:69`, `:136`, `:155`, `method-select/method-select.html:33`) render the icon at 13 × 13 px with no gap. `helpers.scss`'s `.field-error` (`display: flex`, `gap`) and `.field-error .mat-icon` (16 px) lose to Material's form-field styles, which load after the global stylesheet at the same specificity: `.mat-mdc-form-field-error { display: block }` and `.mat-mdc-form-field-subscript-wrapper .mat-icon { width: 1em; height: 1em }` (1em = 13 px there). The roast and rating `<p class="field-error">` aren't in a form field and render right. `design/screens/brew-form.md`, state validation-error: "each invalid field gets error border + error-soft fill + message with alert icon below", and both `brew-form.validation-error` screenshots show the same icon size and gap on every field. The prototype's rule (`design/prototype/components.css` lines 98–99):

> `.field-error { font-size: var(--text-body-sm); color: var(--color-error); display: flex; gap: var(--spacing-xs); align-items: flex-start; }`
> `.field-error .icon { width: 16px; height: 16px; margin-top: 2px; }`

## Hard logic
```scss
/* In a mat-form-field, Material's later-loaded `.mat-mdc-form-field-error { display: block }`
   and `.mat-mdc-form-field-subscript-wrapper .mat-icon { width: 1em; height: 1em }` would win
   at equal specificity, so these carry one class more. */
.mat-mdc-form-field .field-error {
  display: flex;
}
.mat-mdc-form-field .field-error .mat-icon {
  width: 16px;
  height: 16px;
}
```
