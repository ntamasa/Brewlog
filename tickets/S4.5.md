## Names and signatures
- `BrewForm`: `mode = input<'create' | 'edit'>('create')`, `brew = input<Brew | null>(null)` (edit comes later), `methods = input.required<BrewMethod[]>()`, `saved = output<Brew>()`, `closed = output<void>()`.
- `readonly form: FormGroup<BrewFormControls>`, public (test 1 reads its controls), typed:
  - `name`, `beanName`, `origin`, `notes`: `FormControl<string>`, non-nullable, initial `''`
  - `methodId: FormControl<number | null>`
  - `roast: FormControl<Roast | null>`
  - `rating: FormControl<number | null>`
  - `brewDate: FormControl<Date | null>` (create: today at local midnight)
- Interim validators (BREW-27, story "Validate a brew before saving", replaces them with `BREW_VALIDATORS` and adds the messages and the banner):
  - `name`, `beanName`, `origin`: `[Validators.required, Validators.pattern(/\S/)]`, so empty or only spaces is invalid (B3)
  - `methodId`, `roast`, `rating`, `brewDate`: `Validators.required` (B2)
  - `notes`: none
  - The datepicker input also adds its own `matDatepickerParse` and `matDatepickerMax` errors to `brewDate` (B8).
  - Material's default `ErrorStateMatcher` stays: an invalid Material field that is touched shows Material's error outline, with no message yet.
- Template, in this order:
  - head: title "Log a brew", close `icon-button` with aria-label "Close without saving"
  - intro "Everything is required except tasting notes."
  - Brew name (+ help)
  - Bean name | Origin
  - `MethodSelect`
  - roast `mat-button-toggle-group`: Light / Medium / Dark with swatches, values `LIGHT`/`MEDIUM`/`DARK`
  - `BeanRating` in input mode
  - `mat-datepicker` input (`[max]` = today), help "Defaults to today. Change it if you’re logging an earlier brew."
  - notes textarea ("Optional" label, placeholder from the screen spec)
  - foot: "Cancel" + "Add to journal"
- `toBody(value): BrewBody`: strings as typed (the server trims), notes `''` → `null`, `brewDate` → `format(date, 'yyyy-MM-dd')`.
- `private readonly brewApi = inject(BrewApi)`. `saving = signal(false)`. While saving, the primary shows a spinner + "Saving…" with `aria-busy="true"`, and the form is disabled.
- `submit()`: see Hard logic. Its interim rules:
  - **Incomplete form:** while `form.invalid`, nothing is sent and the form stays open (no `saving`, no emit). This keeps nulls and blank text away from BREW-19's `POST /api/brews`, which only trims.
  - **Failed save:** on any error response (status 0, 4xx, 5xx) `saving` resets, the fields and the primary are enabled again with every value kept, the form stays open, `saved` isn't emitted and nothing shows a toast. The server-error banner comes in BREW-30 (story "Save safely"). Field errors from a 400 come in BREW-27.
- Cancel and × emit `closed()`. The discard guard comes in a later story.
- The Brew name input carries the attribute `cdkFocusInitial`, the only element of the form that does. The form moves no focus itself when it opens (no `focus()` call, no `autofocus` attribute, no `cdkTrapFocus`): the container focuses the marked input (the sidenav in BREW-23, R47).

## Hard logic
```ts
submit(): void {
  if (this.saving()) return;
  if (this.form.invalid) {          // interim: BREW-27 adds the messages and the banner here
    this.form.markAllAsTouched();
    return;                         // nothing is sent
  }
  const body = toBody(this.form.getRawValue()); // read before disable(): a disabled group's .value is {}
  this.saving.set(true);
  this.form.disable();
  this.brewApi.create(body).subscribe({
    next: (brew) => this.saved.emit(brew),
    error: () => {                  // any status: values kept, form stays open
      this.saving.set(false);
      this.form.enable();
    },
  });
}
```
