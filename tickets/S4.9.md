## Tests that prove it
**Seam:** component (`BrewForm`, `MethodSelect`) · **Mocked:** HTTP (`HttpTestingController`; the icon sprite)

**Setup:**
- as BREW-22's `brew-form.spec.ts` and BREW-21's `method-select.spec.ts`
- both specs and `journal-page.spec.ts` provide `{ provide: MAT_FORM_FIELD_DEFAULT_OPTIONS, useValue: BREWLOG_FORM_FIELD_OPTIONS }` (BREW-100)
- controls are found by id, as Form fields → Tests says. The `field(label)` helpers become `MatInputHarness.with({ selector: '#name' })` (and `#bean`, `#origin`, `#notes`), the date is `MatDatepickerInputHarness.with({ selector: '#date' })`, and the method is `MatSelectHarness.with({ selector: '#method-btn' })`.

**Happy path**
1. Given the create form, then Brew name, Bean name, Origin, Date and Tasting notes each have a `label.field-label` whose `for` is `name`, `bean`, `origin`, `date` or `notes`. The element with that id is the field's input or textarea. The label texts are "Brew name", "Bean name", "Origin" and "Date", and the notes label starts with "Tasting notes", with its `span.opt` reading "Optional".
2. Given the create form, then every `MatFormFieldHarness` in it has `getAppearance()` "outline" and `hasLabel()` false, and the form contains no `mat-label` element.
3. Given the create form, then `getTextHints()` returns:
   - for `MatFormFieldHarness.with({ ancestor: '[data-field="name"]' })`: ["A name only you would recognise, like “Sunday Moka”. Must be unique."]
   - for `[data-field="date"]`: ["Defaults to today. Change it if you’re logging an earlier brew."]

   Both `mat-hint` elements have the class `field-help`.
4. Given the create form, then Roast level and Rating are `fieldset.field` elements with `legend.field-label` "Roast level" and "Rating", and the Rating fieldset has the id `rating`.
5. Given `MethodSelect` (in its own spec), then:
   - `span.field-label#method-label` reads "Brew method"
   - the `mat-select` has the id `method-btn`, and its `aria-labelledby` contains `method-label`
   - its form field holds a `mat-icon` named `chevron-down` (`MatIconHarness`)
   - clicking that icon opens the select (`MatSelectHarness.isOpen()` true)
6. These existing tests still pass, with only their control lookups changed to the ids: BREW-22's tests 1–11, BREW-21's `MethodSelect` tests and the `JournalPage` form tests of BREW-23.

**Negative**
7. Given the create form with only the default date, when "Add to journal" is clicked, then no POST is sent, and no form field in it has the class `mat-form-field-invalid`.
8. Given "Kenyan Morning" typed into Brew name, then cleared and blurred (so touched, dirty and invalid), then its form field doesn't have the class `mat-form-field-invalid`, and the form contains no `mat-error`.

**Seam:** E2E · **Setup:** like the create test in `e2e/tests/brew-form.spec.ts` (BREW-99), both projects. The form is opened with "+ Add brew" (desktop) or the FAB (phone). · **Mocked:** nothing

9. Given the form open, then:
   - the form's `.head` computes `border-bottom` "1px solid rgb(220, 210, 195)", and its `.foot` computes the same `border-top`
   - the `.mat-mdc-text-field-wrapper` around `#name` computes `background-color` "rgb(255, 253, 248)", and its box is 44 px tall
   - `label[for="name"]` ends above that box: the label's bottom is ≤ the box's top
   - the drawer contains no `.mdc-floating-label` element
   - the method field's `.mat-mdc-select-arrow-wrapper` computes `display` "none", and its `chevron-down` icon is visible
