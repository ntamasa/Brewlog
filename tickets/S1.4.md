## Names and signatures
- `ClockConfig`: `@Bean Clock clock()` returns `Clock.systemDefaultZone()`.
- `TestcontainersConfig`: `@TestConfiguration(proxyBeanMethods = false)`, `@Bean @ServiceConnection PostgreSQLContainer postgres()` with image `postgres:17`.
- `FixedClockConfig`: `@TestConfiguration`, `@Bean @Primary Clock fixedClock()` = `Clock.fixed(Instant.parse("2026-11-01T12:00:00Z"), ZoneOffset.UTC)`.
- `IntegrationTest` (abstract): `@SpringBootTest`, `@AutoConfigureMockMvc`, `@Import({TestcontainersConfig.class, FixedClockConfig.class})`; protected fields `MockMvc mvc`, `JdbcTemplate jdbc`; `@BeforeEach void resetDatabase()` runs `classpath:reset.sql` with `ScriptUtils`.
- `reset.sql`: `TRUNCATE brew, brew_method RESTART IDENTITY CASCADE;` followed by the same 7 inserts as `002-seed-methods.sql`, so Espresso has id 1 … Cold Brew id 6, Other id 7 in every test.

## Tests that prove it
**Seam:** database through Spring · **Setup:** `SchemaIT extends IntegrationTest` · **Mocked:** nothing

**Happy path**
1. Given a fresh database, when `SELECT name, icon_key, predefined, is_protected, position FROM brew_method ORDER BY id` runs, then it returns exactly: (Espresso, espresso, true, false, 1), (Pour Over, pour-over, true, false, 2), (French Press, french-press, true, false, 3), (AeroPress, aeropress, true, false, 4), (Moka Pot, moka-pot, true, false, 5), (Cold Brew, cold-brew, true, false, 6), (Other, cup, true, true, 99).
2. Given a valid row (method 1, roast `LIGHT`, rating 5, date 2026-11-01), when inserted into `brew` without `created_at`, then it is stored with a non-null `created_at`.

**Negative**
3. Given the seed, when a method named `espresso` is inserted, then a `DataIntegrityViolationException` is thrown naming `ux_brew_method_name`, and `brew_method` still has 7 rows.
4. Given a brew named `Kenyan Morning`, when a brew named `KENYAN MORNING` is inserted, then the insert fails on `ux_brew_name`.
5. Given otherwise valid rows, when `rating` 6, `rating` 0 or `roast` `BOLD` is inserted, then each insert fails on its check constraint and `brew` stays empty.

**Wrapper checks** (Story → Repository and tooling)
6. Given the wrapper is made, when `cd backend && ./gradlew --version` runs, then it prints `Gradle 9.9.2`.
7. Given the wrapper is made, then `gradle-wrapper.properties` has exactly the `distributionUrl` and `distributionSha256Sum` lines of the spec, and the SHA-256 of `gradle-wrapper.jar` equals the spec's published wrapper-jar value.
8. Given the wrapper files are staged, when `git ls-files --eol -s backend/gradlew backend/gradlew.bat backend/gradle/wrapper/gradle-wrapper.jar` runs, then `gradlew` shows mode `100755`, `i/lf` and `attr/text eol=lf`, `gradlew.bat` shows `attr/text eol=crlf`, and `gradle-wrapper.jar` shows `attr/-text` (binary).
9. Given the downloaded `gradle-9.9.2-bin.zip` has a SHA-256 other than the spec's value, then it is neither unzipped nor run, no wrapper file is created, and you stop with a blocker report.
10. Given the wrapper is made, then `git status` shows no Gradle zip, no unzipped distribution and no temp dir anywhere in the repo.
