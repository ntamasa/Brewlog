**Goal:** Filter `GET /api/brews` by method, roast and minimum rating, combined with search and sort.

**Read first:**
- Epic → Technical design → API (list params); Technical design → Backend (below, from the spec)
- Story → Acceptance criteria (R6), Business rules (B18, B19)

## Files that change
- modify `backend/src/main/java/com/brewlog/service/BrewSpecifications.java`: `methodIs`, `roastIs`, `ratingAtLeast`.
- modify `controller/BrewQueryParams.java`: bind `methodId` (long), `roast` (`Roast`), `minRating` (int); invalid values are handled in the URL story.
- modify `service/BrewService.java`: combine the four specs with `Specification.allOf(...)` (null specs ignored).
- create `backend/src/test/java/com/brewlog/BrewFilterIT.java`.

## Names and signatures
- `methodIs(Long methodId)`: `root.get("method").get("id") = methodId`; `roastIs(Roast roast)`: equality; `ratingAtLeast(Integer min)`: `rating >= min`. Each returns no restriction for `null`.

**Happy path**
1. `methodId=2&roast=LIGHT&minRating=4&sort=HIGHEST` → `items` exactly P2, P1, P3 in that order (rating desc; P1 and P3 tie on 4, so the newer date, P1 2026-11-05, comes first), `matchingCount` 3, `totalCount` 6, `totalPages` 1 (R6, B19).
2. `methodId=2&roast=LIGHT&minRating=4&q=kenya` → only P3, `matchingCount` 1 (R6, B18).
3. `minRating=5` (default sort NEWEST: date desc) → `items` exactly P2 (2026-11-06), X2 (2026-11-04), X3 (2026-11-03) in that order, `matchingCount` 3 (B18, B19).

**Negative**
4. `roast=MEDIUM` → `items` [], `matchingCount` 0, `totalCount` 6 (B18).
5. `methodId=1&roast=DARK` → [] (AND, not OR) (B18).
