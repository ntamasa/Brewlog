## Names and signatures
- `BrewApi.delete(id: number): Observable<void>` → DELETE `/api/brews/{id}`.
- `JournalStore.reloadAfterDelete()`: reloads the current page; if that answer has 0 items and `page > 1`, loads `page - 1` (and the page reports the new page for the URL).
- `BrewDeleteDialog` (`JournalPage.openDelete` opens it in BREW-39 with `MatDialog.open(BrewDeleteDialog, { data: { brew }, width: '480px', autoFocus: '[cdkFocusInitial]' })`): trash icon, "Delete this brew?", "It will be permanently removed from your journal. This can’t be undone.", summary: brew name + "<Method> · <Light|Medium|Dark> · <formatDate>" (e.g. "Pour Over · Light · 28 Oct 2026"), banner slot, `button-secondary` "Keep brew" (carries the attribute `cdkFocusInitial`, the dialog's only one; no `keep-button` class; closes with `false`) + `button-danger` "Delete brew". The dialog moves no focus itself when it opens and uses no `cdkTrapFocus`: `MatDialog` focuses the marked button (R47).
- `state = signal<'default' | 'deleting' | 'error' | 'gone'>('default')`. "Delete brew" → `deleting`, `BrewApi.delete`. The button is `matButton="filled" class="btn-danger"` with `[disabled]="state() === 'deleting'"`, `disabledInteractive` and `[attr.aria-busy]="state() === 'deleting' ? 'true' : null"`, and while deleting its content is `<span class="spinner" aria-hidden="true"></span>Deleting…`. Its handler starts with `if (this.state() === 'deleting') return;` (R48). "Keep brew" never gets `[disabled]` and still closes with `false` (B26); 204 → `close('deleted')`; network/5xx → `error`: banner "Couldn’t delete this brew" — "The server didn’t respond, so nothing was removed. Try again in a moment.", "Delete brew" retries; 404 → `gone`: banner "This brew no longer exists" — "It may have been deleted in another tab. Your journal has been refreshed.", one `button-primary` "Close" (closes with `'gone'`).
