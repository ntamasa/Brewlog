**Goal:** Add the frontend method API and store, the create call and the toast service.

**Read first:**
- Epic → Technical design → API
- Story → Frontend, Acceptance criteria (R12), Business rules (B21, B24)

## Files that change
- create `frontend/src/app/core/method-api.ts`, `core/toast.ts`, `methods/method.store.ts` (+ `.spec.ts` each).
- modify `core/brew-api.ts`: `create`. modify `core/format.ts`: `methodsAz`. Extend their specs.

## Names and signatures
- `MethodApi.list(): Observable<BrewMethod[]>` → GET `/api/methods`.
- `BrewApi.create(body: BrewBody): Observable<Brew>` → POST `/api/brews`; `interface BrewBody { name: string; beanName: string; origin: string; methodId: number | null; roast: Roast | null; rating: number | null; brewDate: string | null; notes: string | null }` in `models.ts`.
- `methodsAz(methods: BrewMethod[]): BrewMethod[]`: name A–Z with `localeCompare(…, 'en', { sensitivity: 'base' })`, protected methods last.
- `Toaster.show(text: string): void` → `MatSnackBar.open(text, undefined, { duration: 4000 })`.
- `MethodStore` (`signalStore({ providedIn: 'root' })`): state `methods: BrewMethod[]`, `status: 'idle' | 'loading' | 'ready' | 'error'`; `load()` sets `loading`, then `ready` with the list or `error`.

## Tests that prove it
**Seam:** unit · **Setup:** Vitest + TestBed, `HttpTestingController`; `MatSnackBar` spied · **Mocked:** HTTP; the store gets a fake `MethodApi`

**Happy path**
1. `BrewApi.create(body)` sends POST `/api/brews` with exactly the body and emits the flushed brew (R12).
2. `methodsAz` of [Pour Over, Other(protected), chemex, AeroPress] → AeroPress, chemex, Pour Over, Other (B21).
3. `Toaster.show('“Kenyan Morning” saved to your journal')` opens the snack bar with that text and `duration: 4000` (B24).
4. `MethodStore.load()` with the fake answering 7 methods → `status` `ready`, `methods` has 7 entries.

**Negative**
5. `MethodStore.load()` with the fake erroring (status 0) → `status` `error`, `methods` unchanged.
