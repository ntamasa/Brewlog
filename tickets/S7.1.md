**Goal:** Update a brew with `PATCH /api/brews/{id}` using merge-patch semantics and the same validation as a create.

**Read first:**
- Epic → Technical design → API, Backend, Risks (Jackson 3); Story → Hard logic (`patch`)
- Story → Acceptance criteria (R22, R23, R25), Business rules (B2, B3, B9, B25)

## Files that change
- modify `backend/src/main/java/com/brewlog/entity/Brew.java`: add the 8 setters below (no setter for `id` or `createdAt`, B9).
- create `exception/NotFoundException.java`.
- modify `exception/ApiExceptionHandler.java`: `NotFoundException` → `ProblemDetail.forStatus(404)` with property `code` (e.g. `"BREW_NOT_FOUND"`).
- modify `service/BrewDraft.java`: `set(String field, JsonNode value)`; modify `service/BrewService.java`: `patch`; modify `controller/BrewController.java`: `PATCH /api/brews/{id}` consuming `application/json` with a `tools.jackson.databind.JsonNode` body.
- create `backend/src/test/java/com/brewlog/BrewPatchIT.java`.

## Names and signatures
- `Brew`: `setName(String)`, `setBeanName(String)`, `setOrigin(String)`, `setMethod(BrewMethod)`, `setRoast(Roast)`, `setRating(int)` (stored as `(short) rating`), `setBrewDate(LocalDate)`, `setNotes(String)`, each `public void`, assigning only its field.
- `NotFoundException(ErrorCode code)` (`RuntimeException`, getter `code()`).
- `BrewService.patch(long id, JsonNode patch): BrewResponse`, `@Transactional`, as in Story → Hard logic: missing brew → `NotFoundException(BREW_NOT_FOUND)`; for each of the 8 field names present in the object (`patch.has(field)`), `draft.set(field, node)` with JSON null allowed (it becomes `null`); then `validator.validate(draft, id)`; errors → `ValidationException`; else `BrewMethod method = brewMethodRepository.getReferenceById(draft.methodId)`, then `brew.setName(draft.name)`, `setBeanName(draft.beanName)`, `setOrigin(draft.origin)`, `setMethod(method)`, `setRoast(Roast.valueOf(draft.roast))`, `setRating(draft.rating)`, `setBrewDate(draft.brewDate)`, `setNotes(draft.notes)`, then `brewRepository.saveAndFlush(brew)` and `toResponse` (inside the transaction, so the method's name and icon key load). Unknown keys are ignored. The `createdAt` is never changed (B9).
- `BrewDraft.set`: text fields `node.isNull() ? null : node.asString()`; `methodId` long; `rating` int; `brewDate` `LocalDate.parse`; `roast` string. A JSON body that isn't an object → 400 without `errors`.

## Tests that prove it
**Seam:** HTTP API · **Setup:** `BrewPatchIT extends IntegrationTest`, `TestData` · **Mocked:** nothing

**Happy path**
1. Given "Kenyan Morning" (rating 5, notes "Bright"), when PATCH `{"rating": 4}`, then 200 with the full brew, rating 4, and every other field unchanged (R22).
2. When PATCH `{"notes": null}`, then 200 with `notes` null and the column is NULL (R23).
3. When PATCH `{}`, then 200 and the row is unchanged (R23).
4. Given "Kenyan Morning" (bean "AA Kiambu", origin "Kenya", Pour Over = method 2, `LIGHT`, 5, 2026-10-28, notes "Bright"), when PATCH `{"name":"Kenyan Evening","beanName":"Yirgacheffe","origin":"Ethiopia","methodId":1,"roast":"DARK","rating":2,"brewDate":"2026-10-30","notes":"Heavy"}`, then 200 with exactly these values and `method` `{"id":1,"name":"Espresso","iconKey":"espresso"}`, the row holds them, and its `created_at` is the value it had before (R22, B9).

**Negative**
5. When PATCH `{"name": null}` and when PATCH `{"name": "  "}`, then 400 `[{"field":"name","code":"REQUIRED"}]` and the row is unchanged (R23).
6. When PATCH `{"rating": 6}`, then 400 `rating` `OUT_OF_RANGE` (R23).
7. Given another brew "Sunday Moka", when PATCH `{"name": "SUNDAY MOKA"}`, then 400 `name` `DUPLICATE`: the merged brew passes the same validation as a create (R23).
8. When PATCH `/api/brews/999` with `{"rating": 4}`, then 404 with `"code": "BREW_NOT_FOUND"` (R25).
9. When PATCH with body `{"rating": ` (malformed), then 400 without `errors` and the row is unchanged.
