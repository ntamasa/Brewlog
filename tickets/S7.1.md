**Goal:** Update a brew with `PATCH /api/brews/{id}` using merge-patch semantics, the strict body reading of R52 and the same validation as a create.

**Read first:**
- Epic → Technical design → API, Risks (Jackson 3); Technical design → Backend (below, from the spec); Story → Hard logic (`patch`, `draft.apply`)
- Story → Acceptance criteria (R22, R23, R25, R52), Business rules (B2, B3, B6, B9, B25, B28)
- R51 ("The same applies to `PATCH /api/brews/{id}`") and B28, acceptance criterion and rule of story BREW-28 (`jira.mjs read BREW-28`): `validate` already answers one database error per save since BREW-122; tests 10–11 prove it on PATCH.
- Subtask BREW-128 (R52 on `POST`, this story) built `BrewDraft.apply`, `InvalidBodyException`, `ErrorCode.INVALID_BODY` and its 422 answer: reuse them, don't change them.

## Files that change
- modify `backend/src/main/java/com/brewlog/entity/Brew.java`: add the 8 setters below (no setter for `id` or `createdAt`, B9).
- create `exception/NotFoundException.java`.
- modify `exception/ApiExceptionHandler.java`: `NotFoundException` → `ProblemDetail.forStatus(404)` with property `code` (e.g. `"BREW_NOT_FOUND"`).
- modify `service/BrewService.java`: `patch`; modify `controller/BrewController.java`: `PATCH /api/brews/{id}` consuming `application/json` with a `tools.jackson.databind.node.ObjectNode` body.
- create `backend/src/test/java/com/brewlog/BrewPatchIT.java`.

## Names and signatures
- `Brew`: the 8 setters of Technical design → Backend → `entity/`, each `public void` and assigning only its field; `setRating(int)` stores `(short) rating`.
- `NotFoundException(ErrorCode code)` (`RuntimeException`, getter `code()`).
- `BrewController.patch(@PathVariable long id, @RequestBody ObjectNode body): BrewResponse` (200).
- `BrewService.patch(long id, ObjectNode body): BrewResponse`, `@Transactional`, exactly as Story → Hard logic → `patch` and Technical design → Backend → Entity mapping: missing brew → `NotFoundException(BREW_NOT_FOUND)`; `BrewDraft.from(brew)`, then `draft.apply(body)` (its `InvalidBodyException` → 422, nothing changed); `validator.validate(draft, id)`, errors → `ValidationException`; then the 8 setters, `saveAndFlush` and `toResponse` inside the transaction. `createdAt` never changes (B9). A body that isn't a JSON object → Spring's plain 400 (Jackson rejects it before the controller).

## Tests that prove it
**Seam:** HTTP API · **Setup:** `BrewPatchIT extends IntegrationTest`, `TestData` · **Mocked:** nothing

**Happy path**
1. Given "Kenyan Morning" (rating 5, notes "Bright"), when PATCH `{"rating": 4}`, then 200 with the full brew, rating 4, and every other field unchanged (R22).
2. When PATCH `{"notes": null}`, then 200 with `notes` null and the column is NULL (R23).
3. When PATCH `{}`, then 200 and the row is unchanged (R23).
4. Given "Kenyan Morning" (bean "AA Kiambu", origin "Kenya", Pour Over = method 2, `LIGHT`, 5, 2026-10-28, notes "Bright"), when PATCH `{"name":"Kenyan Evening","beanName":"Yirgacheffe","origin":"Ethiopia","methodId":1,"roast":"DARK","rating":2,"brewDate":"2026-10-30","notes":"Heavy"}`, then 200 with exactly these values and `method` `{"id":1,"name":"Espresso","iconKey":"espresso"}`, the row holds them, and its `created_at` is the value it had before (R22, B9).

**Negative** (each: the row is unchanged)
5. When PATCH `{"name": null}` and when PATCH `{"name": "  "}`, then 400 `[{"field":"name","code":"REQUIRED"}]` (R23).
6. When PATCH `{"rating": 6}`, then 400 `rating` `OUT_OF_RANGE` (R23).
7. Given another brew "Sunday Moka", when PATCH `{"name": "SUNDAY MOKA"}`, then 400 `name` `DUPLICATE`: the merged brew passes the same validation as a create (R23).
8. When PATCH `/api/brews/999` with `{"rating": 4}`, then 404 with `"code": "BREW_NOT_FOUND"` (R25).
9. When PATCH with body `{"rating": ` (malformed), and when PATCH with the bodies `[]` and `"x"`, then 400 with no `errors` and no `code` (R41, R52).
10. Given another brew "Sunday Moka" and the method "Kalita Wave" inserted then deleted with `jdbc`, when PATCH `{"name": "SUNDAY MOKA", "methodId": <its id>}`, then 400 with `errors.length()` 1, `errors[0]` `{"field":"name","code":"DUPLICATE"}` (R51).
11. Given the same, when PATCH `{"name": "SUNDAY MOKA", "methodId": <its id>, "origin": <101 "x">}`, then 400 with `errors.length()` 1, `errors[0]` `{"field":"origin","code":"TOO_LONG"}` (R51).
12. When PATCH each body below, then 422 with `$.status` 422, `$.code` "INVALID_BODY", `$.field` as given, and no `$.errors` (R52):

```text
{"rating":"4"} → rating     {"brewDate":"2026-02-30"} → brewDate     {"methodId":3.0} → methodId
{"id":3} → id               {"foo":null} → foo
{"foo":1,"rating":"4","name":5} → name
{"rating":"4","origin":<101 × "x">} → rating
```

13. When PATCH `{"rating":99999999999,"origin":<101 × "x">}`, then 400 with `errors` exactly `[{"field":"origin","code":"TOO_LONG"},{"field":"rating","code":"OUT_OF_RANGE"}]` (R52, R17).
