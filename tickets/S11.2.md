## Tests that prove it
**Seam:** component (`JournalToolbar`) · **Setup:** TestBed + `MatSelectHarness.with({ selector: '#f-sort' })`, the `MAT_FORM_FIELD_DEFAULT_OPTIONS` provider of BREW-100 · **Mocked:** nothing
1. Given `DEFAULT_QUERY`, then the label `#f-sort-label` reads "Sort", the select's `aria-labelledby` contains `f-sort-label`, Sort shows "Newest first" and its options are, in order, "Newest first", "Oldest first", "Highest rated", "Lowest rated" (R7).
2. When "Highest rated" is chosen, then `sort` emits `HIGHEST` (R7).

**Seam:** integration (`JournalPage`) · **Setup:** TestBed, real store and API · **Mocked:** HTTP
3. Given `/journal`, when "Lowest rated" is chosen, then GET `…sort=LOWEST&page=1` is sent and the URL has `sort=LOWEST`; the cards show in the response order (R7).

**Negative**
4. `queryToParams({...DEFAULT_QUERY, sort: 'NEWEST'})` has no `sort`; `queryFromParams(?sort=OLDEST)` → `OLDEST` (R7).
5. Given sort `HIGHEST` and a search, when "Clear all" is clicked, then the sort stays `HIGHEST` (R7).

**Seam:** E2E · **Setup:** compose stack, both projects; through the API, with `p = uniqueName('Sort')`: `<p> A` (today, rating 4), then `<p> B` (today, rating 4), then `<p> C` (yesterday, rating 5) · **Mocked:** nothing
6. Given `/journal?q=<p>`, then the cards read B, A, C; with `&sort=OLDEST` C, A, B; `HIGHEST` C, B, A; `LOWEST` B, A, C (R7). (On phone, set the sort through the URL; the sheet comes in the next story.)
