## Names and signatures
- `MethodsDialog` (opened with `MatDialog.open(MethodsDialog, { width: '560px' })`, injects `MethodStore`, loads it on open): head "Brew methods" + explainer "Renaming updates every brew that uses the method. Deleting moves those brews to “Other”, or to a method you choose." + close; add row (input placeholder "Add a method, e.g. Chemex", sr-only label "New method name", `button-primary` "+ Add"; Enter adds) with the error slot below; list in `methodsDialogOrder`: `MethodIcon`, name, `brewCount(n)` + " · added by you" for custom; protected row: lock + "PROTECTED" (`label-caps`, `matTooltip` "“Other” can’t be renamed or deleted") and no buttons; hint "“Other” is always available and catches brews from deleted methods."; `button-secondary` "Done".
- `add()`: `checkMethodName(value, methods, null)` → error under the input via `methodNameMessage(…, 'dialog')`, nothing sent; else `MethodStore.add`; success: row highlighted (`highlightId`, 1200 ms), `Toaster.show('“' + name + '” added')`, input cleared and refocused; 400 `name` errors → the matching message (DUPLICATE: `existing` from the store, else the typed name); network → "Couldn’t save the method. Try again." with the input keeping its value.
- `MethodStore.status() === 'error'`: add row, list and hint replaced by `banner-error` "We couldn’t load your methods" / "The Brewlog server didn’t respond. Check that the backend is running, then try again." with `button-primary` "Try again" (refresh icon, calls `load()`); "Done" stays.

## Tests that prove it
**Seam:** integration (`MethodsDialog`) · **Setup:** TestBed, real `MethodStore` and `MethodApi`, harnesses · **Mocked:** HTTP (`HttpTestingController`), `MatSnackBar` spied

**Happy path**
1. Given GET `/api/methods` flushed with the 7 seeded methods (Pour Over `brewCount` 14, Espresso 1) + custom "chemex", then rows read Espresso "1 brew", Pour Over "14 brews", French Press, AeroPress, Moka Pot, Cold Brew, chemex "0 brews · added by you", Other with "PROTECTED" and no rename/delete buttons (R29, B11, B23).
2. When " Chemex " is added and POST `{"name":" Chemex "}` answers 201 Chemex, then the row "Chemex" with "0 brews · added by you" has the highlight class, the snack bar shows "“Chemex” added" (4000 ms), the input is empty and focused (R30).

**Negative**
3. When "+ Add" is clicked with an empty input, then "Enter a method name" shows and no request is sent (R30).
4. When 51 characters are added, then "Method name can be at most 50 characters" shows, nothing sent (R30).
5. When "pour over" is added, then "“Pour Over” already exists. Method names must be unique." shows, nothing sent (R30).
6. When the POST fails with status 0 or 500, then "Couldn’t save the method. Try again." shows and the input still reads "Chemex" (R30).
7. Given GET `/api/methods` fails, then the banner "We couldn’t load your methods" / "The Brewlog server didn’t respond. Check that the backend is running, then try again." and "Try again" show instead of the add row, list and hint, and "Done" is still there; "Try again" sends GET `/api/methods` again (R39).

**Seam:** integration (`JournalPage`) · **Setup:** TestBed, real stores · **Mocked:** HTTP
8. When "Manage methods" in the header is clicked, then the dialog opens; with the form open, choosing "Manage methods…" in the method list opens it too and leaves the method value unchanged (R29).
9. Given Chemex added in the dialog, then the Method filter and the form's method list contain Chemex between AeroPress and Cold Brew (R30, B21).

**Seam:** E2E · **Setup:** compose stack, both projects, `n = uniqueName('Chemex')` · **Mocked:** nothing
10. Given `/journal`, when "Manage methods" is clicked and `n` added, then the toast "“<n>” added" shows and the row "<n>" reads "0 brews · added by you"; adding `n` again shows "“<n>” already exists. Method names must be unique." (R30).
