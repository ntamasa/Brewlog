## Names and signatures
- `MethodsDialog` (opened with `MatDialog.open(MethodsDialog, { width: '560px', autoFocus: '[cdkFocusInitial]' })` from the header button and from the form's "Manage methods…" alike, `restoreFocus` at its default, true; injects `MethodStore`, loads it on open): head "Brew methods" + explainer "Renaming updates every brew that uses the method. Deleting moves those brews to “Other”, or to a method you choose." + close `icon-button` × (aria-label "Close", carries the attribute `cdkFocusInitial`, the dialog's only one; it stays in the head in the load-error state too, so it's there whenever the dialog opens); add row (`methods.html` lines 90–98: `<form class="field" data-field="add">` holding `<label class="sr-only" for="new-m">New method name</label>`, a `<mat-form-field>` with `<input matInput id="new-m" placeholder="Add a method, e.g. Chemex" />`, and `button-primary` "+ Add"; Enter adds) with the error slot below; list in `methodsDialogOrder`: `MethodIcon`, name, `brewCount(n)` + " · added by you" for custom; protected row: lock + "PROTECTED" (`label-caps`, `matTooltip` "“Other” can’t be renamed or deleted") and no buttons; hint "“Other” is always available and catches brews from deleted methods."; `button-secondary` "Done".
- `add()`: `checkMethodName(value, methods, null)` → `addError` set to `methodNameMessage(…, 'dialog')`, nothing sent. `addError = signal<string | null>(null)` shows as `<mat-error class="field-error">` with the `alert` icon inside the add input's form field, which is in the error state while `addError()` is set (`[errorStateMatcher]="addErrorMatcher"`, `addErrorMatcher: ErrorStateMatcher = { isErrorState: () => this.addError() !== null }`, Form fields → Error state), and each `add()` first sets it back to null; else `MethodStore.add`; success: row highlighted (`highlightId`, 1200 ms), `Toaster.show('“' + name + '” added')`, input cleared and refocused; 400 `name` errors → the matching message (DUPLICATE: `existing` from the store, else the typed name); network → "Couldn’t save the method. Try again." with the input keeping its value.
- The dialog moves no focus itself when it opens and uses no `cdkTrapFocus`: `MatDialog` focuses × (R47). The add input's refocus after a successful add (R30) stays the dialog's own `focus()` call.
- `MethodStore.status() === 'error'`: add row, list and hint replaced by `banner-error` "We couldn’t load your methods" / "The Brewlog server didn’t respond. Check that the backend is running, then try again." with `button-primary` "Try again" (refresh icon, calls `load()`); "Done" stays.

1. Given GET `/api/methods` flushed with the 7 seeded methods (Pour Over `brewCount` 14, Espresso 1) + custom "chemex", then rows read Espresso "1 brew", Pour Over "14 brews", French Press, AeroPress, Moka Pot, Cold Brew, chemex "0 brews · added by you", Other with "PROTECTED" and no rename/delete buttons (R29, B11, B23).
