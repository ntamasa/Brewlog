**Goal:** The sort e2e test reads the card names through a user-facing heading locator instead of the CSS selector `app-brew-card h3`, asserting the same four orders.

**Source (review of PR #11, tests reviewer):** `e2e/tests/journal.spec.ts` line 238, in `describe("journal sort")`, test "sorts the cards by the URL sort, newest first by default": `const cards = page.locator("app-brew-card h3");`. `~/.claude/skills/tdd/tests.md` → Playwright: "Locators are always readable and user-facing. Never use CSS or XPath selectors, ids, classes, …" and its first choice, "`getByRole` with its accessible name".

**Read first:**
- Story → Acceptance criteria (R7)
- BREW-48 (`jira.mjs read BREW-48`): it wrote this test (its test 6)

## Files that change
- modify `e2e/tests/journal.spec.ts`: in that one test, line 238 only, replace `page.locator("app-brew-card h3")` with `page.getByRole("heading", { level: 3, name: p })`. `p` is the test's own `uniqueName(...)` prefix, which every one of its three card names starts with, so the locator matches exactly those three headings, in page order. Keep the name `cards`, the `search(sort)` helper, the brews it creates and the four `toHaveText` assertions exactly as they are. Change nothing else in the file: the other tests' locators are not part of this fix.
