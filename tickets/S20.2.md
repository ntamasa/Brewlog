**Goal:** When the methods dialog closes, reload method data in the journal and the form, and switch an open form whose method was just deleted to "Other".

**Read first:**
- Story → Frontend, Acceptance criteria (R40), Business rules (B14)
- `design/screens/methods.md` (Interactions: last three bullets), `design/screens/brew-form.md` (Interactions: "Manage methods…"), `design/screenshots/brew-form.edit.desktop.png`

## Files that change
- modify `frontend/src/app/methods/methods-dialog/methods-dialog.ts`, `.spec.ts`: remember `deletedIds: number[]` and close with `{ deletedIds }` (Done, × and Esc).
- modify `frontend/src/app/journal/journal-page/journal-page.ts`, `.spec.ts`: after the dialog closes: `MethodStore.load()`, `JournalStore.reload()`, and pass `deletedIds` to the open form.
- modify `frontend/src/app/brew-form/brew-form.ts`, `.spec.ts`: `methodsDeleted(ids: number[])`.

## Names and signatures
- `BrewForm.methodsDeleted(ids: number[])`: if `methodId` is in `ids`, set it to the protected method's id from `MethodStore.methods()` (marking the control dirty); every other value stays.

## Tests that prove it
**Seam:** integration (`JournalPage` with the form open) · **Setup:** TestBed, real stores and APIs, real `MatDialog` · **Mocked:** HTTP (`HttpTestingController`)

**Happy path**
1. Given the form in edit mode with method Moka Pot (5), name "Sunday Moka" and rating 4, when "Manage methods…" is chosen, Moka Pot deleted in the dialog (POST answered 200) and "Done" clicked, then the form still reads "Sunday Moka" and rating 4, GET `/api/methods` is sent, the method select shows "Other", and GET `/api/brews…` is sent (R40).
2. Given the dialog opened from the header with no form open, when it is closed with Esc, then GET `/api/methods` and GET `/api/brews…` are sent (R40).

**Negative**
3. Given the form with method AeroPress and Moka Pot deleted in the dialog, when the dialog closes with ×, then the form keeps AeroPress (R40).
