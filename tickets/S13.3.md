## Names and signatures
- On init: `MethodStore.load()` first; when it is `ready` (or `error`, then skip the method check), take `queryFromParams` + `sanitizeQuery`; if anything was dropped, `router.navigate([], { queryParams: queryToParams(query), replaceUrl: true })`; then `store.setQuery(query)`.
- Subscribe to `route.queryParamMap` (Back/Forward and links change it without re-creating the page): when the parsed query differs from `store.query()`, call `store.setQuery(parsed)`. The URL-writing `effect` skips writing when the URL already matches, so there is no loop. When the store moves to the last page (R10), the URL is updated with `replaceUrl: true`.
- Toolbar, chips and sheet always show `store.query()` values.
- On `pageChange`: after setting the page, `gridTop.nativeElement.scrollIntoView({ block: 'start' })` (the element above the grid).

## Tests that prove it
**Seam:** integration (`JournalPage`) · **Setup:** TestBed, real stores and APIs, `RouterTestingHarness` · **Mocked:** HTTP

**Happy path**
1. Given `/journal?q=kenya&roast=LIGHT&minRating=4&sort=HIGHEST&page=2`, then after GET `/api/methods` the brews GET is `q=kenya&roast=LIGHT&minRating=4&sort=HIGHEST&page=2`, the Search field reads "kenya", Roast "Light", Min. rating "4+ beans", Sort "Highest rated" (R8).
2. Given page 3 of 4, when the search, the method, the roast, the min rating or the sort changes, then each next GET has `page=1` (R8, B20).
3. Given the user went from page 1 to page 2, when the router navigates back to `/journal` (no params), then GET `…page=1` is sent and page 1 is current (R8).
4. Given `?page=9` answered with `items` [] and `totalPages` 4, then GET `…page=4` follows and the URL reads `page=4` (R10).
5. When page 2 is clicked, then `scrollIntoView` is called on the grid top (R8).

**Negative**
6. Given `/journal?roast=FOO&methodId=9` and methods without id 9, then the URL becomes `/journal` (both params removed), the brews GET has neither param, and the toolbar shows "All roasts" and "All methods" (R9).
7. Given the last page, then › is disabled (R8).

**Seam:** E2E · **Setup:** compose stack, both projects; with `p = uniqueName('URL')`, 14 brews `<p> 01`…`<p> 14` (Pour Over, Light, rating 4) created through the API · **Mocked:** nothing
8. Given `/journal?q=<p>&roast=LIGHT&minRating=4&sort=HIGHEST&page=2`, then 2 cards show and "Showing 13–14 of 14"; after `page.reload()` the same; after going to page 1 and `page.goBack()`, page 2 again (R8).
