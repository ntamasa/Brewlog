**Goal:** Publish the compose `db` port on the host's loopback only, so the LAN can't reach Postgres with its known password.

**Source (review of PR #3):** Technical design → Deployment below, `docker-compose.yml` bullet: "port `127.0.0.1:5432:5432` (host loopback only, so the LAN can't reach Postgres with its known password while a backend run outside Compose still finds it on `localhost:5432`; from grilling)". 1. When `docker compose config` runs, then `db.ports` has exactly one entry with `host_ip: 127.0.0.1`, `target: 5432`, `published: "5432"`, `protocol: tcp`; `db` still mounts `brewlog-data` at `/var/lib/postgresql/data`, and `brewlog-data` is still under the top-level `volumes:`.
2. Given `docker compose down -v && docker compose up -d --build --wait`, when `docker compose port db 5432` runs, then it prints `127.0.0.1:5432`; and `cd e2e && npx playwright test` passes in both projects (the backend still reaches Postgres on `db:5432` inside the compose network).

**Negative**

4. `docker compose config` still shows no `ports` on `backend` and `8081:80` on `frontend` (unchanged).
