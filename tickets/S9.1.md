## Names and signatures
- `BrewDetailDialog` (opened with `MatDialog.open(BrewDetailDialog, { data: { brew }, width: '640px', autoFocus: '[cdkFocusInitial]' })`, `restoreFocus` at its default, true): method icon + name, brew name, "Bean · Origin", facts Rating ("n of 5"), Roast ("Light"/"Medium"/"Dark"), Method, Brewed on (`formatDate`), notes with `white-space: pre-line`, or muted "No tasting notes yet. Edit this brew to add some."; ghost "Delete" (closes with `'delete'`), primary "Edit brew" (closes with `'edit'`), close `icon-button` × (aria-label "Close", carries the attribute `cdkFocusInitial`, the dialog's only one; closes with `undefined`). The dialog moves no focus itself and uses no `cdkTrapFocus`: `MatDialog` focuses × on open and returns focus to the card's name button on close (R47, R26).
- `JournalPage.openDetail(brew)`: on `'edit'` → `openEdit(brew)`; on `'delete'` → `openDelete(brew)`.

## Tests that prove it
**Seam:** component (`BrewDetailDialog`) · **Setup:** TestBed, real `MatDialog` · **Mocked:** HTTP (sprite)

**Happy path**
1. Given Kenyan Morning (AA Kiambu, Kenya, Pour Over, LIGHT, 5, 2026-10-28, notes "Jasmine\nBlackcurrant"), then the dialog shows "Pour Over", "Kenyan Morning", "AA Kiambu · Kenya", "5 of 5", "Light", "Brewed on" "28 Oct 2026", and the notes element's text contains the line break with computed `white-space` `pre-line` (R26).
2. When "Edit brew" is clicked, it closes with `'edit'`; when "Delete" is clicked, it closes with `'delete'` (R26).

**Negative**
3. Given notes `null`, then "No tasting notes yet. Edit this brew to add some." shows (R26).
4. When Esc is pressed or × clicked, then it closes with `undefined` (R26).

**Seam:** integration (`JournalPage`) · **Setup:** TestBed, real stores and `MatDialog`; focus tests like those in `journal-page.spec.ts` (BREW-23: `MATERIAL_ANIMATIONS` disabled, the card's name button focused with its harness's `focus()` before `click()`, `vi.waitFor` on `document.activeElement`) · **Mocked:** HTTP
5. Given a card, when it is clicked, then the detail opens; when "Edit brew" is clicked there, the form opens in edit mode for that brew; when "Delete" is clicked, "Delete this brew?" opens (R26).
6. Given a card's name button focused, when it is clicked, then the detail opens with focus on × "Close"; when Esc is pressed, then focus returns to that card's name button (R47, R26).
7. Given the detail opened from the focused name button of the second card, when × "Close" is clicked, then focus returns to the second card's name button, not the first card's (R47, R26).

**Negative**
8. Given a card, when its ⋮ is clicked, then the menu opens and the detail does not (R26).
9. Given the detail just opened, then "Edit brew" doesn't have focus, and the dialog contains exactly one `[cdkFocusInitial]` element, × "Close" (R47).
