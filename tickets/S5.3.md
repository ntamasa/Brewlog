## Names and signatures
- Controls get `BREW_VALIDATORS`. `updateOn` stays `change`, but a control shows its error only when `submitted()` is true and the control is touched or dirty, so a field re-validates on blur or change after the first submit.
- The error state follows Form fields → Error state. `BrewForm` replaces BREW-101's `NO_ERROR_STATE` provider with `{ provide: ErrorStateMatcher, useExisting: forwardRef(() => BrewForm) }` and implements `isErrorState(control: AbstractControl | null): boolean`, which returns `this.submitted() && !!control && control.invalid && (control.touched || control.dirty)` and the control's message (its name found in `this.form.controls`, then `fieldErrorMessage`) isn't `null`, so a field never shows the red error state without a text.
- `submitted = signal(false)`. `submit()` sets `submitted` and marks all touched. If the form is invalid, it sends nothing and shows the banner:
  - its text is `n === 1 ? "1 field needs your attention" : n + " fields need your attention"`, so singular only for exactly 1
  - it holds one `<li><a href="#<id>">message</a></li>` per invalid field, in form order
  - the ids are those of Form fields: `name`, `bean`, `origin`, `method-btn`, `date`, `notes`; Rating's fieldset is `rating`, and the Roast level fieldset gets `id="roast"`
  - the banner gets the focus (`tabindex="-1"`)
  - clicking a link focuses that control: `#<id>` itself, or inside a fieldset its first `input[tabindex="0"]` or `button`
- Each field's message is `fieldErrorMessage(field, control.errors)` (BREW-26), with the API field names (`name`, `beanName`, `origin`, `methodId`, `roast`, `rating`, `brewDate`, `notes`). Never pick the code with `Object.keys(errors)[0]`: the date control also carries Material's `matDatepickerMax` (from `[max]="today"`, which stays so the picker greys out later days) and `matDatepickerParse`, which `fieldErrorMessage` skips. So a typed future date shows "The date can’t be in the future" exactly once.
- A field whose message is `null` (no listed code, or a pair with no text, e.g. a server `{field:'methodId', code:'TOO_LONG'}`) renders no `mat-error` / `p.field-error`, is not in the error state (no `mat-form-field-invalid`, no `has-error` class), and isn't in the banner. The banner's `n` and links count only fields with a message, and the banner shows only when `n >= 1`.
- One message per field, one at a time:
  - Brew name, Bean name, Origin, Date and Tasting notes show it, inside `@if (message)`, as exactly one `<mat-error class="field-error"><mat-icon svgIcon="alert" aria-hidden="true" />{{ message }}</mat-error>` inside their `mat-form-field`. Material links it with `aria-describedby`, draws the red outline and the error-soft fill (`theme.scss`, BREW-100), and hides the hint meanwhile.
  - Brew method: `MethodSelect` gets `error = input<string | null>(null)`. Its `mat-select` gets `[errorStateMatcher]="errorMatcher"`, with `errorMatcher: ErrorStateMatcher = { isErrorState: () => this.error() !== null }`, and its form field shows the same `mat-error` with `error()`. `BrewForm` passes the method's message, or null.
  - Roast level and Rating show `<p class="field-error">` with the same alert icon under their group, and their fieldset gets the class `has-error`.
  - `brew-form.scss` ports `components.css` line 110 as `.field.has-error .segmented { border-color: var(--color-error); background-color: var(--color-error-soft); }`.
  - `bean-rating.scss` ports line 127 as `:host-context(.field.has-error) .rating-input label { color: var(--color-error); }`.
- `serverErrors = signal<ApiFieldError[]>([])`: on a 400 `fields` answer (via `parseApiError`), set each control's error `{ [code]: true }` with `setErrors`, and show the same banner with those fields.
- Notes counter: shown when `notes.trim().length > 1800`, text `n.toLocaleString('en-US') + ' / 2,000'`, class `counter-error` when over 2000, `aria-live="polite"` region updated only when it appears and when it crosses 2000.
- Date input: an unparseable typed value leaves the control `null`, so it shows "Choose a date".

## Tests that prove it
**Seam:** component · **Setup:** TestBed + harnesses, `vi.setSystemTime(new Date(2026, 10, 1, 9, 0))`, the `MAT_FORM_FIELD_DEFAULT_OPTIONS` provider of BREW-100 · **Mocked:** HTTP (`HttpTestingController`)

Following Form fields → Tests:
- controls are found by id (`MatInputHarness.with({ selector: '#origin' })`)
- a field's message is `MatFormFieldHarness.with({ ancestor: '[data-field="origin"]' }).getTextErrors()`
- the error state is the form field's class `mat-form-field-invalid`
- the roast and rating messages are the `p.field-error` text in `[data-field="roast"]` and `[data-field="rating"]`

**Happy path**
1. Given an empty create form, when "Add to journal" is clicked, then no request is sent, the banner reads "6 fields need your attention" with links "Enter a brew name", "Enter a bean name", "Enter where the beans are from", "Choose a brew method", "Choose a roast level", "Choose a rating from 1 to 5 beans", the banner has focus, and each field shows its message (R13).
2. Given that state, when "Kenyan Morning" is typed in Brew name and the field blurs, then its error disappears and the banner count stays until the next submit (R13).
3. Given notes of 1801 characters, then the counter reads "1,801 / 2,000"; at 1800 there is no counter; at 2001 it reads "2,001 / 2,000" with `counter-error`, and the text is not cut off (R15).
4. Given a filled form whose POST answers 400 `{errors:[{field:'origin',code:'TOO_LONG'}]}`, then Origin shows "Origin can be at most 100 characters" and the form keeps every value (R15).

**Negative**
5. Given the date input cleared, when submitting, then "Choose a date" shows (R13).
6. Given the typed date "2 Nov 2026" and everything else valid, when submitting, then the date control's errors hold both `FUTURE_DATE` and `matDatepickerMax`, the date field's `getTextErrors()` is exactly `["The date can’t be in the future"]`, the banner reads "1 field needs your attention" with exactly one link "The date can’t be in the future", and nothing is sent (R18).
7. Given name of 101 characters (pasted), then the input holds all 101 and, on submit, "Brew name can be at most 100 characters" shows; the same for bean ("Bean name can be at most 100 characters") and origin (R15).
8. Given bean `"   "` and everything else valid, when submitting, then only Bean name shows an error ("Enter a bean name"), the banner reads exactly "1 field needs your attention" (not "1 fields …") with exactly one link "Enter a bean name", and no request is sent (R13, R14).
9. Given only Brew name, Bean name and Origin empty, when submitting, then the banner reads "3 fields need your attention" with 3 links (R13).
10. Given rating not set, then "Choose a rating from 1 to 5 beans" shows, and the rating group reads "Not rated" (R17).
11. Given an empty create form, when "Add to journal" is clicked, then the Brew name, Bean name, Origin and method form fields have the class `mat-form-field-invalid`. Each of their `mat-error`s has the class `field-error` and holds an icon named `alert`. The Brew name hint isn't shown (R13).
12. Given a new form, when "Kenyan Morning" is typed into Brew name, then cleared and blurred before any submit, then no form field has `mat-form-field-invalid` and the form has no `mat-error` (R13).
13. Given test 1's state, when "Kenyan Morning" is typed into Brew name, then its form field loses `mat-form-field-invalid` and its hint "A name only you would recognise, like “Sunday Moka”. Must be unique." shows again (R13).
14. Given test 1's state, when the banner link "Enter where the beans are from" is clicked, then focus is on `#origin` (R13).
15. Given the typed date "not a date" and everything else valid, when submitting, then the date field's `getTextErrors()` is exactly `["Choose a date"]` and nothing is sent (R13).
16. Given a filled form whose POST answers 400 `{errors:[{field:'origin',code:'TOO_LONG'},{field:'methodId',code:'TOO_LONG'}]}`, then Origin shows "Origin can be at most 100 characters", the method form field has no `mat-error` and no `mat-form-field-invalid`, and the banner reads "1 field needs your attention" with exactly one link "Origin can be at most 100 characters" (R15).
