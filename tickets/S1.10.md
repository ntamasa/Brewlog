**Goal:** Make `SchemaIT` prove which check constraint each bad insert violates, and make the test reset replay the seed changeset itself instead of a copy of it.

**Source (review of PR #3):**
- BREW-8, test 5: "Given otherwise valid rows, when `rating` 6, `rating` 0 or `roast` `BOLD` is inserted, then each insert fails on its check constraint and `brew` stays empty." The tests only check `DataIntegrityViolationException`, not the constraint.
- Technical design → Seams and tests, "Backend integration" row, Setup (published in story BREW-10): "`IntegrationTest.resetDatabase()` (`@BeforeEach`) runs `classpath:reset.sql` (only `TRUNCATE brew, brew_method RESTART IDENTITY CASCADE;`), then `classpath:db/changelog/002-seed-methods.sql` (its Liquibase lines are SQL comments), so the seed has one source and Espresso is id 1 … Other id 7 in every test (from grilling)".

**Read first:**
- Epic → Technical design → Data model, Risks (the bullet "The test reset replays only `002-seed-methods.sql`")
- `backend/src/test/java/com/brewlog/SchemaIT.java`, `support/IntegrationTest.java`, `backend/src/test/resources/reset.sql`, `backend/src/main/resources/db/changelog/002-seed-methods.sql`

## Files that change
- modify `backend/src/test/resources/reset.sql`: only the line `TRUNCATE brew, brew_method RESTART IDENTITY CASCADE;`. The 7 `INSERT` rows are removed.
- modify `backend/src/test/java/com/brewlog/support/IntegrationTest.java`: `resetDatabase()` becomes `protected` (still `@BeforeEach`, still `throws Exception`) and, on the same connection, runs `ScriptUtils.executeSqlScript(connection, new ClassPathResource("reset.sql"))` and then `ScriptUtils.executeSqlScript(connection, new ClassPathResource("db/changelog/002-seed-methods.sql"))`. `ScriptUtils` skips `--` lines, so the Liquibase header lines need no handling. The seed rows are never copied into test code or test resources.
- modify `backend/src/test/java/com/brewlog/SchemaIT.java`: extend `rejectsARatingAboveFive`, `rejectsARatingBelowOne` and `rejectsAnUnknownRoast` (tests 3–5) and add `resetRestoresTheSeedWithIdsOneToSeven` (test 1). The other tests stay as they are.

## Names and signatures
- `protected void resetDatabase() throws Exception` in `IntegrationTest`
- Constraint names: PostgreSQL names an unnamed column `CHECK` `<table>_<column>_check`, so `001-init.sql` gives `brew_rating_check` and `brew_roast_check`.

## Tests that prove it
**Seam:** database through Spring · **Setup:** `SchemaIT extends IntegrationTest` · **Mocked:** nothing

**Happy path**
1. Given a method `Siphon` inserted into `brew_method` (it gets id 8) and one valid brew inserted, when the test calls `resetDatabase()`, then `brew` has 0 rows and `SELECT id, name FROM brew_method ORDER BY id` returns exactly (1, Espresso), (2, Pour Over), (3, French Press), (4, AeroPress), (5, Moka Pot), (6, Cold Brew), (7, Other). The reset runs right after the `@BeforeEach` one without failing on `ux_brew_method_name`.
2. `seedsTheSevenPredefinedMethodsInOrder` passes unchanged, now against the replayed `002-seed-methods.sql`.

**Negative**
3. Given otherwise valid rows, when a brew with `rating` 6 is inserted, then a `DataIntegrityViolationException` is thrown whose message contains `brew_rating_check`, and `brew` stays empty.
4. The same with `rating` 0: the message contains `brew_rating_check`, and `brew` stays empty.
5. The same with `roast` `BOLD` (rating 5): the message contains `brew_roast_check`, and `brew` stays empty.
6. `grep -rn "INSERT" backend/src/test/resources` prints nothing: the seed exists only in `002-seed-methods.sql`.

## Out of scope
- `001-init.sql` and `002-seed-methods.sql` don't change: editing an applied changeset breaks its Liquibase checksum.
- Testing the constraint name through `PSQLException`: the PostgreSQL driver is `runtimeOnly`, so test code can't import it. Check the message, as the `ux_brew_name` tests already do.
