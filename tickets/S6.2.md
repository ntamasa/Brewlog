**Goal:** Show the duplicate-name, method-gone and server-error states in the brew form, keeping every value.

**Read first:**
- Story → Frontend, Acceptance criteria (R16, R19, R20), Business rules (B5, B25)
- `design/screens/brew-form.md` (States duplicate-name, method-gone, server-error, saving), `design/prototype/screens/brew-form.html` (banners, lines 75–105), `design/screenshots/brew-form.duplicate-name.desktop.png`, `design/screenshots/brew-form.method-gone.desktop.png`, `design/screenshots/brew-form.server-error.desktop.png`

## Files that change
- modify `frontend/src/app/brew-form/brew-form.ts`, `.html`, `.spec.ts`.
- modify `frontend/src/app/journal/journal-page/journal-page.ts`: pass a `reloadMethods` handler (calls `MethodStore.load()`).
- modify `e2e/tests/brew-form.spec.ts`.

## Names and signatures
- `banner = signal<FormBanner | null>(null)` with `type FormBanner = { kind: 'fields'; fields: string[] } | { kind: 'duplicate' } | { kind: 'methodGone' } | { kind: 'server' }`.
- On a 400 with `name` `DUPLICATE`: banner "Couldn’t save your changes" + link "That brew name is already taken" (to `#name`), name error `brewFieldMessage('name', 'DUPLICATE', <name as typed, trimmed>)`.
- On a 400 with `methodId` `METHOD_NOT_FOUND`: `MethodStore.load()`, `methodId` set to `null`, its error `METHOD_NOT_FOUND` ("This method no longer exists. Choose another one."), banner "Couldn’t save your brew" + link "This method no longer exists" (to the method field) + ". Choose another one." Choosing a method clears that error.
- On `network` (status 0, 5xx, 400 without errors): banner "Couldn’t save your brew" + "The Brewlog server didn’t respond. Nothing was lost: your entry is still here, so you can try again."; no toast; `saved` is not emitted.
- Every banner gets focus; the fields keep their values; `saving` is reset.

## Tests that prove it
**Seam:** component (`BrewForm`) · **Setup:** TestBed + harnesses, real `BrewApi`, `MethodStore` · **Mocked:** HTTP (`HttpTestingController`), `MatSnackBar` spied

**Happy path**
1. Given a filled form named "kenyan morning", when the POST answers 400 `{errors:[{field:'name',code:'DUPLICATE'}]}`, then the banner reads "Couldn’t save your changes" with "That brew name is already taken", the name error reads "You already have a brew called “kenyan morning”. Brew names must be unique, ignoring capitals.", every field keeps its value and `saved` is not emitted (R16).
2. Given method Moka Pot selected, when the POST answers 400 `methodId` `METHOD_NOT_FOUND`, then GET `/api/methods` is sent, the select shows "Choose a method" with "This method no longer exists. Choose another one.", the banner reads "Couldn’t save your brew", and the other fields keep their values (R19).
3. Given that state, when AeroPress is chosen and "Add to journal" clicked, then the method error is gone and a POST with `methodId` 4 is sent (R19).

**Negative**
4. Given the POST fails with status 0, then the banner reads "Couldn’t save your brew" / "The Brewlog server didn’t respond. Nothing was lost: your entry is still here, so you can try again.", the fields keep their values, the button reads "Add to journal" again and no snack bar opens (R20).
5. Given the POST answers 500, then the same server banner shows (R20).
6. Given the POST unflushed, then the button reads "Saving…" with `aria-busy="true"` and all inputs are disabled (R20).

**Seam:** E2E · **Setup:** compose stack, both projects · **Mocked:** nothing
7. Given a brew created through the API with `uniqueName('Dup')`, when the form is submitted with that name in lower case, then the name error "You already have a brew called “<lower-case name>”. Brew names must be unique, ignoring capitals." shows and the form stays open (R16).
