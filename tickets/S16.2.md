## Names and signatures
- `MethodApi.rename(id: number, name: string): Observable<BrewMethod>` → PUT `/api/methods/{id}` `{ name }`.
- `MethodStore.rename(id, name): Observable<BrewMethod>`: on success replaces that method in `methods`.
- Dialog: each non-protected row gets a pencil `icon-button` (aria-label "Rename <name>"); `renamingId = signal<number | null>(null)`; the row turns ivory with `<label class="sr-only" for="rename">Rename <name></label>` and a `<mat-form-field>` holding the focused `<input matInput id="rename" />` with the current name (`methods.html` lines 112–115), ghost "Cancel" + primary "Save". `renameError = signal<string | null>(null)` shows as `<mat-error class="field-error">` with the `alert` icon inside that form field, which is in the error state while it is set (`[errorStateMatcher]`, as `addErrorMatcher` in BREW-60); each save attempt first sets it back to null. Enter / "Save": `checkMethodName(value, methods, id)` → `renameError` (`'dialog'` texts), nothing sent; else `MethodStore.rename`; success: row back to normal with the new name, `Toaster.show('Renamed to “' + name + '”')`, `JournalStore.reload()` (cards show the new name); 400 → matching message; network → "Couldn’t save the method. Try again.". Esc / "Cancel": leave the row unchanged, focus back on the pencil.
- For now every valid rename saves directly; the next story adds the confirmation step for methods with brews.

## Tests that prove it
**Seam:** integration (`MethodsDialog`) · **Setup:** TestBed, real `MethodStore`, `MethodApi`, `JournalStore` · **Mocked:** HTTP (`HttpTestingController`), `Toaster` (`{ provide: Toaster, useValue: { show: vi.fn() } }`, BREW-104) · the `MAT_FORM_FIELD_DEFAULT_OPTIONS` provider of BREW-100; the input is `MatInputHarness.with({ selector: '#rename' })`

**Happy path**
1. Given "Chemex" (0 brews), when its pencil is clicked, "Chemex Classic" typed and Enter pressed, then PUT `/api/methods/8` `{"name":"Chemex Classic"}`; after 200 the row reads "Chemex Classic" and `Toaster.show` is called with "Renamed to “Chemex Classic”" (R32).
2. Given "moka" (custom), when renamed to "Moka", then the PUT is sent (no duplicate error with itself) (R24).

**Negative**
3. Given the rename input, when Esc is pressed or "Cancel" clicked, then no request is sent and the row still reads "Chemex" (R32).
4. When the input is emptied → "Enter a method name"; 51 characters → "Method name can be at most 50 characters"; "espresso" → "“Espresso” already exists. Method names must be unique."; in each case nothing is sent (R32).
5. Given the PUT answers 503, then the rename field's `mat-error` reads "Couldn’t save the method. Try again.", the field has `mat-form-field-invalid`, and the input keeps "Chemex Classic" (R32).
6. Given "Other", then it has no pencil (B11).
