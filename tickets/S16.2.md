## Names and signatures
- `MethodApi.rename(id: number, name: string): Observable<BrewMethod>` → PUT `/api/methods/{id}` `{ name }`.
- `MethodStore.rename(id: number, name: string, from: 'row-rename' | 'step-rename'): Observable<BrewMethod>`: on success replaces that method in `methods`. It sets `pending` exactly as `add` does (BREW-59, Hard logic there: `defer` sets `from`, `finalize` sets null). This subtask calls it with `'row-rename'`; the rename step (BREW-68) with `'step-rename'`.
- Pencil (`matIconButton`, aria-label "Rename <name>"): `[disabled]="methodStore.pending() !== null"`, `disabledInteractive`, `[tabIndex]="methodStore.pending() !== null ? -1 : 0"`; its handler starts with `if (this.methodStore.pending()) return;`, so a blocked pencil opens no rename (R48).
- Row "Save" (`matButton="filled"`, label "Save", no spinner): `[disabled]="methodStore.pending() !== null"`, `disabledInteractive`, `[attr.aria-busy]="methodStore.pending() === 'row-rename' ? 'true' : null"`, `[tabIndex]="methodStore.pending() !== null && methodStore.pending() !== 'row-rename' ? -1 : 0"`. `#rename` (a plain `matInput` like `#new-m`, `#renameInput`, `renameInput = viewChild<ElementRef<HTMLInputElement>>('renameInput')`): `[disabled]="methodStore.pending() === 'row-rename'"`. Row "Cancel" never gets `[disabled]`, and Esc still cancels (B26).
- The save handler (Enter and "Save") starts with `if (this.methodStore.pending()) return;`. After an error answer (400 or network), `#rename` keeps its value and is focused after the next render, as BREW-60 refocuses `#new-m` (R49).
- Dialog: each non-protected row gets a pencil `icon-button` (aria-label "Rename <name>"); `renamingId = signal<number | null>(null)`; the row turns ivory with `<label class="sr-only" for="rename">Rename <name></label>` and a `<mat-form-field>` holding the focused `<input matInput id="rename" />` with the current name (`methods.html` lines 112–115), ghost "Cancel" + primary "Save". `renameError = signal<string | null>(null)` shows as `<mat-error class="field-error">` with the `alert` icon inside that form field, which is in the error state while it is set (`[errorStateMatcher]="renameErrorMatcher"`, `renameErrorMatcher: ErrorStateMatcher = { isErrorState: () => this.renameError() !== null }`, as `addErrorMatcher` in BREW-60); each save attempt and each pencil click that opens a rename first set it back to null. Enter / "Save": `checkMethodName(value, methods, id)` → `renameError` (`'dialog'` texts), nothing sent; else `MethodStore.rename(id, name, 'row-rename')`; success: row back to normal with the new name, `Toaster.show('Renamed to “' + name + '”')`, `JournalStore.reload()` (cards show the new name); 400 → matching message; network → "Couldn’t save the method. Try again.". Esc / "Cancel": leave the row unchanged, focus back on the pencil.
- Error state of `#rename`: as `#new-m` in BREW-60, it has no ngControl, so `MatInput.ngDoCheck` never re-runs its matcher (`@angular/material/fesm2022/input.mjs` lines 204–210, Material 22.3.0) and `[errorStateMatcher]` alone never shows `mat-form-field-invalid` or the `mat-error`. So the dialog adds `private readonly renameMatInput = viewChild('renameInput', { read: MatInput })` (not `required`: no row is in rename most of the time) and, in its constructor next to BREW-60's effect, `effect(() => { this.renameError(); this.renameMatInput()?.updateErrorState(); })`. It re-runs when the message changes and when a new `#rename` appears. No `FormControl` on `#rename`.
- For now every valid rename saves directly; the next story adds the confirmation step for methods with brews.

## Tests that prove it
**Seam:** integration (`MethodsDialog`) · **Setup:** TestBed, real `MethodStore`, `MethodApi`, `JournalStore` · **Mocked:** HTTP (`HttpTestingController`), `Toaster` (`{ provide: Toaster, useValue: { show: vi.fn() } }`, BREW-104) · the `MAT_FORM_FIELD_DEFAULT_OPTIONS` provider of BREW-100; the input is `MatInputHarness.with({ selector: '#rename' })` and its field `MatFormFieldHarness.with({ ancestor: '.m-row.editing' })` (the row in rename has the prototype's classes `m-row editing`), its message that field's `getTextErrors()`

**Happy path**
1. Given "Chemex" (0 brews), when its pencil is clicked, "Chemex Classic" typed and Enter pressed, then PUT `/api/methods/8` `{"name":"Chemex Classic"}`; after 200 the row reads "Chemex Classic" and `Toaster.show` is called with "Renamed to “Chemex Classic”" (R32).
2. Given "moka" (custom), when renamed to "Moka", then the PUT is sent (no duplicate error with itself) (R24).

**Negative**
3. Given the rename input, when Esc is pressed or "Cancel" clicked, then no request is sent and the row still reads "Chemex" (R32).
4. When the input is emptied → "Enter a method name"; 51 characters → "Method name can be at most 50 characters"; "espresso" → "“Espresso” already exists. Method names must be unique."; in each case the field has `mat-form-field-invalid` and nothing is sent; before the first Enter it had neither. Then, when "Chemex Classic" is typed and Enter pressed, the field no longer has `mat-form-field-invalid`, its `getTextErrors()` is `[]`, and exactly one PUT `/api/methods/8` is open (R32). Without the `renameError` effect this test fails.
5. Given the PUT answers 503, then the rename field's `mat-error` reads "Couldn’t save the method. Try again.", the field has `mat-form-field-invalid`, and the input keeps "Chemex Classic" (R32).
6. Given "Other", then it has no pencil (B11).
**Busy and blocked (R48, R49, B26)**, same seam and setup:
7. Given "Chemex" (0 brews) in rename with "Chemex Classic" and Enter pressed, PUT not flushed yet, then the row "Save" has `aria-busy="true"` and `aria-disabled="true"`, no `disabled` attribute, the text "Save" and no `span.spinner`; `#rename` is disabled and reads "Chemex Classic"; "+ Add" and every pencil ("Rename Espresso", …) have `aria-disabled="true"` and `tabindex="-1"` and no `aria-busy`; the row "Cancel", "Done" and × have neither `disabled` nor `aria-disabled` (R48, R49, B26).
8. Negative: in test 7's state, a second click on "Save" leaves exactly one PUT `/api/methods/8`, and a click on "Rename Espresso" opens no second rename input (still exactly one `#rename`, reading "Chemex Classic") (R48).
9. Negative: in test 7's state, when the PUT answers 503, then "Save" has no `aria-busy`, `#rename` is enabled, still reads "Chemex Classic" and is `document.activeElement` (after `await fixture.whenStable()`), and the pencils have no `aria-disabled="true"` (R48, R49).
10. Given "Chemex" typed into `#new-m` and "+ Add" clicked (POST not flushed), then every pencil has `aria-disabled="true"` and `tabindex="-1"`, and clicking "Rename Espresso" opens no `#rename` (R48, state adding).
11. Negative: given the rename of "Chemex" open, when "Kalita" is added with "+ Add" (POST not flushed), then the row "Save" has `aria-disabled="true"`, `tabindex="-1"` and no `aria-busy`, and clicking it sends no PUT (`http.expectNone`) (R48).

**Error state reset**, same seam and setup:
12. Negative: given "Chemex"'s rename showing "Enter a method name" (input emptied, Enter pressed), when Esc is pressed and "Rename Chemex" clicked again, then the field has no `mat-form-field-invalid` and its `getTextErrors()` is `[]` (R32).
