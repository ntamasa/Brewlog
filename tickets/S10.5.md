**Goal:** A search typed again after the search was cleared (chip ×, "Clear all", "Clear search and filters", or a URL change) is sent again.

**Read first:**
- Story → Frontend, Acceptance criteria (R5)
- BREW-44 (`jira.mjs read BREW-44`): `JournalStore.setSearch`
- BREW-45 (`jira.mjs read BREW-45`): `clearFilters`, `removeFilter`, the chip × and "Fake-timer harness" under "Tests that prove it"

**The bug:** `setSearch` runs `debounceTime(250)`, then `distinctUntilChanged()`, so it compares each search only with the last *search*. `clearFilters`, `removeFilter` and `setQuery` reset `query().q` without going through `setSearch`. So: search "kenya", clear it with the chip ×, type "kenya" again: `distinctUntilChanged` drops it. No request is sent, the list stays unfiltered, and the URL has no `q` (breaks R5).

## Files that change
- modify `frontend/src/app/journal/journal.store.ts`: `setSearch` only.
- modify `frontend/src/app/journal/journal.store.spec.ts` (tests 1–5, in the existing `describe('setSearch')`).
- modify `frontend/src/app/journal/journal-page/journal-page.spec.ts` (tests 6–7).

## Names and signatures
- `JournalStore.setSearch` stays `rxMethod<string>`. After `debounceTime(250)`, it compares the text with the store's **current** query instead of the previous search: it drops the text only when `text === store.query().q`. Remove `distinctUntilChanged` (and its import).
- Compare the raw text, untrimmed, as today: the store keeps `q` as typed and the API trims (BREW-44).

## Hard logic
```ts
const search = rxMethod<string>(
  pipe(
    debounceTime(250),
    filter((text) => text !== store.query().q),
    tap((text) => load({ ...store.query(), q: text, page: 1 })),
  ),
);
```
