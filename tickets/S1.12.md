**Goal:** Make the brand-mark test start from a scrolled-down page, so it proves that the brand mark drops the fragment and lands on `/`.

**Source (review of PR #3):** BREW-7, negative test 5: "Given the page scrolled down, when the brand mark is clicked, then the URL stays `/` with no fragment (R1)." The test "keeps the URL at / when the brand mark is clicked (R1)" starts at `/` without scrolling and checks only `router.url`, so it passes even if the brand mark did nothing.

**Read first:**
- Story → Acceptance criteria (R1)
- `frontend/src/app/landing/landing-page/landing-page.spec.ts` (its `render` and `click` helpers), `frontend/src/app/landing/landing-page/landing-page.html` (the two `a.brand` links)

## Files that change
- modify `frontend/src/app/landing/landing-page/landing-page.spec.ts`: replace the test "keeps the URL at / when the brand mark is clicked (R1)" with the test "goes to / with no fragment from both brand marks after scrolling down (R1)" (tests 1 and 2). The other tests stay as they are.
- No production code changes: both brand links already have `routerLink="/"`.

## Tests that prove it
**Seam:** component · **Setup:** the spec's existing `render('/')`, `Router` from `TestBed` · **Mocked:** HTTP

How the page is scrolled down: jsdom has no layout and doesn't implement `window.scrollTo`, so the test scrolls down the way the page itself does, by clicking "How it works", which moves to the `#how` section. Assert that start state before clicking the brand mark.

**Negative**
1. Given `/` rendered and "How it works" clicked (`router.url` is `/#how`), when the hero nav brand mark (`.hero-nav a.brand`, text "Brewlog") is clicked, then `router.url` is `'/'` and `router.parseUrl(router.url).fragment` is `null` (R1).
2. Given the same start state again (`/#how` after clicking "How it works"), when the footer brand mark (`footer a.brand`, text "Brewlog") is clicked, then `router.url` is `'/'` and the fragment is `null` (R1).
3. One-off check that the test isn't vacuous: temporarily add `fragment="how"` to the hero brand link in `landing-page.html`, and test 1 fails. Revert it.

## Out of scope
- The real scroll to the top of the page, which the router's `scrollPositionRestoration` in `app.config.ts` does. This test doesn't configure it.
- The focus rings (next subtask).
