## Names and signatures
- `interface Reassignment { brewId: number; methodId: number }`; `MethodApi.delete(id: number, reassignments: Reassignment[]): Observable<{ reassignedBrewCount: number }>` → POST `/api/methods/{id}/delete` `{ reassignments }`.
- `MethodStore.remove(id: number, reassignments: Reassignment[], from: 'inline-delete' | 'step-delete'): Observable<{ reassignedBrewCount: number }>`: on success reloads `methods` (counts change) and returns the response. It sets `pending` exactly as `add` does (BREW-59, Hard logic there): `from` while the POST is in flight, null once it answers. This subtask calls it with `'inline-delete'`; the delete step (BREW-74) with `'step-delete'`.
- Trash (`matIconButton`, aria-label "Delete <name>"): `[disabled]="methodStore.pending() !== null"`, `disabledInteractive`, `[tabIndex]="methodStore.pending() !== null ? -1 : 0"`; its handler starts with `if (this.methodStore.pending()) return;`, so a blocked trash opens no panel (R48).
- Inline "Delete method" (`matButton="filled" class="btn-danger"`, label "Delete method", no spinner): `[disabled]="methodStore.pending() !== null"`, `disabledInteractive`, `[attr.aria-busy]="methodStore.pending() === 'inline-delete' ? 'true' : null"`, `[tabIndex]="methodStore.pending() !== null && methodStore.pending() !== 'inline-delete' ? -1 : 0"`; its handler starts with `if (this.methodStore.pending()) return;`. "Keep" never gets `[disabled]` (B26).
- Dialog: trash `icon-button` (aria-label "Delete <name>", error colour on hover) on non-protected rows with `brewCount` 0 (rows with brews get it in the next story). `confirmingDeleteId = signal<number | null>(null)` (one panel at a time): error-soft panel under the row: "**Delete “<name>”?** No brews use it. This can’t be undone." + "Keep" + `button-danger` "Delete method". Delete → `MethodStore.remove(id, [], 'inline-delete')`; success: panel closes, row gone, `Toaster.show('“<name>” deleted')`; network failure: "Couldn’t delete the method. Try again." inside the panel. "Keep" closes the panel.

## Tests that prove it
**Seam:** integration (`MethodsDialog`) · **Setup:** TestBed, real stores and APIs · **Mocked:** HTTP (`HttpTestingController`), `Toaster` (`{ provide: Toaster, useValue: { show: vi.fn() } }`, BREW-104)

**Happy path**
1. Given "Kalita Wave" with 0 brews, when its trash is clicked, then the panel reads "Delete “Kalita Wave”? No brews use it. This can’t be undone." (R34).
2. When "Delete method" is clicked, then POST `/api/methods/<id>/delete` `{"reassignments":[]}`; after 200 `{"reassignedBrewCount":0}` and the reloaded list, the row is gone and `Toaster.show` is called with "“Kalita Wave” deleted" (R34).
3. Given "Other", then its row shows a lock and "PROTECTED" and has neither a pencil nor a trash button (R37).

**Negative**

6. Given a panel open on one row, when another row's trash is clicked, then only the second panel shows (R34).
