**Goal:** Delete a method without brews from the dialog with the inline confirm, and show "Other" as protected.

**Read first:**
- Story → Frontend, Acceptance criteria (R34, R37), Business rules (B11, B14, B24)
- `design/screens/methods.md` (Layout 3–4; States delete-confirm, delete-error; Interactions: Delete), `design/prototype/screens/methods.html` (delete-confirm panel), `design/screenshots/methods.delete-confirm.desktop.png`, `design/screenshots/methods.delete-confirm.mobile.png`, `design/screenshots/methods.default.desktop.png`

## Files that change
- modify `frontend/src/app/core/method-api.ts` (+ spec): `delete`; `core/models.ts`: `Reassignment`.
- modify `frontend/src/app/methods/method.store.ts` (+ spec): `remove`.
- modify `frontend/src/app/methods/methods-dialog/methods-dialog.ts`, `.html`, `.scss`, `.spec.ts`.

## Names and signatures
- `interface Reassignment { brewId: number; methodId: number }`; `MethodApi.delete(id: number, reassignments: Reassignment[]): Observable<{ reassignedBrewCount: number }>` → POST `/api/methods/{id}/delete` `{ reassignments }`.
- `MethodStore.remove(id, reassignments)`: on success reloads `methods` (counts change) and returns the response.
- Dialog: trash `icon-button` (aria-label "Delete <name>", error colour on hover) on non-protected rows with `brewCount` 0 (rows with brews get it in the next story). `confirmingDeleteId = signal<number | null>(null)` (one panel at a time): error-soft panel under the row: "**Delete “<name>”?** No brews use it. This can’t be undone." + "Keep" + `button-danger` "Delete method". Delete → `MethodStore.remove(id, [])`; success: panel closes, row gone, `Toaster.show('“<name>” deleted')`; network failure: "Couldn’t delete the method. Try again." inside the panel. "Keep" closes the panel.

## Tests that prove it
**Seam:** integration (`MethodsDialog`) · **Setup:** TestBed, real stores and APIs · **Mocked:** HTTP (`HttpTestingController`), `Toaster` (`{ provide: Toaster, useValue: { show: vi.fn() } }`, BREW-104)

**Happy path**
1. Given "Kalita Wave" with 0 brews, when its trash is clicked, then the panel reads "Delete “Kalita Wave”? No brews use it. This can’t be undone." (R34).
2. When "Delete method" is clicked, then POST `/api/methods/<id>/delete` `{"reassignments":[]}`; after 200 `{"reassignedBrewCount":0}` and the reloaded list, the row is gone and `Toaster.show` is called with "“Kalita Wave” deleted" (R34).
3. Given "Other", then its row shows a lock and "PROTECTED" and has neither a pencil nor a trash button (R37).

**Negative**
4. When "Keep" is clicked, then no request is sent and the panel closes (R34).
5. Given the POST fails with 503, then "Couldn’t delete the method. Try again." shows in the panel and the row stays (R34).
6. Given a panel open on one row, when another row's trash is clicked, then only the second panel shows (R34).
