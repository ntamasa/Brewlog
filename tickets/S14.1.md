**Goal:** Add custom methods with `POST /api/methods`, validated (required, at most 50, unique ignoring case).

**Read first:**
- Technical design → Data model and Backend (below, from the spec); Epic → Technical design → API
- Story → Acceptance criteria (R29, R30), Business rules (B3, B4, B10, B12, B21, B22)

## Files that change

- create `dto/MethodRequest.java`.

## Names and signatures
- `public BrewMethod(String name, String iconKey, boolean predefined, boolean isProtected, Integer position)`: sets the 5 fields; `id` stays unset (the database fills it).
- `record MethodRequest(String name)`
- `BrewMethodService.validateName(String name, Long selfId): String` returns the stripped name or throws `ValidationException` with one `FieldErrorDto("name", …)`: null/empty after `strip()` → `REQUIRED`; longer than 50 → `TOO_LONG`; `existsByNameIgnoreCaseAndIdNot(name, selfId == null ? -1L : selfId)` → `DUPLICATE`.
- `BrewMethodService.create(MethodRequest request): MethodResponse`: `String name = validateName(request.name(), null)`, then `brewMethodRepository.saveAndFlush(new BrewMethod(name, "cup", false, false, null))` (B22), response from the saved entity with `brewCount` 0. A unique-index race maps to `DUPLICATE` through the existing handler.

## Tests that prove it
**Seam:** HTTP API · **Setup:** `MethodCreateIT extends IntegrationTest` · **Mocked:** nothing

**Happy path**
1. POST `{"name":" Chemex "}` → 201 `{"id":8,"name":"Chemex","iconKey":"cup","predefined":false,"protected":false,"position":null,"brewCount":0}` (R30).
2. POST a name of exactly 50 characters → 201 (R30, B4).
3. Given "chemex" added, `GET /api/methods` → AeroPress, chemex, Cold Brew, Espresso, French Press, Moka Pot, Pour Over, Other, and every seeded entry has `predefined` true, `position` 1–6 (Other 99), `iconKey` as seeded, and `protected` true only for Other (R29).

**Negative**
4. POST `{"name":"   "}` and POST `{}` → 400 `[{"field":"name","code":"REQUIRED"}]`, `brew_method` still 7 rows (R30).
5. POST 51 characters → 400 `name` `TOO_LONG` (R30).
6. POST `{"name":"pour over"}` → 400 `name` `DUPLICATE`; POST `{"name":"OTHER"}` → 400 `name` `DUPLICATE` (R30, B12).
