**Goal:** Show 6 skeleton cards while the list loads and the error panel with "Try again" when it fails.

**Read first:**
- Story → Frontend, Acceptance criteria (R4)
- `design/screens/brews.md` (States: loading, error), `design/prototype/screens/brews.html` (skeleton and error panel markup), `design/prototype/components.css` (`skeleton`, `panel`), `design/screenshots/brews.loading.desktop.png`, `design/screenshots/brews.error.desktop.png`

## Files that change
- modify `frontend/src/app/journal/journal.store.ts`: `load` sets `status: 'error'` when `BrewApi.list` errors (any `HttpErrorResponse`: status 0 or ≥ 500, and any other non-2xx), keeping the previous query; the stream keeps working after an error (`catchError` inside the `switchMap`).
- modify `frontend/src/app/journal/journal-page/journal-page.html`, `.scss`: `status() === 'loading'` → 6 skeleton cards in the grid, a skeleton bar in place of the count, `aria-busy="true"` on the grid; `status() === 'error'` → the error panel (`role="alert"`, alert icon, "We couldn’t load your brews", "The Brewlog server didn’t respond. Check that the backend is running, then try again. Your entries are safe.", primary "Try again" with refresh icon) instead of grid and footer.
- modify `journal.store.spec.ts`, `journal-page/journal-page.spec.ts`.

## Names and signatures
- "Try again" calls `JournalStore.reload()`.

## Tests that prove it
**Seam:** unit (`JournalStore`) · **Setup:** TestBed, fake `BrewApi` · **Mocked:** API
1. Given the fake API errors with status 503, when `setQuery(DEFAULT_QUERY)`, then `status` is `error` (R4).
2. Given that error, when `reload()` and the fake API now succeeds, then `status` is `ready` with the new items (R4).

**Seam:** integration (`JournalPage`) · **Setup:** TestBed, real store and API · **Mocked:** HTTP (`HttpTestingController`)

**Happy path**
3. Given `/journal` with the list request not yet flushed, then 6 elements with the class `skeleton` show and the grid has `aria-busy="true"` (R4).
4. Given the request flushed with an error (status 0, `ProgressEvent('error')`), then the panel shows "We couldn’t load your brews" and the message text above, with `role="alert"` (R4).
5. Given the error panel, when "Try again" is clicked, then a new GET `/api/brews?sort=NEWEST&page=1` is sent and the skeletons show; flushing 12 items shows the cards (R4).

**Negative**
6. Given the list request answered 500, then the same error panel shows and no card or footer renders (R4).
7. Given "Try again" fails again with 500, then the error panel shows again (R4).

## Out of scope
