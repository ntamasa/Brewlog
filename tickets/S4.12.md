## Names and signatures
- `toast.ts`:
  - `export type ToastIcon = 'check' | 'refresh';`
  - `export interface ToastData { text: string; icon: ToastIcon }`
  - `Toaster.show(text: string, icon: ToastIcon = 'check'): void` calls `this.snackBar.openFromComponent(ToastMessage, { data: { text, icon }, duration: 4000 })`.
  - Every toast so far is a confirmation, so its caller keeps calling `show(text)`. Only "That method no longer exists. The list has been refreshed." (R38, BREW-76) passes `'refresh'`, as in `methods.html` line 190.
- `ToastMessage`: standalone, `selector: 'app-toast-message'`, imports `MatIconModule` and `MatSnackBarLabel`.
  - `protected readonly data = inject<ToastData>(MAT_SNACK_BAR_DATA)`
  - template: `<div matSnackBarLabel class="toast"><mat-icon class="icon icon-sm" [svgIcon]="data.icon" aria-hidden="true" />{{ data.text }}</div>`
  - Material keeps the bar's `role="status"` live region and moves this content into it.
- `toast-message.scss`: `.toast { display: flex; align-items: center; gap: var(--spacing-sm); }` and `.toast .mat-icon { color: var(--color-tertiary-soft); }` (`components.css` lines 219 and 223). `theme.scss`'s `mat.snack-bar-overrides` keep the bar's espresso fill, ivory text and 2 px corners. Its position stays Material's bottom centre.

## Tests that prove it
**Seam:** unit (`Toaster`), component (`ToastMessage`) · **Mocked:** `MatSnackBar`; HTTP (the icon sprite)

**Setup:**
- `Toaster` is tested with `{ provide: MatSnackBar, useValue: { open: vi.fn(), openFromComponent: vi.fn() } }`.
- `ToastMessage` is created with `{ provide: MAT_SNACK_BAR_DATA, useValue: … }`, `provideHttpClient()`, `provideHttpClientTesting()` and `MatIconHarness`, like `brew-card.spec.ts`.

**Happy path**
1. `show('“Kenyan Morning” saved to your journal')` calls `openFromComponent` once, with `ToastMessage` and `{ data: { text: '“Kenyan Morning” saved to your journal', icon: 'check' }, duration: 4000 }` (R12, B24).
2. `show('That method no longer exists. The list has been refreshed.', 'refresh')` calls it with `data.icon` "refresh" and `duration` 4000 (B24).
3. `ToastMessage` with `{ text: 'Brew deleted', icon: 'check' }` shows the text "Brew deleted" after exactly one `mat-icon`, which is named `check` and has `aria-hidden="true"`. Both sit inside the element with the attribute `matSnackBarLabel`.
4. `JournalPage` (BREW-23's save test in `journal-page.spec.ts`): after a saved brew, `Toaster.show` was called once, with exactly `'“Kenyan Morning” saved to your journal'` (R12).

**Negative**
5. `ToastMessage` with `{ text: 'That method no longer exists. The list has been refreshed.', icon: 'refresh' }` shows one icon, named `refresh`, and no `check` icon.
6. After test 1's call, `MatSnackBar.open` wasn't called. The plain-text bar has no icon.
7. `BrewForm` (BREW-22's tests 6 and 7 in `brew-form.spec.ts`): after a failed save, `Toaster.show` isn't called.

**Seam:** E2E · **Setup:** the create test in `e2e/tests/brew-form.spec.ts` (BREW-99), both projects · **Mocked:** nothing

8. After "Add to journal", the `mat-snack-bar-container` shows the text "“<name>” saved to your journal" and also holds a visible `mat-icon[data-mat-icon-name="check"]` (R12).
