**Goal:** Serve the method list with brew counts from `GET /api/methods`, A–Z ignoring case with "Other" last.

**Read first:**
- Story → Data model; Epic → Technical design → API, Backend
- Story → Business rules (B10, B21, B22)

## Files that change
- create `backend/src/main/java/com/brewlog/dto/MethodResponse.java`, `service/BrewMethodService.java` (only `list` for now), `controller/BrewMethodController.java`.
- `repository/BrewMethodRepository.java` and `repository/MethodWithCount.java` don't change: `findAllWithBrewCount()` and its projection already exist (BREW-94, a fix subtask of story BREW-10).
- create `backend/src/test/java/com/brewlog/MethodListIT.java`.

## Names and signatures
- `record MethodResponse(long id, String name, String iconKey, boolean predefined, @JsonProperty("protected") boolean isProtected, Integer position, long brewCount)`
- Existing: `BrewMethodRepository.findAllWithBrewCount(): List<MethodWithCount>`, one row per method (count 0 when it has no brews), unordered; `interface MethodWithCount { BrewMethod getMethod(); long getBrewCount(); }`.
- `BrewMethodService.list(): List<MethodResponse>`: one `MethodResponse` per `findAllWithBrewCount()` row, from `getMethod()`'s fields and `getBrewCount()`, sorted with `Comparator.comparing((MethodResponse m) -> m.isProtected()).thenComparing(MethodResponse::name, String.CASE_INSENSITIVE_ORDER)` (protected "Other" last).
- `GET /api/methods` → `BrewMethodController.list(): List<MethodResponse>`

## Tests that prove it
**Seam:** HTTP API · **Setup:** `MethodListIT extends IntegrationTest`, data via `TestData` · **Mocked:** nothing

**Happy path**
1. Given a fresh database, when `GET /api/methods`, then 200 with names in order AeroPress, Cold Brew, Espresso, French Press, Moka Pot, Pour Over, Other; AeroPress is `{"id":4,"name":"AeroPress","iconKey":"aeropress","predefined":true,"protected":false,"position":4,"brewCount":0}`; Other has `"protected": true`, `"position": 99`, `"iconKey": "cup"` (B10, B21, B22).
2. Given 2 brews with method Pour Over (id 2) and 1 with Espresso (id 1), then Pour Over has `brewCount` 2, Espresso 1, all others 0.
3. Given a custom method `chemex` (inserted with `jdbc`: `icon_key` `cup`, `predefined` false, `position` null), then the order is AeroPress, chemex, Cold Brew, Espresso, French Press, Moka Pot, Pour Over, Other and chemex has `"position": null`, `"predefined": false` (B21).

**Negative**
4. Given a custom method `zebra`, then Other is still last, after zebra (B21).
