**Goal:** On phones, open the brew form, the brew detail and the methods dialog as bottom sheets.

**Read first:**
- Story → Frontend, Acceptance criteria (R42)
- `design/DESIGN.md` (`bottom-sheet`, `sheet-handle`), `design/screens/brew-form.md` (Layout: Phone), `design/screens/brew-detail.md`, `design/screens/methods.md` (Layout), `design/screenshots/brew-form.create.mobile.png`, `design/screenshots/brew-detail.default.mobile.png`, `design/screenshots/methods.default.mobile.png`

## Files that change
- create `frontend/src/app/core/sheet-or-dialog.ts` (+ spec).
- modify `frontend/src/app/journal/journal-page/journal-page.ts`, `.html`, `.spec.ts`: detail and methods open through `SheetOrDialog`; the form opens in the sidenav on ≥ 768 px and in a bottom sheet below. Until now (BREW-23) the phone FAB opened the same `mat-sidenav` as on desktop; this subtask replaces that on phones.
- modify `e2e/tests/brew-form.spec.ts`: the create test of BREW-23 expects the form "Log a brew" in a `mat-bottom-sheet-container` on the `phone` project (it expected the `mat-sidenav` there), still in the `mat-sidenav` on `desktop`.
- modify `frontend/src/app/brew-form/brew-form.ts`, `.html`, `.scss`; `journal/brew-detail-dialog/*`; `methods/methods-dialog/*`: inject the data and close through `SheetOrDialog`'s ref type so they work in both containers; sheet styles (4 px top corners, `sheet-handle`, 90 % max height; the form 90 % height with equal-width foot buttons).

## Names and signatures
- `SheetOrDialog.open<T, R>(component: Type<T>, config: { data?: unknown; width: string; panelClass?: string }): { afterClosed(): Observable<R | undefined> }`: `Viewport.isPhone()` → `MatBottomSheet.open(component, { data, panelClass: ['brewlog-sheet', …] })`; else `MatDialog.open(component, { data, width, panelClass })`.
- `injectOverlayData<D>(): D` and `injectOverlayRef<R>(): { close(result?: R): void }`: read `MAT_BOTTOM_SHEET_DATA`/`MatBottomSheetRef` or `MAT_DIALOG_DATA`/`MatDialogRef`, whichever is present (`inject(..., { optional: true })`).

## Tests that prove it
**Seam:** integration (`JournalPage`) · **Setup:** TestBed, real stores, fake `BreakpointObserver` · **Mocked:** HTTP, breakpoints

**Happy path**
1. Given phone, when a card is clicked, then the detail opens in a `mat-bottom-sheet-container`; when "Manage methods" is tapped, the methods list opens in a bottom sheet; when the FAB is tapped, the form ("Log a brew") opens in a bottom sheet (R42).
2. Given phone and the form sheet, when a valid brew is saved, then the sheet closes and the toast shows (R42).
3. Given desktop, then the detail and methods open in `mat-dialog-container` and the form in the sidenav (R42).

**Negative**
4. Given phone and a changed form, when the sheet backdrop is tapped, then the sheet stays open with "Discard changes?" (`disableClose: true` on the sheet) (R42).
