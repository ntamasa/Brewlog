## Names and signatures
- `interface MethodBrew { id: number; name: string; beanName: string; origin: string; brewDate: string }`; `MethodApi.brewsOf(id): Observable<MethodBrew[]>` → GET `/api/methods/{id}/brews`.
- Dialog: `view = signal<'list' | 'rename' | …>('list')`. A valid rename of a method with `brewCount >= 1` calls `brewsOf(id)` and switches to `view 'rename'` with `RenameStep`; `brewCount` 0 saves directly as before.
- `RenameStep`: inputs `method: BrewMethod`, `newName: string`, `brews: MethodBrew[]`; outputs `confirm`, `cancel`. Head: back `icon-button` (chevron-left, aria-label "Back to methods"), title "Rename “<old>” to “<new>”?" (receives focus on enter, `tabindex="-1"`), close. Text `brewCount(n) + (n === 1 ? ' uses' : ' use') + ' this method and will show the new name:'`; list rows: name over "Bean · Origin · <formatDate>" in a scrolling frame; foot `button-secondary` "Cancel" + `button-primary` `"Rename for " + (n === 1 ? '1 brew' : 'all ' + n + ' brews')`. `saving` input: primary shows spinner + "Renaming…" with `aria-busy`; `error` input: `banner-error` "Couldn’t save the method — Nothing was changed. Try again." above the actions, the primary retries.
- Confirm → `MethodStore.rename`; success → `view 'list'`, `Toaster.show('Renamed to “<new>”')`, `JournalStore.reload()`, focus back on the row's pencil. Cancel, back or Esc → `view 'list'` with the row still in rename mode and the typed new name kept; nothing sent.

## Tests that prove it
**Seam:** integration (`MethodsDialog`) · **Setup:** TestBed, real stores and APIs · **Mocked:** HTTP (`HttpTestingController`), `Toaster` (`{ provide: Toaster, useValue: { show: vi.fn() } }`, BREW-104)

**Happy path**
1. Given Pour Over with `brewCount` 14, when renamed to "Pour Over (V60)" and Enter pressed, then GET `/api/methods/2/brews` is sent (no PUT yet); flushing 14 brews shows the title "Rename “Pour Over” to “Pour Over (V60)”?", "14 brews use this method and will show the new name:", 14 rows (first row e.g. "Kenyan Morning" / "AA Kiambu · Kenya · 28 Oct 2026"), and "Rename for all 14 brews" (R33).
2. When "Rename for all 14 brews" is clicked, then PUT `/api/methods/2` `{"name":"Pour Over (V60)"}` is sent and the button reads "Renaming…"; after 200 the list shows "Pour Over (V60)" with the `pour-over` icon, `Toaster.show` is called with "Renamed to “Pour Over (V60)”" and GET `/api/brews…` is sent (R33, B22).
3. Given a method with 1 brew, then the texts read "1 brew uses this method and will show the new name:" and "Rename for 1 brew" (R33, B23).

**Negative**
4. Given the step view, when "Cancel", back or Esc is used, then no PUT is sent, the list shows with the row's rename input still reading "Pour Over (V60)" (R33).
5. Given the PUT fails with 503, then the banner "Couldn’t save the method — Nothing was changed. Try again." shows in the step view; clicking the primary sends the PUT again (R33).

**Seam:** E2E · **Setup:** compose stack, both projects; method `m = uniqueName('Kalita')` created through the API and 2 brews with that method · **Mocked:** nothing
6. Given `/journal`, when "Manage methods" → pencil on `m` → "<m> V2" → Enter, then the step view lists the 2 brews; "Rename for all 2 brews" shows the toast "Renamed to “<m> V2”", and after closing the dialog both cards (searched by their names) show "<m> V2" (R33).
