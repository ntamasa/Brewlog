**Goal:** Support all four sort orders with their tie-breakers in `GET /api/brews`, and reject an unknown `sort` with 400 `INVALID`.

**Read first:**
- Epic → Technical design → API (list params, errors); Technical design → Backend (below, from the spec: `BrewQueryParams` binds and validates the list params); Story → Hard logic (sort)
- Story → Acceptance criteria (R7), Business rules (B9, B19)
- R9 (story "Keep my journal view in the URL", BREW-53): this subtask builds only its `sort=X` case.

## Files that change
- modify `backend/src/main/java/com/brewlog/service/BrewSort.java`: all keys.
- modify `controller/BrewQueryParams.java`: bind `sort` as a raw `String` (never as `SortKey`, so a bad value never reaches Spring's own binding errors) and parse it in `toQuery()`.
- modify `service/BrewSortTest.java`; create `backend/src/test/java/com/brewlog/BrewSortIT.java`.

## Names and signatures
- `BrewSort.toSort(SortKey key): Sort`:
  - `NEWEST`: `brewDate desc, createdAt desc, id desc`
  - `OLDEST`: `brewDate asc, createdAt asc, id asc`
  - `HIGHEST`: `rating desc, brewDate desc, createdAt desc, id desc`
  - `LOWEST`: `rating asc, brewDate desc, createdAt desc, id desc`
- `BrewQueryParams`: field `private String sort`, `getSort(): String`, `setSort(String sort)` (stores the value as given). In `toQuery()`:
  - `sort` null or empty → `SortKey.NEWEST`
  - exactly one of `NEWEST`, `OLDEST`, `HIGHEST`, `LOWEST` (case-sensitive) → that `SortKey`
  - anything else → `throw new ValidationException(List.of(new FieldErrorDto("sort", ErrorCode.INVALID)))` (handled by the existing `ApiExceptionHandler.handleValidation`: 400 with `errors`)

## Tests that prove it
**Seam:** HTTP API · **Setup:** `BrewSortIT extends IntegrationTest`; `TestData`: A (2026-11-01, rating 4, `createdAt` 2026-11-01T08:00Z), B (2026-11-01, rating 4, `createdAt` 2026-11-01T09:00Z), C (2026-10-30, rating 5, `createdAt` 2026-10-30T08:00Z) · **Mocked:** nothing

**Happy path**
1. `sort=NEWEST` (and no `sort`) → B, A, C (R7).
2. `sort=OLDEST` → C, A, B (R7).
3. `sort=HIGHEST` → C, B, A (R7).
4. `sort=LOWEST` → B, A, C (R7).

**Negative**
5. Given A and B with equal `createdAt` too, `sort=NEWEST` orders them by id descending, the same on every call (B19).
6. `GET /api/brews?sort=FOO` → 400, body `errors` exactly `[{"field":"sort","code":"INVALID"}]`, and no `items` (R9, `sort` case).
7. `GET /api/brews?sort=newest` (lower case) → 400 with exactly `[{"field":"sort","code":"INVALID"}]` (R9, `sort` case).
8. `GET /api/brews?sort=` (empty) → 200 in Newest order B, A, C (R7).

**Seam:** unit · **Setup:** JUnit 5 · **Mocked:** nothing
9. `toSort(LOWEST)` equals `Sort.by(asc("rating"), desc("brewDate"), desc("createdAt"), desc("id"))` (B19).
