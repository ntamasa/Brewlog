**Goal:** Support all four sort orders with their tie-breakers in `GET /api/brews`.

**Read first:**
- Epic → Technical design → API (list params), Backend, Hard logic (sort)
- Story → Acceptance criteria (R7), Business rules (B9, B19)

## Files that change
- modify `backend/src/main/java/com/brewlog/service/BrewSort.java`: all keys.
- modify `controller/BrewQueryParams.java`: bind `sort` (`NEWEST` when absent).
- modify `service/BrewSortTest.java`; create `backend/src/test/java/com/brewlog/BrewSortIT.java`.

## Names and signatures
- `BrewSort.toSort(SortKey key): Sort`:
  - `NEWEST`: `brewDate desc, createdAt desc, id desc`
  - `OLDEST`: `brewDate asc, createdAt asc, id asc`
  - `HIGHEST`: `rating desc, brewDate desc, createdAt desc, id desc`
  - `LOWEST`: `rating asc, brewDate desc, createdAt desc, id desc`

## Tests that prove it
**Seam:** HTTP API · **Setup:** `BrewSortIT extends IntegrationTest`; `TestData`: A (2026-11-01, rating 4, `createdAt` 2026-11-01T08:00Z), B (2026-11-01, rating 4, `createdAt` 2026-11-01T09:00Z), C (2026-10-30, rating 5, `createdAt` 2026-10-30T08:00Z) · **Mocked:** nothing

**Happy path**
1. `sort=NEWEST` (and no `sort`) → B, A, C (R7).
2. `sort=OLDEST` → C, A, B (R7).
3. `sort=HIGHEST` → C, B, A (R7).
4. `sort=LOWEST` → B, A, C (R7).

**Negative**
5. Given A and B with equal `createdAt` too, `sort=NEWEST` orders them by id descending, the same on every call (B19).

**Seam:** unit · **Setup:** JUnit 5 · **Mocked:** nothing
6. `toSort(LOWEST)` equals `Sort.by(asc("rating"), desc("brewDate"), desc("createdAt"), desc("id"))` (B19).

## Out of scope
- Rejecting an unknown `sort` with 400 (story "Keep my journal view in the URL").
