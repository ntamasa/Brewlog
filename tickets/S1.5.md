**Goal:** Run the whole stack with Docker Compose and add the Playwright end-to-end project with its CI workflow and the landing page test.

**Read first:**
- Epic → Technical design → Overview, Risks
- Story → Repository and tooling, Deployment, CI

## Files that change
- create `backend/Dockerfile`: stage 1 `gradle:jdk25` runs `gradle bootJar --no-daemon` (or `./gradlew bootJar`); stage 2 `eclipse-temurin:25-jre` copies the jar, `EXPOSE 8080`, `ENTRYPOINT ["java", "-jar", "/app/app.jar"]`. Add `backend/.dockerignore` (`build`, `.gradle`).
- create `frontend/Dockerfile`: stage 1 `node:22` runs `npm ci` and `npm run build`; stage 2 `nginx:1.29-alpine` copies `dist/frontend/browser` to `/usr/share/nginx/html` and `nginx.conf` to `/etc/nginx/conf.d/default.conf`. Add `frontend/.dockerignore` (`node_modules`, `dist`, `.angular`).
- create `frontend/nginx.conf`: `listen 80`; `location / { try_files $uri /index.html; }`; `location /api/ { proxy_pass http://backend:8080; }`.
- create `docker-compose.yml` exactly as in Story → Deployment; `db` healthcheck `pg_isready -U brewlog`; `backend` `depends_on: db: condition: service_healthy`; `frontend` `depends_on: [backend]`.
- create `e2e/package.json` (dev dependency `@playwright/test`, `typescript`; script `test` = `playwright test`), `e2e/tsconfig.json`, `e2e/playwright.config.ts`: `testDir: 'tests'`, `fullyParallel: false`, `workers: 1`, `use.baseURL: 'http://localhost:8081'`, projects `desktop` (viewport 1440×900, Chromium) and `phone` (viewport 390×844, Chromium, `isMobile: true`, `hasTouch: true`).
- create `e2e/tests/support.ts`: `uniqueName(prefix: string): string` → `` `${prefix} ${Date.now().toString(36)}` `` for later tests.
- create `e2e/tests/landing.spec.ts` (tests below).
- create `.github/workflows/e2e.yml` as in Story → CI.
- modify `.gitignore`: add `node_modules/`, `e2e/test-results/`, `e2e/playwright-report/`, `backend/build/`, `backend/.gradle/`, `frontend/dist/`, `frontend/.angular/`.

**E2E rule for every later story:** tests run against one shared database in both projects, so every test creates its own data with `uniqueName(...)` names through the API (`request.post('/api/...')`) and scopes its assertions to that data (e.g. by searching for the unique prefix). Never assume an empty database.

## Tests that prove it
**Seam:** E2E · **Setup:** `docker compose down -v && docker compose up -d --build --wait`, projects `desktop` and `phone` · **Mocked:** nothing

**Happy path**
1. Given `/`, then the heading "Remember every cup worth remembering." and the three photos are visible (R1).
2. Given `/`, when the hero "Open my journal" is clicked, then the URL ends with `/journal` (R1).
3. Given `/`, when "How it works" is clicked, then the section "Brew. Log. Rediscover." is in the viewport (R1).

**Negative**
4. Given `/no-such-page`, then the landing page is shown at `/` (R1).
