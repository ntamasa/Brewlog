**Goal:** Validate brews on the server (required fields, lengths, rating, roast, future date) and answer 400 with field error codes.

**Read first:**
- Epic → Technical design → API (errors), Risks (time zones); Technical design → Backend (below, from the spec)
- Story → Acceptance criteria (R13, R14, R15, R17, R18), Business rules (B2, B3, B4, B6, B7, B8)

## Files that change
- modify `backend/src/main/java/com/brewlog/service/BrewValidator.java`: the checks below (it gets the `Clock` injected).
- create `exception/ValidationException.java`, `exception/ApiExceptionHandler.java`.
- modify `service/BrewService.java`: `create` throws `ValidationException` when `validate` returns errors, before saving.

## Names and signatures
- `ValidationException(List<FieldErrorDto> errors)` (`RuntimeException`, getter `errors()`).
- `ApiExceptionHandler extends ResponseEntityExceptionHandler` (`@RestControllerAdvice`): `ValidationException` → `ProblemDetail.forStatus(400)` with property `errors` = the list (serialised as `[{"field":"name","code":"REQUIRED"}]`). The default handling of unreadable JSON stays a 400 without `errors`.
- `BrewValidator.validate(draft, selfId)` after normalising, per field in this order, at most one error per field, first match wins:
  - `name`, `beanName`, `origin`: null or empty → `REQUIRED`; longer than 100 → `TOO_LONG`
  - `methodId`: null → `REQUIRED`
  - `roast`: null or empty → `REQUIRED`; not `LIGHT`/`MEDIUM`/`DARK` → `INVALID`
  - `rating`: null → `REQUIRED`; outside 1–5 → `OUT_OF_RANGE`
  - `brewDate`: null → `REQUIRED`; after `LocalDate.now(clock).plusDays(1)` → `FUTURE_DATE`
  - `notes`: longer than 2000 → `TOO_LONG`
- Length = `String.length()` of the stripped value.

## Tests that prove it
**Seam:** unit (`BrewValidatorTest`) · **Setup:** JUnit 5, `Clock.fixed(2026-11-01T12:00Z, UTC)` · **Mocked:** nothing

**Happy path**
1. A draft with name of exactly 100 characters, bean and origin of 100, notes of 2000, rating 1 (and again 5), roast `DARK`, date 2026-11-02 → no errors (R15, R17, R18).

**Negative**
2. An all-null draft → `REQUIRED` for `name`, `beanName`, `origin`, `methodId`, `roast`, `rating`, `brewDate`, in that order (R13).
3. Bean `"   "` → `beanName` `REQUIRED` (R14).
4. Name of 101 characters → `name` `TOO_LONG`; the same for `beanName`, `origin`, and notes of 2001 → `notes` `TOO_LONG` (R15).
5. Rating 0 and rating 6 → `rating` `OUT_OF_RANGE`; roast `BOLD` → `roast` `INVALID` (R17).
6. Date 2026-11-03 → `brewDate` `FUTURE_DATE` (R18).

**Seam:** HTTP API (`BrewValidationIT`) · **Setup:** `IntegrationTest` (fixed clock 2026-11-01) · **Mocked:** nothing
7. POST `{}` → 400 with `errors` containing `{"field":"name","code":"REQUIRED"}` … `{"field":"brewDate","code":"REQUIRED"}` (7 entries), and `brew` stays empty (R13).
8. POST a valid body with name of 101 characters → 400 `[{"field":"name","code":"TOO_LONG"}]`, nothing saved; with exactly 100 → 201 (R15).
9. POST with `rating` 6 → 400 `rating` `OUT_OF_RANGE`; with `roast` "BOLD" → 400 `roast` `INVALID`; with `brewDate` "2026-11-03" → 400 `brewDate` `FUTURE_DATE`; with "2026-11-02" → 201 (R17, R18).
10. POST with name `"  Kenyan Morning "`, bean `"   "`, notes `"   "` → 400 `[{"field":"beanName","code":"REQUIRED"}]`; after fixing the bean → 201 with name "Kenyan Morning" and `notes` null (R14).
