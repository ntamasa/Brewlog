# Design changes: Brewlog

## Summary
Brewlog had no UI, so this is the whole first design: a design system ("ivory editorial luxury", light theme only, designed for 390px phone and 1440px desktop) and six screens. A photographic landing page leads into the journal app page (`brews`), which hosts every other screen as an overlay: the brew form (drawer / bottom sheet), brew detail, the delete confirmation and the brew-methods dialog.

Points the design adds beyond the intent (pagination, method uniqueness and the predefined list were confirmed in the spec grilling):
- **Pagination:** the journal shows 12 brews per page with numbered pagination; any search, filter or sort change resets to page 1.
- **Method names unique, ignoring case** (same rule as brew names), at most 50 characters.
- **Brew counts per method** are shown in the methods dialog and its rename/delete confirmations. Counts use the singular for exactly 1 everywhere ("1 brew", "1 of 41 brews", "Show 1 brew").
- **Method rename/delete confirmations** (replace the intent's simpler behavior, decided in spec grilling): renaming a method used by brews asks for confirmation and lists them (declining changes nothing); deleting one lists its brews with a per-brew method picker (default "Other") plus "Move all brews to".
- **Predefined methods:** Espresso, Pour Over, French Press, AeroPress, Moka Pot, Cold Brew, plus the protected "Other".
- **Method order:** the brew form's method dropdown and the journal's Method filter list methods A–Z with "Other" last; the methods dialog uses predefined (fixed order), then custom A–Z, then "Other".
- **Length limits and future dates:** brew name, bean and origin at most 100 characters, notes at most 2000 (counter after 1,800); the date can't be after today (picker greys out future days). Nothing is cut off while typing; over-long values get inline errors.
- **Deleted-elsewhere handling:** editing a brew that no longer exists offers "Save as new brew" or "Close"; deleting one shows a "no longer exists" message with a single "Close"; a chosen method that no longer exists gets an inline error on the method field.
- **Methods dialog errors:** load failure (banner + "Try again"), save and delete failures inline or in the step view's banner; a method deleted elsewhere reloads the list with a toast. The brew form's quick-add box uses the same method-name errors.
- **No "Last edited" date** in the edit form.
- **Brew detail** screen (full brew incl. untruncated notes) opened by clicking a card; cards clamp notes to 3 lines.
- **Unsaved-changes guard:** closing the form with changes asks inline "Discard changes?".
- **Landing photos** are three Unsplash images stored locally in `design/prototype/assets/` (hero-pour-over.jpg, beans.jpg, cup-notebook.jpg), credited in the landing footer.

## Design system changes
New `design/DESIGN.md` (Google Stitch format) and generated `design/prototype/tokens.css`:
- **Colors (22):** espresso ink `primary` #2B1D16 with `on-primary` ivory, mocha `secondary`, one burnt-terracotta accent `tertiary` #B4532A (+ hover, soft), warm paper neutrals (`neutral`, `surface`, `surface-sunken`, `on-surface`, `on-surface-muted`, `outline`, `outline-strong`), `error` / `error-soft`, roast swatches `roast-light` / `roast-medium` / `roast-dark`, and `scrim`, `backdrop`, `on-scrim` for the landing hero and overlays.
- **Typography (11 scales):** Cormorant Garamond for display and headlines (`display-xl` 88px … `headline-sm` 24px), Inter for UI and data, plus `label-caps` for eyebrows and labels.
- **Shapes, spacing, layout:** 4 radius levels (small, near-square corners), 8px spacing rhythm `xs` 4 … `5xl` 144, content max width 1200px, page margins 48px desktop / 16px phone. Breakpoints: phone < 768px (1 column), tablet 768–1119px (2 columns), desktop ≥ 1120px (3 columns). Hairline borders instead of shadows.
- **Components (33):** `button-primary`(+hover), `button-accent`(+hover), `button-secondary`, `button-ghost`, `button-danger`, `icon-button`, `fab`, `input-field`, `input-field-error`, `field-label`, `field-error`, `chip-filter`, `segmented-option-selected`, `brew-card`, `brew-card-highlight`, `bean-rating`, `roast-swatch-light/medium/dark`, `roast-tag`, `method-icon`, `dialog`, `modal-backdrop`, `drawer`, `bottom-sheet`, `sheet-handle`, `banner-error`, `toast`, `skeleton`, `pagination-current`, `hero-scrim`.
- **Focus rings (added after review of PR #3):** keyboard focus (`:focus-visible`) shows a 2px solid ring with 2px offset. It's `tertiary` terracotta everywhere except on the controls over the landing hero scrim, which use `on-scrim` ivory #FAF6EE: terracotta reaches only 1.0–3.8:1 against the photo there, below WCAG's 3:1 for non-text. This applies to Material controls too: their state layer alone isn't a visible focus indicator. No new tokens.
- **Busy and blocked buttons (added after review of PR #6):** a button whose own request is in flight is *busy*: own fill and label colour at 75% opacity, progress cursor, `aria-busy="true"`, disabled (click and Enter do nothing). Buttons with a designed busy label show the spinner plus that label ("Saving…", "Renaming…", "Deleting…"); the others keep their own label with no spinner. While a request is in flight, the other buttons in the same overlay that send a request or start a method change are *blocked*: disabled, own label and colours at 75% opacity, default cursor. Never Material's grey disabled look. Cancel, Keep, back, ×, Done and Esc stay enabled. Written into DESIGN.md's Components text and `components.css` (`.btn` / `.icon-btn` `:disabled` and `[aria-disabled="true"]`). No new tokens.
- **Prototype support files:** `prototype/components.css` (component styles built only from tokens.css) and `prototype/icons.js` (fine-line icon sprite: brand mark, bean, a method icon per predefined method, generic cup for custom methods and "Other", UI icons).
